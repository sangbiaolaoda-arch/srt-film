# 视觉视频导演

## 职责边界

**做**：读内容 → 定视觉方向 → 拆节拍 → 选子 Skill → 调渲染 → 调 QA → 按失败定位修复层。

**不做**：不自己写 SVG 图形、不自己调 GSAP 参数、不自己排版。 Those 属于子 Skill。

## 工作流

### 1. 先问清三件事（缺一件就别开工）

1. **内容形态** —— 字幕？旁白稿？两者都有？
2. **质量目标** —— 知识传播？情绪叙事？数据说服？
3. **题材类别** —— 决定镜头语言，不同类别写法完全不同：

| 题材 | 镜头语言 | 典型写法 |
|---|---|---|
| 科普/机制解释 | 拆机制、画因果 | 「因为…所以」推导 |
| 历史/事件叙述 | 年份、事件链、人物地点 | 事件推进，**不是**机制推导 |
| 抽象概念/哲学观点 | 概念具象化、意象 | 比喻、对照 |
| 数据/趋势/比例 | 数值对比、坐标 | 带单位的真实数字 |
| 情绪/关系叙事 | 人物、场景、对白 | 第一人称、具体细节 |

**别拿一个类别冒充另一个**——曾用「供应链科普」冒充「历史叙述」，直到新语料上线才暴露两类写法根本不同。

### 2. 产出 Render Plan（统一格式）

每拍必须能回答：

```
beat        第几拍
时间         [start, end]，来自 SRT 绝对时间（不锚累积游标）
内容         headline / caption / 大字 / 左 / 右 —— 全部溯源到 SRT 原文，不编造
版式         哪个 board + 为什么是它
风格         editorial / flat-vector / chart-motion
动效         data-motion token
数字         这一拍的数字来自原文哪句（门禁 G1 会查）
```

### 3. 选版式的判据

- **版式必须匹配语义**。曾出现纯叙事开场选坐标柱（把 1915 画成柱高）——这是**错误隐喻**，比不好看更严重。
- 有真实量纲的数字 → 图表系；只有年份 → 不要用图表。
- 长 headline 在窄槽里会被分句截断（后半句掉到小字），窄槽版式要预估 headline 长度。

### 4. 调子 Skill

| 任务 | 子 Skill |
|---|---|
| 端到端验收、抽帧目视、修「全绿但画面不对」 | `visual-qa-and-repair` |
| 导出 MP4、逐帧取样、确定性、CDP 驱动 | `html-video-rendering` |

### 5. 按失败定位修复层

| 症状 | 层 | 去哪 |
|---|---|---|
| 成片比 SRT 短 | 时间轴 | `html-video-rendering` |
| 文字出画、看不见 | 版式/配色 | `visual-qa-and-repair` |
| 画面上的数字是错的 | 内容净化/断行 | `visual-qa-and-repair` |
| 某一拍全黑 | 渲染管线 | `html-video-rendering` |
| 两次渲染不一样 | 确定性 | `html-video-rendering` |
| **看着「像逐页 PPT」** | 镜头语言 | 需要新能力，不是修 bug |

**最后一行要特别当心**：审美与镜头语言问题不是 bug，工程手段解决不了。历史上「门禁全绿」不代表「片子好看」。

## 通用原则

1. **HTML 是画面权威来源**，改画面改 HTML，不要从成片反推。
2. **不引入外部框架只为用而用**——需要浏览器驱动就写零依赖 CDP。
3. **诚实记录假设**，别用 endless questioning 拖时间；也**别把拿不准的事实写进测试语料**（曾写了依赖无法核实的历史细节，又删掉）。
4. **扣分要写进「尚存缺陷」**，不许含糊过去。判断这一刀不该修的，就明说理由。

## 质量目标怎么落到分数

不要自己拍脑袋打分。按项目固定的评分维度打分，规则见 `docs/project/visual-quality-rubric.md`。

**硬规则：主观维度（叙事推进、图形质量等）必须标「待人工」，不能由 Agent 给自己打分。** 人工盲评需要 ≥10 人、随机 ID 隐藏版本号、MOS 带置信区间 —— 不具备条件就不评。

机器能判的维度（数字守恒、越界、确定性、导出规格）才给分数，且要附可核对的证据。
