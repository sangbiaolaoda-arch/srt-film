# 流程 · 确定性动画与逐帧验收

> 这份文档沉淀自《光很慢 LIGHT LAG》（45 秒单文件 HTML 科普片）的完整制作过程，
> 以及 srt-film 自己的 probe 体系。**只讲流程和画面操控**，不讲题材、文案、配色。
>
> 配套工具：`tools/check-html-syntax.mjs`（语法门禁）、`tools/qa-frames.mjs`（逐帧验收）。
> 可跑的参考实现：`examples/reference/light-lag.html`。

---

## 0. 一句话

**让「画面在时刻 t 长什么样」成为一个纯函数，然后用机器逐帧把它看一遍。**

前半句是确定性契约，后半句是验收流水线。没有前半句，后半句不可能稳定；
没有后半句，前半句写出来的 bug 你根本看不见。

## 1. 三条契约（页面侧必须满足）

| # | 契约 | 形态 | 为什么 |
|---|---|---|---|
| 1 | **时间轴可寻址** | `render(t)` 是 t 的纯函数；`timeline.seek(t)` 任意跳转结果一致 | 可验收（seek 到任意帧截图）、可复现（同一 t 逐像素一致）、可导出（录屏/渲染等同源） |
| 2 | **时长与结构可读** | 时间轴对象暴露 `dur`（或 `duration`）与场景表 `scenes` | 工具要知道该在哪些 t 截图 |
| 3 | **报错可收** | 页面把运行时错误推进 `window.__err` 数组 | 白屏/半途崩掉的片子，控制台报错必须能被机器读到，而不是靠人盯 DevTools |

参考实现（`light-lag.html` 末尾）：

```js
window.__err = [];
addEventListener("error", (e) => window.__err.push("error: " + e.message));
addEventListener("unhandledrejection", (e) => window.__err.push("reject: " + (e.reason?.message ?? String(e.reason))));

window.__tl = {
  dur: DUR,
  scenes: SC.map((s) => ({ a: s.a, b: s.b, label: s.label })),
  seek: (t) => { T.playing = false; seek(t); },
  play, pause,
  state: () => ({ t: T.t, playing: T.playing, scene: sceneAt(T.t).id }),
};
```

srt-film 本体走的是另一套等价契约：`window.__stage = { duration, seek(t), play(), pause(),
setAutoRender(bool), shots, svg }`，纯函数是 `src/render/frame.ts` 的
`renderFrame({ ctx, svg, shots, t, frame })`。`tools/qa-frames.mjs` 两种都认。

### 确定性的三个常见破绽

1. **`Math.random()`** —— 用确定性伪随机替代：
   ```js
   const rnd = (i, k) => { const x = Math.sin((i + 1) * 12.9898 + (k + 1) * 78.233) * 43758.5453; return x - Math.floor(x); };
   ```
   同一个 `(i,k)` 永远同一值，粒子/星点/抖动全部可 replay。
2. **`Date.now()` / `performance.now()` 进了画面** —— 时间只能从 `t` 来。
3. **跨帧累积状态**（`x += v`）—— 位置必须是 `f(t)`，不是积分。要「飘」就用
   `wave(t, f)` 这类周期函数。

## 2. 画面操控：结构与原语

### 2.1 固定舞台 + 缩放

**不要用响应式布局做片子。** 舞台尺寸固定（如 1600×900），外面套一层按窗口缩放：

```
#fit   → 铺满视口，grid 居中，负责缩放
#stage → 1600×900 固定，所有坐标都是这套坐标系里的绝对值
```

好处：排版所见即所得，不会因为窗口大小变化而重排；逐帧截图尺寸恒定。

### 2.2 分层（z-index 从下到上）

| 层 | 内容 | 说明 |
|---|---|---|
| `canvas#sky` | 背景粒子/星点 | 独立一层，参数随场景变（曝光/缩放/拉线） |
| `canvas#fx` | 前景几何 | 每场一个 `drawXxx(t, al)` 往这层画 |
| `.sc`（DOM） | 文案/标签 | 每场一个 `<section class="sc">`，opacity/visibility 切换 |
| `#hud` | 常驻仪表 | 时间码/场景号/大读数/计算日志，不随场消失 |
| `#flash` `#flashk` | 闪白 / 黑场 | 场切换的「剪辑感」 |
| `#vig` `#grain` `#lines` | 暗角/颗粒/扫描线 | 质感层，`pointer-events:none` |

两层 canvas 的意义：背景（慢变的粒子海）和前景（每场完全不同的几何）重绘成本不同，
分开 clear 各画各的，避免一场重绘拖累全局。

### 2.3 ⚠ 最大的坑：`.sc > *` 必须 `position:absolute`

```css
.sc{position:absolute;inset:0;opacity:0;visibility:hidden;pointer-events:none}
.sc>*{position:absolute}   /* ← 少了这一行，所有子元素会按普通流堆在左上角 */
```

light-lag 第一版漏了第二行，**6 处文字跑到画面外，最后一整场的文案全部消失**。
而且它不报错——逐帧截图里那几拍就是「空的」，看起来像「本来就该空」。
规则：**凡是绝对定位的舞台，子元素必须显式 `position:absolute`，靠截图兜底，别靠脑补。**

### 2.4 时间轴原语（全部画面操控都由这几个函数组合出来）

```js
const clamp = (v, a = 0, b = 1) => (v < a ? a : v > b ? b : v);
const lerp  = (a, b, p) => a + (b - a) * p;
const seg   = (t, a, b) => clamp((t - a) / (b - a));   // ★ 核心：[a,b] 区间内的进度 0→1
const easeOut  = (p) => 1 - Math.pow(1 - p, 3);
const easeIO   = (p) => (p < .5 ? 4*p*p*p : 1 - Math.pow(-2*p + 2, 3) / 2);
const back     = (p) => { const c = 1.70158, c3 = c + 1; return 1 + c3*Math.pow(p-1,3) + c*Math.pow(p-1,2); };
const wave     = (t, f) => Math.sin(t * Math.PI * 2 * f);   // 呼吸/闪烁
```

`seg(t, a, b)` 是唯一的时间原语：**所有动画都是「某段区间上的进度」再套一个缓动**。
没有 `setTimeout`、没有 `await`、没有回调链 —— 那些都不可 seek。

用法范例（一个元素的进场+退场，一行写完）：

```js
const q = easeOut(seg(p, .2, 1.2));          // p = t - 场起点
const out = 1 - easeOut(seg(p, 3.6, 4.0));   // 退场
setEl(E["s6-l1"], { opacity: String(q * out), filter: `blur(${(1 - q) * 10}px)` });
```

### 2.5 每场一个绘制函数，`al` 是场的透明度

```js
function drawStars(t, al) {
  const p = t - 24.80;          // 场内局部时间
  cx.globalAlpha = al;          // al = 场的淡入淡出，由外层统一算
  ...
}
```

外层按场景表算出 `i = sceneAt(t).id` 和 `al = seg(t, a, a+.5) * (1 - seg(t, b-.4, b))`，
然后只调当前场的 draw。**场与场之间不共享可变状态**，这是能任意 seek 的前提。

### 2.6 场切换的视觉语言

硬切很廉价，用这三样（都是覆盖层，不碰场景内容）：

- **闪白** `#flash`：100ms 内从 0.85 衰减到 0 —— 换景的「咔哒」
- **黑场** `#flashk`：进结论场前压到全黑再放出来 —— 大转折
- **拉线** 星点沿离心方向拉成短线 200ms —— 只在跨量级（秒→分→年）时用

### 2.7 HUD 常驻层：让数字可信

左下「计算日志」逐字打出**真实换算式**（`384,400 ÷ 299,792.458 = 1.2823 s`），
右下大读数随场升级（1.28 s → 08:19 → 79.7 min → 548 年 → 2,540,000 年）。
这不是装饰 —— **屏幕上的算式必须等于画面事实**，观众会拿计算器按。

### 2.8 交互与降级（最低配）

- 空格/←→/数字键跳场/R 重播，进度条带章节刻度，控制条 2.6s 自动隐藏
- `prefers-reduced-motion: reduce` → 不自动播放、关掉颗粒/扫描线
- 动画只动 `transform` / `opacity` / `filter`

## 3. 验收流水线

```
写/改 HTML
   │
   ├─ ① 语法门禁   npm run lint:html          （秒级，挡住「改坏一个括号 → 全片白屏」）
   │
   ├─ ② 起服务     python -m http.server 5299  （或 npm run dev）
   │
   ├─ ③ 逐帧截图   npm run qa:frames -- --url ... --sheet
   │
   └─ ④ 人工判读   看 contact-sheet.png + report.md，回改，回到 ①
```

### ① 语法门禁 `tools/check-html-syntax.mjs`

抽出每段内联 `<script>` 做真正的语法解析（`node:vm`，零子进程），错误行号映射回 HTML 行。
单文件 HTML 片子没有构建步骤，**这是唯一能挡住「白屏」的关卡**。
（light-lag 靠它抓到过一次「重排 if/else 漏了闭合花括号」。）

### ② 逐帧验收 `tools/qa-frames.mjs`

自动识别 `window.__tl` / `window.__stage` / `window.__VIDEO_TEST__`（第三方写法，此时
场景表从 DOM 的 `section.scene[data-start/data-end]` 读），按**每镜 5 点**
（起始 / 25% / 50% / 75% / 结束前）seek → 截图 → 量亮度 + 量结构差 → 收报错 → 出报告。

```bash
# 默认：每镜 5 点 + 接触印相
npm run qa:frames -- --url http://127.0.0.1:5299/final/light-lag.html --sheet

# 指定时点 + 指定视口 + 指定截图元素
npm run qa:frames -- --url http://localhost:5201/ --shots 0.8,4.5,15 --width 1280 --height 720

# 每镜只取首帧（快速过一遍）
npm run qa:frames -- --url <url> --per-scene 1

# 只测主图那块画面（治「主图只占一角、被静止背景平均掉」，见 ④）
npm run qa:frames -- --url <url> --roi 0.48,0.2,0.48,0.63

# 同一时刻渲染两次比像素，抓非确定性（见 ⑤）
npm run qa:frames -- --url <url> --determinism --fail-on-nondeterministic

# 把「某一拍没动」当失败（可用于 CI）
npm run qa:frames -- --url <url> --fail-on-still

# srt-film 本体：先用 --prepare 填字幕点载入，__stage 才会出现
npm run qa:frames -- --url http://localhost:5201/ --sheet --prepare "
  (async () => {
    const r = await fetch('/examples/01-explanatory-tech.srt');
    const ta = document.getElementById('srt-input');
    ta.value = await r.text();
    ta.dispatchEvent(new Event('input', { bubbles: true }));
    document.getElementById('override-input').value = '{}';
    document.getElementById('btn-load').click();
    return 'filled';
  })()"
```

产出：`shots/NN.png` + `shots/manifest.json` + `repeat/NN.png`（开了 `--determinism`）
+ `report.md` + `report.json` + `contact-sheet.png`。

**四条机器判据**：

| 判据 | 量什么 | 阈值 | 通常意味着 |
|---|---|---|---|
| ⚠ 全黑 | YAVG（`signalstats`，16–235） | ≤ 18（纯黑 = 16） | 这一拍没渲染 / 时间轴没被 seek / 元素没显示 |
| ⚠ 爆白 | YAVG | ≥ 235 | 白蒙版忘了淡出 / 文字层叠了一屏 |
| ⚠ 无主运动 | 结构差 Δ（见 ③） | 镜内最大 Δ < 1.2 | 这一拍从头到尾主结构没变，只有细节在动 |
| ⚠ 重复渲染不一致 | 同一 t 两次渲染的原始分辨率像素差（见 ⑤） | > 0.5 | 有 `Math.random` / 实时钟 / 累加状态 / 墙钟 UI 混进了画面 |

**人工判读清单**（看接触印相，每格 3 秒）：

1. 文字是否都在安全区内、有没有被截断或挤出画面
2. 标签有没有互相叠住；同一位置是否出现两个说明
3. 每一拍是否有「主视觉」——大面积空屏 = 这一拍没设计
4. 文案与画面对不上（说了 A 画的是 B）
5. 连续几格几乎一样 = 节奏拖了
6. 读数/日志里的数字与文案是否一致

### ③ 结构差 Δ：抓「这一拍根本没动」

亮度判据只能回答"画面在不在"。它回答不了更常见的一种失效：

> **画面一直在动，但主结构从头到尾没变过。**
> 循环粒子在飘、扫描线在跑、光晕在呼吸 —— 观众却什么新信息都没拿到。

《HTML 科普视频制作流程学习手册》§13.1 的最后一问正是这个：
「这一镜能否被直接替换成普通标题页而不损失任何信息？」这一节把它变成可计算的量。

做法：把两帧各缩到 **32×18** 再求平均像素差。

```bash
ffmpeg -i a.png -i b.png -lavfi "[0]scale=32:18[x];[1]scale=32:18[y];[x][y]blend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG" -f null -
```

**为什么必须先缩小**：不缩小的话画面里永远有东西在动，逐像素差永远很大，什么也判不出来。
缩到 32×18（576 个采样点）后局部细节被平均掉，只剩结构性变化。

**实测校准**（两份真实样本，同一套参数）：

| 样本 | 镜内最大 Δ | 里面是什么在变 |
|---|---|---|
| 每场都有真实主运动的样片 | **2.18 ~ 24.43** | 数字滚动、标签逐条出现、坐标轴生长 |
| 镜内只有循环动效的样片 | **0.16 ~ 0.77** | 概率云缓慢接近、粒子旋转、涟漪循环 |

两组不重叠，门槛取 **1.2**（默认值，可用 `--motion-min` 覆盖）。

**灵敏度边界**（实测，别误读绝对值）：Δ 对**文字级变化**敏感（大块文本更换 → 1~24），
对 **canvas 几何渐变**偏钝（概率云间距收窄 34%、隧道 6 倍缩放 → 只有 0.2~0.8）。
所以 Δ 适合回答"这一拍有没有变化"，**不适合横向比较"哪一拍更精彩"**。

顺带验证过两条替代路线，都没采用：

- **全尺寸 SSIM** —— 会被粒子噪声污染。实测中动效最密集的那一场反而 SSIM 最低
  （0.942，低于真正更静的场），排序不可信。
- **96×54 SSIM** —— 排序与 Δ 一致，但数值语义不如像素差直观（0 = 完全一致）。

**入场段必须排除**：每个场景的第一个 Δ 量的是「标题与主图从无到有」，实测 4~7，
而镜内段只有 0.1~0.8。把它算进取值，所有场景都会判成"有运动"，判据直接失效。
工具取的是**镜内段（其余采样点）的最大值**，报告里单列一列「入场段 Δ」备查。

### ④ 主图 ROI：治「整帧被静止背景平均掉」

Δ 的第二个失效模式：**主图确实在动，但主图只占画面一角**，大面积静止背景把变化
平均掉了，整帧 Δ 被低估，于是判成「没动」。

修法：`--roi x,y,w,h`（0–1 归一化，相对**被截图的那个元素**）。给了它，先裁出这块
区域再缩到 32×18 算 Δ，**判定也切换到 ROI Δ**，同时保留整帧 Δ 做对照，并算出放大倍数。

```bash
# 只测画面中右部那块主图；配合 --selector 时坐标相对该元素
npm run qa:frames -- --url <url> --selector "#stage" --roi 0.48,0.2,0.48,0.63
```

实测放大效果（同一名外部样片，用作者自带的证据帧重算）：

| 场 | 整帧 Δ | ROI 内 Δ | 放大 |
|---|---|---|---|
| 原子尺度 | 0.393 | **1.234** | 3.14× |
| 神经系统 | 0.344 | **0.874** | 2.54× |
| 相互作用 | 2.027 | **4.844** | 2.39× |

**放大倍数在 1.5~3.1 倍之间**，足以把「整帧看着没动」翻成「其实一直在动」。

⚠ **ROI 改变量纲**：`1.2` 是按整帧校准的，ROI 模式下必须按 ROI 的分布重新标定。
工具会在 ROI 模式下打印这条警告，而不是让你悄悄沿用一个不成立的门槛。
（`--roi` 归一化坐标相对截图元素，所以做 ROI 分析时**务必配 `--selector`**，
否则坐标相对的是整个视口。）

### ⑤ 同一时刻重复渲染：抓「看着能播、实际不能导出」

前四条判据都在问「画面变了没有」。这条问的是另一个问题：
**同一个 t 渲染两次，画面一样吗？**

不一样就意味着这块画面里有**不受时间参数控制的输入**：`Math.random()`、
`Date.now()`/`performance.now()`、`x += v` 这类累加状态、相位不受控的无限动画、
第二次绘制才回来的异步数据。这类片子「看着能播」，但**永远不能被逐帧渲染管线接管**。

```bash
npm run qa:frames -- --url <url> --determinism --fail-on-nondeterministic
```

做法：同一个 t 连渲染两次，两帧在**原始分辨率**下比平均像素差（**故意不缩小** ——
非确定性常只落在少数像素上，缩到 32×18 会被平均掉）。真确定的实现这个值是 0，
默认容差 0.5。

**踩坑记录（这次新写的代码第一天就被它自己咬了一口，值得记下来）**：
初版判据用 `/YAVG=([0-9.]+)/` 解析 ffmpeg 的输出，而 ffmpeg 对「两帧几乎一样」打印的是
**科学计数法**：

```
lavfi.signalstats.YAVG=7.07334e-06      # 真值 0.00000707，即「完全一致」
```

正则只认 `[0-9.]`，把 `e-06` 截掉，于是 `7.07e-06` 被读成 **7.07** ——
一个「零差异」被报成「差异 7.07」。**而且是假阳性，恰好发生在最该判成「静止」的
场景上**（把该报警的镜头放过去）。修法是解析时带上指数部分：

```js
/YAVG=(-?[0-9]+(?:\.[0-9]+)?(?:e[-+]?[0-9]+)?)/i
```

教训：**判据的解析层本身也要被验证**。一个量错了的数字比没有数字更危险 ——
它会让你去改一个本来没问题的东西。发现它的方式很朴素：报告给出 7.073 后，
我没有直接采信，而是用另一套实现（Pillow 逐像素）重算了一遍，得到 0.000 且
无一个像素差异超过 10，两个数字对不上，才回头查解析。

### ⑥ 环境硬约束（工具实现时绕开的，换机器前先确认）

| 约束 | 影响 | 绕法 |
|---|---|---|
| 同步子进程一律 EBUSY | `spawnSync`/`execSync`/`execFileSync` 全废 | 只用**异步** `spawn`（`tools/qa-frames.mjs` 的 `run()`） |
| 子进程输出走管道会被 SIGTERM | 连带父进程一起死 | `stdio: ["pipe", fd, fd]` 重定向到文件，跑完再读 |
| `agent-browser` 是 sh shim | Windows 下 Node 无法直接 spawn | 解析到真实的 `node_modules/agent-browser/bin/agent-browser.js` 再用 node 跑 |
| ffmpeg 的 libavformat 没编 glob | `-pattern_type glob` 不可用 | 截图按 `%0Nd` 纯序号命名，走 image2 序列输入 |
| 日志含中文 | 字节偏移 ≠ 字符偏移 | 读回时用 `Buffer.subarray(from)` 按字节切 |

## 4. 坑清单（都是实锤过的，不是猜的）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 一整场文案消失 | `.sc > *` 漏 `position:absolute`，普通流排到画面外 | 见 §2.3 |
| 2 | 五个行星挤在 300px 里 | 对数轴量程跨 4 个数量级 | 量程砍到 1.5 个数量级以内，超出的用延伸注 |
| 3 | 标签互相叠住 | DOM 标签绝对定位写死坐标 | 改画布内右对齐 + 引线，历史项降透明度 |
| 4 | 三行文案同时出现又同时消失 | 时序重叠 | 递进-退场-定版，任何时刻最多一个主文案 |
| 5 | 读数显示「…」成三个大圆点 | 占位文本进了 96px mono 大读数 | 未开始/已结束的场把读数收起来 |
| 6 | 旋臂亮带像光束 | canvas 宽笔触 + 低透明度叠加 | 删掉，改纯粒子成形 |
| 7 | 改完全片白屏 | 内联脚本漏闭合括号 | 语法门禁（§3 ①） |
| 8 | 所有截图长得一样 | 页面报错没被看到，或 `render` 不是纯函数 | `window.__err` + 确定性契约（§1） |
