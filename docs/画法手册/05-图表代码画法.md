# 图表代码画法手册（数据坐标 → 屏幕坐标）

> 用途：**给定一种图表，代码怎么把它画出来**。
> 不讨论「该选哪种图」（那是选型文档的事），只讨论「落地怎么写」。
> 每条技法给可直接复制运行的最小代码 + **什么时候用**。
> 代码围栏统一 `js` / `html`；`html` 围栏里的片段粘进一个 `.html` 就能在浏览器看效果。

技法编号：`V01`–`V48`，末尾有索引表。

---

## 0. 地基：把数据坐标映射到屏幕坐标

所有手绘图表（SVG / Canvas / WebGL）都建立在这一步之上。库只是把这步包好了，原理不变。

### V01 线性映射公式

要把数据域 `[d0, d1]` 映射到屏幕值域 `[r0, r1]`：

```
ratio   = (value - d0) / (d1 - d0)          // 归一化到 0..1
screen  = r0 + ratio * (r1 - r0)            // 展开到目标值域
```

展开成一次函数就是斜率截距式：

```
k = (r1 - r0) / (d1 - d0)
b = r0 - k * d0
screen = k * value + b
```

```js
const k = (r1 - r0) / (d1 - d0);
const screen = r0 + (value - d0) * k;
```

**什么时候用**：任何「数值 → 位置/长度/颜色通道/半径/线宽」的映射。改图表尺寸时只改 `r0/r1`，映射逻辑不动。

**边界**：`d0 === d1` 时除零，得到 `Infinity/NaN`。单点数据要单独处理（见 V05）。

---

### V02 y 轴必须翻转

屏幕坐标 **y 向下增大**，数据通常 **y 向上增大**，所以纵向的值域要写成**反序**：`[plotHeight, 0]`。

```js
// 值越大 → 屏幕 y 越小（越靠上）
const y = (v) => plotHeight - (v - vMin) / (vMax - vMin) * plotHeight;
```

等价于 `k` 为负的一次映射。**忘了翻转是手绘图表最常见的第一个 bug**（图会上下颠倒）。

**什么时候用**：所有笛卡尔坐标系图表。极坐标/弧长映射不需要。

---

### V03 内边距（plot area）的完整推导

版心 = 整张画布；绘图区 = 版心减去四边留白。留白给坐标轴、刻度标签、标题用。

```
plotWidth  = W - margin.left - margin.right
plotHeight = H - margin.top  - margin.bottom
```

分两步走，**先算相对绘图区的坐标，再加偏移得到绝对坐标**：

```
// 第 1 步：数据 → 绘图区内的相对坐标
xRel = (i / (n - 1)) * plotWidth          // n = 点数
yRel = plotHeight - ((v - vMin) / (vMax - vMin)) * plotHeight

// 第 2 步：相对坐标 → 绝对坐标（加上左边距、上边距）
X = margin.left + xRel
Y = margin.top  + yRel
```

举例：`W=600, H=400, margin={t:40,r:30,b:50,l:60}` →

```
plotWidth  = 600 - 60 - 30 = 510
plotHeight = 400 - 40 - 50 = 310
```

一行代码的等价写法（把偏移直接并进值域）：

```js
// 纵向：数据域 → [margin.top + plotHeight, margin.top]
const y = (v) => M.t + plotHeight - (v - vMin) / (vMax - vMin) * plotHeight;
```

**什么时候用**：**一律这么写**。把「相对坐标」和「绝对坐标」在脑子里分成两件事，改布局时不会算乱。导出静态图、算 hover 命中区、画十字准线都依赖这个两段式。

### V04 十行 `scaleLinear` 替代品（零依赖）

不引任何库，手搓等价的线性比例尺。带 `invert`（屏幕坐标反查数据值，交互时要用）。

```js
function scaleLinear(domain, range) {
  const [d0, d1] = domain;
  const [r0, r1] = range;
  const k = (r1 - r0) / (d1 - d0);       // 斜率
  const f = (v) => r0 + (v - d0) * k;     // 数据 → 屏幕
  f.invert = (p) => d0 + (p - r0) / k;    // 屏幕 → 数据
  f.domain = domain;
  f.range = range;
  return f;
}

// 用法
const x = scaleLinear([0, 100], [0, 510]);
const y = scaleLinear([0, 80], [310, 0]);   // 注意值域反序 = 自动翻转 y
x(50);        // 255
y.invert(310); // 0
```

**什么时候用**：只要图不复杂就别引库，这 10 行覆盖 90% 的笛卡尔图。需要 nice/ticks 时见 V25。

### V05 离散 → 位置的 `scaleBand`（柱状图专用）

柱状图的 x 是**分类**不是数值，要算「每格多宽、格子从哪开始、每个类的带宽」。

```js
function scaleBand(domain, range, paddingInner = 0.2, paddingOuter = 0.2) {
  const n = domain.length;
  const [start, stop] = range;
  // 1 个 step 里包含 1 个带宽 + 内部间隙；两端再加外侧间隙
  const step = (stop - start) / Math.max(1, n - paddingInner + paddingOuter * 2);
  const bandwidth = step * (1 - paddingInner);
  const idx = new Map(domain.map((d, i) => [d, i]));   // 分类值 → 下标
  const f = (d) => start + step * paddingOuter + step * idx.get(d);
  f.bandwidth = bandwidth;
  f.step = step;
  return f;
}

// 用法：6 个分类，绘图区宽 510
const xb = scaleBand(["A", "B", "C", "D", "E", "F"], [0, 510]);
xb("C");          // 该柱左边缘的 x
xb("C") + xb.bandwidth;  // 该柱右边缘
```

**什么时候用**：柱状图、堆叠柱、柱状刻度轴、网格热力图的分组标签。**别用 `scaleLinear` 画柱子**——会得到错误的柱宽和不对齐的间隙。

**边界**：`domain` 里重复值会让 `Map` 只留最后一个下标；分类必须唯一。`n === 0` 时返回 `NaN`，先挡掉空数据。

### V06 手绘折线图（完整 SVG）

把 V01/V03/V04 串起来。这条路径**不含任何库**。

```html
<!doctype html>
<meta charset="utf-8">
<svg id="line" width="600" height="400" viewBox="0 0 600 400"
     xmlns="http://www.w3.org/2000/svg"></svg>
<script>
  const data = [12, 34, 28, 51, 43, 66, 58, 72];

  const W = 600, H = 400;
  const M = { t: 40, r: 30, b: 50, l: 60 };
  const pw = W - M.l - M.r;   // 510
  const ph = H - M.t - M.b;   // 310

  // 比例尺：x 用序号，y 用数据值（值域反序 = 翻转 y）
  const n = data.length;
  const yMax = 80;
  const x = (i) => M.l + (n === 1 ? pw / 2 : (i / (n - 1)) * pw);
  const y = (v) => M.t + ph - (v / yMax) * ph;

  // 生成 path 的 d：M 起点，之后全部 L
  const d = data.map((v, i) => `${i ? "L" : "M"} ${x(i)} ${y(v)}`).join(" ");

  const svg = document.getElementById("line");
  svg.innerHTML = `
    <path d="${d}" fill="none" stroke="#3b82f6" stroke-width="3"
          stroke-linejoin="round" stroke-linecap="round"/>
    <circle cx="${x(n - 1)}" cy="${y(data[n - 1])}" r="4" fill="#3b82f6"/>`;
</script>
```

生成的静态 SVG（可直接贴）：

```svg
<svg width="600" height="400" viewBox="0 0 600 400" xmlns="http://www.w3.org/2000/svg">
  <path d="M 60 263.5 L 132.86 178.25 L 205.71 201.5 L 278.57 112.38 L 351.43 143.38 L 424.29 54.25 L 497.14 85.25 L 570 30.5"
        fill="none" stroke="#3b82f6" stroke-width="3" stroke-linejoin="round" stroke-linecap="round"/>
</svg>
```

**什么时候用**：需要精确控制坐标轴、标注、图例版式；需要把「线」「点」「标签」拆成独立元素分别动画（见 V44）。

### V07 手绘柱状图（完整 SVG）

同样三件套，但 x 换成 `scaleBand`。

```html
<!doctype html>
<meta charset="utf-8">
<svg id="bar" width="600" height="400" viewBox="0 0 600 400"
     xmlns="http://www.w3.org/2000/svg"></svg>
<script>
  const labels = ["A", "B", "C", "D", "E", "F"];
  const values = [12, 34, 28, 51, 43, 66];

  const W = 600, H = 400;
  const M = { t: 40, r: 30, b: 50, l: 60 };
  const pw = W - M.l - M.r;
  const ph = H - M.t - M.b;

  function scaleBand(domain, range, pi = 0.3, po = 0.3) {
    const n = domain.length, [s, e] = range;
    const step = (e - s) / Math.max(1, n - pi + po * 2);
    const bw = step * (1 - pi);
    const idx = new Map(domain.map((d, i) => [d, i]));
    const f = (d) => s + step * po + step * idx.get(d);
    f.bandwidth = bw;
    return f;
  }

  const xb = scaleBand(labels, [0, pw]);
  const yMax = 70;
  const y = (v) => M.t + ph - (v / yMax) * ph;   // 柱顶
  const baseY = y(0);                            // 柱底（基线）

  const svg = document.getElementById("bar");
  svg.innerHTML = labels.map((c, i) => {
    const bx = M.l + xb(c);
    const by = y(values[i]);
    return `<rect x="${bx}" y="${by}" width="${xb.bandwidth}"
                  height="${baseY - by}" fill="#10b981" rx="3"/>`;
  }).join("");
</script>
```

要点：
- 柱高 = `baseY - by`（**基线在屏幕上的 y 减柱顶 y**，别写成 `by - baseY`）。
- 柱子必须从 `y(0)` 长出来；如果 y 轴不截断（`vMin=0`），基线就在绘图区底部。

**什么时候用**：分类比较。配合 V27 的长标签避让 + V46 的排序原则。

## 1. D3 的「只取计算、不要渲染」用法

D3 的 `d3-scale` / `d3-shape` 是**纯数学模块，不碰 DOM**。只引这两个子包，拿到 `scale` 的函数和 `path` 的 `d` 字符串，再自己写 SVG/Canvas 渲染——既白嫖 D3 的数学，又不受它 `selection` 数据绑定模型的绑架。

### V08 为什么要拆开用

| 只用 D3 的计算 | 用 D3 的整套（enter/update/exit） |
|---|---|
| 数学留在手里，渲染随便换（SVG / Canvas / WebGL） | 渲染被 `d3-selection` 绑定 |
| 和 React/Vue 改造点重叠少 | 两套 DOM 模型容易打架 |
| 只引 2 个 ESM 子包，tree-shaking 干净 | 容易整个 d3 进包 |

**什么时候用**：你自己的组件已经管理着 DOM（框架组件、手写渲染循环），只需要「比例尺 + path 数学」。

### V09 单独引入

只装、只引需要的子包：

```js
import { scaleLinear, scaleBand, scaleTime, scaleLog } from "d3-scale";
import { line, area, arc, pie, stack, curveBasis } from "d3-shape";
```

它们**不依赖 `d3-selection`**，引进来不会顺带拖入 DOM 模块。浏览器里也可以只做纯计算：

```js
const gen = line().x((d) => x(d.x)).y((d) => y(d.y));
const d = gen(points);              // 返回字符串，不生成任何 DOM 节点
somePath.setAttribute("d", d);      // 渲染交给自己
```

**什么时候用**：想让「计算」和「渲染」分家时，这是标准入口。

### V10 `scaleLinear` 的 domain / range / nice / ticks / invert

D3 的比例尺比 V04 的手搓版多几个关键能力：

```js
import { scaleLinear } from "d3-scale";

const y = scaleLinear()
  .domain([0, 83])        // 数据域
  .range([310, 0])        // 值域（反序 = 翻转 y）
  .nice(5);               // 把 domain 扩到好看的整刻度，比如 [0, 100]

y(41);                    // 位置
y.invert(155);            // 反查数据值
y.ticks(5);               // 候选刻度：[0, 20, 40, 60, 80, 100]
y.tickFormat(5, "+%");    // 刻度格式化函数：+20%, -10% 之类
```

- `nice(n)`：向外扩 `domain` 到「下一步长」的整数倍，让轴端点是圆整数值。**这是它比 V04 值得用的第一个理由。**
- `ticks(n)`：返回**近似 n 个**「1/2/5×10^k」型候选刻度。**第二个理由。**
- `tickFormat(count, specifier)`：返回一个把刻度值转成字符串的函数（内部就是 `d3-format`）。
- `invert()`：交互必需。

**什么时候用**：需要自动刻度（V25）、需要 `invert` 做 hover、需要格式化标签时。

### V11 `scaleBand` / `scalePoint`：分类轴

```js
import { scaleBand, scalePoint } from "d3-scale";

const xb = scaleBand()
  .domain(["A", "B", "C", "D"])
  .range([0, 510])
  .paddingInner(0.2)     // 柱间间隙（占 step 的比例）
  .paddingOuter(0.2)     // 两端留白
  .align(0.5);           // 整组对齐方式

xb("B");           // 该柱左边缘
xb.bandwidth();    // 柱宽
xb.step();         // 相邻柱起点间距

// 折线图的点轴（无宽度、只有位置）：用 point
const xp = scalePoint().domain(["A","B","C"]).range([0, 510]).padding(0.5);
```

**什么时候用**：柱状图用 `band`（有宽度）；折线/散点的分类轴用 `point`（只取一个点位置）。`paddingInner` 控制柱间空隙，`paddingOuter` 控制两端留白，`align` 控制整体居中与否（默认 0.5）。

### V12 `scaleTime` / `scaleLog` / `scalePow`：换映射不是换图

| 子模块 | 适用数据 | 关键点 |
|---|---|---|
| `scaleLinear` | 普通定量数据 | 默认选择 |
| `scaleTime` | 时间序列 | 输入 `Date`，`ticks()` 自动给「月/年/天」这类人类刻度 |
| `scaleLog` | 跨数量级的正数（1 到 1000000） | 不能有 0 或负数；`base(10)` 可调 |
| `scalePow` | 也有大范围，但允许 0/负数 | `exponent(0.5)` 近似开方，用来压平长尾 |
| `scaleSymlog` | 跨 0 的数量级数据 | 0 点附近近似线性，远处对数 |
| `scaleOrdinal` | 分类 → 颜色/形状 | 配 `d3-scale-chromatic` 出配色 |
| `scaleQuantile` / `quantize` / `threshold` | 连续值 → 离散档位 | 分级填色、分段色阶 |

```js
import { scaleTime, scaleLog } from "d3-scale";

const tx = scaleTime().domain([new Date(2020, 0, 1), new Date(2024, 0, 1)]).range([0, 510]);
const ly = scaleLog().domain([1, 1e6]).range([310, 0]).base(10);
```

**什么时候用**：**换映射不动图形代码**——这是比例尺最大的价值。对数和线性图的区别只是构造时换一个函数，`path` 生成逻辑一个字都不用改。

### V13 `d3.line`：生成折线的 `d`

```js
import { line } from "d3-shape";

const genLine = line()
  .x((d) => x(d.date))
  .y((d) => y(d.value))
  .defined((d) => d.value != null);   // 空值处断线，而不是连过去

const d = genLine(data);   // "M0,300L50,280L100,250…"
pathEl.setAttribute("d", d);
```

- `.x()/.y()` 是 accessor，**返回屏幕坐标**（比例尺在这里调用）。
- `.defined()` 让缺失数据产生**断点**，而不是把不存在的点连成直线。
- 结果就是普通 `d` 字符串，可以塞进任何 `<path>`，也能交给 Canvas（V18）。

**什么时候用**：任何想用 D3 算折线但自己渲染的场合。

### V14 `d3.area`：生成面积图的 `d`

```js
import { area } from "d3-shape";

const genArea = area()
  .x((d) => x(d.date))
  .y0(y(0))            // 下边界（基线，可以是常数或 accessor）
  .y1((d) => y(d.value));   // 上边界

const d = genArea(data);   // 自动闭合成面积
pathEl.setAttribute("d", d);
```

**什么时候用**：面积图、堆叠面积（`y0` 用堆叠后的下界）、带状区间（置信区间：`y0` 取下界、`y1` 取上界）。

### V15 `d3.arc` + `d3.pie`：饼图/甜甜圈的 `d`

`arc` 是**几何**生成器，`pie` 是**角度**计算器，两个配合用：

```js
import { arc, pie } from "d3-shape";

const data = [{ k: "A", v: 30 }, { k: "B", v: 50 }, { k: "C", v: 20 }];

// 1) pie 把值 → 起止角（弧度，0 在 12 点方向、顺时针为正）
const angles = pie().sort(null).value((d) => d.v)(data);
// 每项拿到 startAngle / endAngle / padAngle

// 2) arc 把角 → path
const genArc = arc()
  .innerRadius(0)       // 0 = 饼图；>0 = 甜甜圈
  .outerRadius(120)
  .cornerRadius(4);     // 圆角扇区（可选）

document.querySelector("svg").innerHTML = angles.map((a) =>
  `<path d="${genArc(a)}" fill="${color(a.data.k)}"/>`
).join("");
```

**什么时候用**：饼图、甜甜圈（`innerRadius > 0`）、玫瑰图（`outerRadius` 做成 accessor）、桑基/和弦图的弧段。
**注意**：d01 的坑清单里明确「人眼不擅长读角度」——能用柱状图就别用饼图；非要用，直接标注每片，别放侧边图例。

### V16 `d3.stack`：堆叠

`stack` 把多序列的数值转成 `[y0, y1]` 区间对，正好喂给 `area().y0().y1()` 或堆叠柱：

```js
import { stack, area, scaleLinear } from "d3-shape";

const series = [
  { name: "A", values: [10, 20, 30, 40] },
  { name: "B", values: [15, 15, 15, 15] },
  { name: "C", values: [5, 10, 5, 20] },
];

const y = scaleLinear().domain([0, 90]).range([310, 0]);
const layers = stack().keys(["A", "B", "C"])(series);
// layers[i][j] = [y0, y1]（数据值，不是像素）

const genArea = area()
  .x((d, j) => x(j))
  .y0((d) => y(d[0]))       // 下界
  .y1((d) => y(d[1]));      // 上界

layers.forEach((layer, i) => {
  const d = genArea(layer);
  // 渲染成 <path>，一层一条
});
```

**什么时候用**：堆叠面积、堆叠柱、河流图的基础。堆叠顺序会显著影响可读性，**多试几种顺序**。

### V17 `curve*` 插值曲线清单

`line().curve(...)` / `area().curve(...)` 决定点与点**之间怎么走**：

| 曲线 | 形状 | 什么时候用 |
|---|---|---|
| `curveLinear` | 直线段 | 默认；数据本身稀疏、不想暗示插值 |
| `curveMonotoneX` | 单调（不过冲） | **折线图首选**：平滑且不会在点之间冲过头造出假峰 |
| `curveBasis` | B 样条，平滑 | 只要趋势、不要求过每个点 |
| `curveCardinal` | 经过点的样条 | 要平滑且经过点，可调 `tension` |
| `curveCatmullRom` | 经过点的样条 | 同上，类 `curveCardinal`，常用 `alpha=0.5` |
| `curveNatural` | 自然三次样条 | 形状平缓的平滑曲线 |
| `curveStep` / `curveStepAfter` / `curveStepBefore` | 阶梯 | 状态/阈值随时间变化、离散取值 |
| `curveBumpX` | 起终点平缓的弧 | 连接两点的过渡；桑基/和弦的连线感 |

```js
import { line, curveMonotoneX, curveStepAfter } from "d3-shape";

const smooth = line().x(X).y(Y).curve(curveMonotoneX);
const step   = line().x(X).y(Y).curve(curveStepAfter);
```

**什么时候用**：折线图默认上 `curveMonotoneX`（平滑且不骗人）；数据是「突变型」用 `curveStep`；数据点稀疏、不能被平滑误导时老实用 `curveLinear`。

### V18 `line.context(ctx)`：同一份生成器渲染到 Canvas

同一个生成器既能出 SVG `d`，也能**直接画到 Canvas**——注意带了 `context` 之后返回 `undefined`，不再返回字符串：

```js
import { line, curveMonotoneX } from "d3-shape";

const gen = line().x(X).y(Y).curve(curveMonotoneX);
const ctx = canvas.getContext("2d");

// 渲染到 Canvas2D：先设置好样式，再调用生成器
ctx.beginPath();
gen.context(ctx)(data);      // 描边路径已加入当前路径
ctx.stroke();
```

**什么时候用**：同一套数据处理既要出 SVG（静态导出/打印）又要出 Canvas（大数据量/高频动画帧）时，只写一份 accessor。

## 2. 常见图表的 SVG path 生成法（纯手写，无 D3）

只要理解了 `d` 的语法，任何图表都能手搓。下面每种给**数学说明 + 生成代码 + 成品 SVG**。

### V19 折线：`M` + 若干个 `L`

```
d = "M x0,y0 L x1,y1 L x2,y2 …"
```

```js
function polylinePath(points) {           // points: [[x,y], …]
  if (!points.length) return "";
  return points.map(([x, y], i) => `${i ? "L" : "M"}${x},${y}`).join("");
}
```

**什么时候用**：默认折线形状。点少、要「诚实」不插值。

### V20 平滑曲线：Catmull-Rom → 三次贝塞尔

直线段拐角硬。想平滑且**曲线经过每个数据点**，用 Catmull-Rom 样条，再把它**转成 SVG 的三次贝塞尔 `C`**（SVG 没有样条图元，只能转成贝塞尔）。

对相邻四点 `p0, p1, p2, p3`，段 `p1→p2` 的两个控制点：

```
c1 = p1 + (p2 - p0) / 6
c2 = p2 - (p3 - p1) / 6
```

首尾各复制一个端点当虚拟点。张力 `tension=1` 时就是标准（均匀）Catmull-Rom。

```js
function smoothPath(points, tension = 1) {
  const p = points;
  if (p.length < 2) return p.length ? `M${p[0][0]},${p[0][1]}` : "";
  let d = `M${p[0][0]},${p[0][1]}`;
  for (let i = 0; i < p.length - 1; i++) {
    const p0 = p[i - 1] || p[i];
    const p1 = p[i];
    const p2 = p[i + 1];
    const p3 = p[i + 2] || p2;
    const c1x = p1[0] + ((p2[0] - p0[0]) / 6) * tension;
    const c1y = p1[1] + ((p2[1] - p0[1]) / 6) * tension;
    const c2x = p2[0] - ((p3[0] - p1[0]) / 6) * tension;
    const c2y = p2[1] - ((p3[1] - p1[1]) / 6) * tension;
    d += `C${c1x},${c1y} ${c2x},${c2y} ${p2[0]},${p2[1]}`;
  }
  return d;
}
```

**参数化圆（弧）版**：若想把圆换成贝塞尔逼近，四段三次贝塞尔的魔法常数是 `0.5523`：控制点偏移 = `r * 0.5523`。手写圆/圆角多用这个。

```js
// 用 4 段贝塞尔拟合半径 r、圆心 (cx,cy) 的圆
const h = r * 0.5523;
const d =
  `M${cx},${cy - r}` +
  `C${cx + h},${cy - r} ${cx + r},${cy - h} ${cx + r},${cy}` +
  `C${cx + r},${cy + h} ${cx + h},${cy + r} ${cx},${cy + r}` +
  `C${cx - h},${cy + r} ${cx - r},${cy + h} ${cx - r},${cy}` +
  `C${cx - r},${cy - h} ${cx - h},${cy - r} ${cx},${cy - r}Z`;
```

**什么时候用**：折线太硬、要「生长感」曲线；做 streamgraph、示意图曲线、需要弧形连线时。
**注意**：张力大会**过冲**（在点之间冲出数据范围），造成视觉上的假峰。数据是「不允许过冲」的类型（如非负的比例、浓度）改用单调插值（对应 D3 的 `curveMonotoneX`，见 V17）。

### V21 面积图：折线 + 回填 + 闭合

面积 = 上边界折线（右→进）→ 拉到基线 → 回到起点 → `Z` 闭合。

```
d = 上边界点序列 (M…L…)  +  L 最后一点基线  +  L 第一点基线  +  Z
```

```js
function areaPath(points, baseY) {   // points: [[x,y],…]，baseY = 基线屏幕 y
  if (!points.length) return "";
  const top = points.map(([x, y], i) => `${i ? "L" : "M"}${x},${y}`).join("");
  const [fx] = points[0];
  const [lx] = points[points.length - 1];
  return `${top}L${lx},${baseY}L${fx},${baseY}Z`;
}
```

成品（线深、填充浅是同色透明，d01 推荐的做法）：

```svg
<svg width="600" height="400" viewBox="0 0 600 400" xmlns="http://www.w3.org/2000/svg">
  <path d="M60,263.5 L160,190 L260,220 L360,120 L460,160 L560,60 L560,350 L60,350 Z"
        fill="#3b82f6" fill-opacity="0.18"/>

```

**技巧**：面积填充和轮廓线用**同一个颜色**，填充加 `fill-opacity`，视觉最干净。

**什么时候用**：单个变量随时间的累积量、置信区间带、堆叠面积的每一层。
**坑**：堆叠面积里读某一层的绝对值很难（要心算减去下层高度），d01 建议优先考虑小倍数图或折线图。

### V22 柱状图：`rect` 还是 `path`

最简单的柱就是 `<rect>`（见 V07）。需要圆角只在顶角、或需要和折线共用一条 path 时用 path：

```js
// 只有顶部两角圆角的柱子
function barPath(x, y, w, h, r = 4) {
  r = Math.min(r, w / 2, h);
  return `M${x},${y + h}` +
         `L${x},${y + r}` +
         `Q${x},${y} ${x + r},${y}` +                     // 左上圆角
         `L${x + w - r},${y}` +
         `Q${x + w},${y} ${x + w},${y + r}` +             // 右上圆角
         `L${x + w},${y + h}Z`;
}
```

**什么时候用**：需要精细柱形（圆角、非矩形、和动画路径统一）时用 path；普通矩形老实用 `rect`，浏览器渲染更省。

### V23 堆叠柱：先累加基线，再给每段算起止 y

堆叠的本质是**第二层的下界 = 第一层的上界**。

```js
function stack(valuesBySeries) {          // [[A0,A1,…],[B0,B1,…],…] 按「列」排
  const n = valuesBySeries[0].length;
  const baseline = new Array(n).fill(0);
  return valuesBySeries.map((series) =>
    series.map((v, i) => {
      const y0 = baseline[i];              // 这一列当前已堆到的高度（数据值）
      const y1 = y0 + v;
      baseline[i] = y1;
      return [y0, y1];                     // 单位是数据值
    })
  );
}

// 渲染（y 已经是「数据值 → 屏幕」的比例尺）
const layers = stack([[10, 20, 30], [15, 15, 15], [5, 10, 5]]);
layers.forEach((layer, s) => layer.forEach(([y0, y1], i) => {
  const top = y(y1), bottom = y(y0);
  const bx = M.l + xb(labels[i]);
  // 渲染 <rect y=top height=bottom-top>
}));
```

**什么时候用**：堆叠柱、堆叠面积（把 `[y0,y1]` 交给 V14 的 `area().y0().y1()`）。
**坑**：组内顺序（从下到上谁在前）影响可读性，**换几种顺序试试**；负值堆叠要分别往上下两个方向累加。

### V24 饼图 / 甜甜圈：`arc` 的四段结构

一条扇区 path 由**四段**组成：外弧 → 侧边 → 内弧 → 侧边，最后 `Z`。

```
M 外弧起点
A R,R 0 largeArc,1 外弧终点        ← 外弧（sweep=1 顺时针）
L 内弧终点
A r,r 0 largeArc,0 内弧起点        ← 内弧（sweep=0 逆时针走回来）
Z
```

- 圆上一点：`x = cx + R·cos θ`，`y = cy + R·sin θ`（θ 单位弧度；屏幕 y 向下，θ 增大 = 顺时针）。
- `largeArcFlag = (Δθ > π) ? 1 : 0`：**超过半圈才能取 1**，否则弧会走错边。
- `sweepFlag`：外弧 `1`、内弧 `0`。
- `R` 是外半径，`r` 是内半径（`r=0` 时退化成饼图，用 `M cx,cy L 外弧起点` 起手）。
- **`Δθ ≥ 2π`（整圆）时单段弧会失效**，要拆成两段。

```js
function arcPath(cx, cy, R, r, a0, a1) {     // a0,a1 弧度，a1>a0
  const pt = (rad, ang) => [cx + rad * Math.cos(ang), cy + rad * Math.sin(ang)];
  const large = (a1 - a0) > Math.PI ? 1 : 0;
  const [x0, y0] = pt(R, a0);
  const [x1, y1] = pt(R, a1);

  if (r === 0) {                              // 饼图
    return `M${cx},${cy}L${x0},${y0}A${R},${R} 0 ${large},1 ${x1},${y1}Z`;
  }
  const [x2, y2] = pt(r, a1);
  const [x3, y3] = pt(r, a0);
  return `M${x0},${y0}` +
         `A${R},${R} 0 ${large},1 ${x1},${y1}` +   // 外弧
         `L${x2},${y2}` +                          // 侧边
         `A${r},${r} 0 ${large},0 ${x3},${y3}` +   // 内弧
         `Z`;
}

// 值 → 角度：从 -90°（12 点方向）起、顺时针分配
function toAngles(values) {
  const total = values.reduce((a, b) => a + b, 0);
  let acc = -Math.PI / 2;
  return values.map((v) => {
    const a0 = acc;
    const a1 = acc + (v / total) * Math.PI * 2;
    acc = a1;
    return [a0, a1];
  });
}
```

成品（3 片、甜甜圈内半径 60）：

```svg
    <path d="M103.9,60 A120,120 0 0 1 -103.9,60 L-51.9,30 A60,60 0 0 0 51.9,30 Z" fill="#10b981"/>
    <path d="M-103.9,60 A120,120 0 0 1 0,-120 L0,-60 A60,60 0 0 0 -51.9,30 Z" fill="#f59e0b"/>
  </g>

```

**什么时候用**：占比（甜甜圈中间还能放总数）、玫瑰图（`R` 随值变）、和弦图/桑基图的弧段端点。

### V25 刻度算法：nice numbers

要让刻度落在 `1 / 2 / 5 × 10^k` 上（而不是 `0, 23.7, 47.4…`），用经典 Heckbert 算法：

```js
// 找出「刚好不小于 range」的 1/2/5×10^k
function niceNum(range, round) {
  const exp = Math.floor(Math.log10(range));
  const f = range / Math.pow(10, exp);
  let nf;
  if (round) {
    if (f < 1.5) nf = 1; else if (f < 3) nf = 2; else if (f < 7) nf = 5; else nf = 10;
  } else {
    if (f <= 1) nf = 1; else if (f <= 2) nf = 2; else if (f <= 5) nf = 5; else nf = 10;
  }
  return nf * Math.pow(10, exp);
}

function niceScale(min, max, maxTicks = 6) {
  if (min === max) { min -= 1; max += 1; }              // 退化为单点
  const range = niceNum(max - min, false);
  const step = niceNum(range / (maxTicks - 1), true);
  const niceMin = Math.floor(min / step) * step;
  const niceMax = Math.ceil(max / step) * step;
  const ticks = [];
  for (let v = niceMin; v <= niceMax + step / 2; v += step) ticks.push(v);
  return { min: niceMin, max: niceMax, step, ticks };
}

niceScale(3, 87);
// → { min:0, max:100, step:20, ticks:[0,20,40,60,80,100] }
```

**什么时候用**：任何要画坐标轴的场合。先 `niceScale` 拿到圆整的 `[min,max]` 和 `ticks`，**再用这个 `[min,max]` 去构造比例尺**（顺序不能反，否则轴端点和数据范围会错位）。

### V27 刻度标签避让

标签比刻度密的时候会重叠。四种解法，按推荐度排：

```js
// 1) 隔一个显示（最省事，x 轴常用）
const shown = ticks.filter((_, i) => i % 2 === 0);

// 2) 旋转（-45° 斜排），配 text-anchor="end"
`<text transform="rotate(-45 ${x} ${y})" text-anchor="end">2024-Q1</text>`

// 3) 缩写（1000 → 1k，1000000 → 1M）
const fmt = (v) => v >= 1e6 ? (v / 1e6) + "M" : v >= 1e3 ? (v / 1e3) + "k" : v;

// 4) 分类标签太长 → 改横向柱状图（标签跑到左侧，天然不挤）
```

**经验判据**：文字宽度 ≈ `字数 × 字号 × 0.6`。相邻标签间距 < 这个宽度就重叠了。

**什么时候用**：**分类标签长的时候优先把柱状图改成横向**（d01 明确列为常见坑的推荐解），比旋转更易读；连续轴密了优先隔位显示。

### V29 Canvas 渲染的取舍

Chart.js 用 **HTML5 Canvas** 渲染，不是 SVG。带来的取舍：

| 得到 | 失去 |
|---|---|
| 大数据量下性能好（不会往 DOM 塞几千个节点） | **不能用 CSS 给图元加样式**，样式得走内置 `options` 或自定义 plugin/图表类型 |
| 树摇友好，按需引部分代码 | 图元无法被 CSS 选中、无法用 CSS 过渡动画 |
| 混合图（一个 canvas 上叠多种 type）容易 | 导出的不是矢量路径，交给设计软件二次编辑不友好 |

```js
// 混合图：同一画布叠折线 + 柱
new Chart(ctx, {
  data: {
    labels,
    datasets: [
      { type: "bar",  data: [5, 20, 36, 10] },
      { type: "line", data: [8, 18, 30, 14] }
    ]
  }
});
```

**什么时候用**：数据量大、图元多、只需视觉呈现不需要 CSS 参与时。**需要 CSS 参与版式/图元级动画时改用手绘 SVG（V06/V07）或 ECharts 的 SVG 渲染器（V35）。**

### V30 常用插件

Chart.js 本身是核心，扩展（标注、缩放、拖拽、数据标签）以**插件**形式加：

用途：`annotation`（画参考线/注释框）、`zoom`（滚轮缩放 + 拖拽平移）、数据标签直接写在图元上、拖拽改数据点。

**什么时候用**：需要「图上加条基准线」「允许用户缩放」「把数值直接标在柱上」这类交互时优先找现成插件，别自己写渲染。

### V31 响应式与 DPR

```js
new Chart(ctx, {
  options: {
    responsive: true,             // 默认开：容器变化时自动重绘
    maintainAspectRatio: false,   // 关掉固定宽高比，交给容器高度
    devicePixelRatio: 2           // 一般不用管，默认跟随屏幕
  }
});
```

规则：
- `responsive: true` 时，**容器必须有确定的尺寸**（不能是 0 高度），否则图会塌成 0。
- 想摆脱默认 `2:1` 宽高比就设 `maintainAspectRatio: false`，并给外层容器定高。
- Chart.js **内部自己处理 DPR**（高 DPI 下自动放大 canvas 再缩显示），一般不用手动调。

**什么时候用**：嵌入响应式布局（Flex/Grid 容器）时必看这两条。**手绘 Canvas 时** DPR 得自己处理：

```js
const dpr = window.devicePixelRatio || 1;
canvas.width = cssW * dpr;
canvas.height = cssH * dpr;
canvas.style.width = cssW + "px";
canvas.style.height = cssH + "px";
ctx.scale(dpr, dpr);      // 之后按 CSS 像素坐标画
```

### V32 大数据量的两个开关

```js
new Chart(ctx, {
  data: { datasets: [{ data: bigArray }] },
  options: {
    parsing: false,                                    // 数据已是 {x,y} 内部格式，跳过解析
    plugins: { decimation: { enabled: true, algorithm: "lttb" } }  // 抽稀降采样
  }
});
```

- **跳过解析**：数据按 Chart.js 的**内部格式**喂进去，省掉格式归一化开销。
- **抽稀（decimation）**：渲染前先采样减点数，保留趋势（LTTB 算法）。

**什么时候用**：上万点的折线/散点。几千点以内不用管。

### V33 动画

Chart.js **默认开启动画**，不用配置就有入场效果。要关或要调：

```js
options: { animation: false }                                  // 全关
options: { animation: { duration: 600, easing: "easeOutQuart" } }
options: { animations: { y: { from: 0 } } }                    // 只让 y 从 0 长出来
```

**什么时候用**：默认动画已经够用；要「柱子从 0 生长」这类定制效果，用 `animations.y.from` 比手写 rAF 省事。**但若图表要和页面其它动画编舞（严格时间轴、逐帧、和其它元素同步），就该上手绘 SVG（见第 4 节）。**

### V35 SVG 渲染器 vs Canvas 渲染器

`echarts.init` 第三个参数指定渲染器：


| | Canvas 渲染器（默认） | SVG 渲染器 |
|---|---|---|
| 适合 | **图元极多 / 大数据量**（几万点、密集热力图） | 图元少、需要**矢量** |
| 导出 | 位图 | 矢量，**打印/放大不糊** |
| 交互 | 内部命中检测，稳定 | 图元是 DOM，可被 CSS/工具选中 |
| 服务端渲染 | 需要 canvas | **SSR 友好**（无需 canvas 也能出图） |
| 大数据性能 | 好 | 图元多时 DOM 压力大 |

**判据**：图元总数几千以内、或者要打印/SSR/被设计工具二次编辑 → **SVG 渲染器**；几万点以上、密集散点/热力图 → **Canvas 渲染器**。

**什么时候用**：需要矢量导出或服务端出图就必须显式写 `renderer: "svg"`；其余默认 canvas 即可。

### V36 按需引入（减包体）

从 `echarts/core` 入口，只 `use()` 用到的模块：

```js
import * as echarts from "echarts/core";
import { BarChart, LineChart, PieChart } from "echarts/charts";
import {
  GridComponent, TooltipComponent, TitleComponent, LegendComponent
} from "echarts/components";
import { CanvasRenderer, SVGRenderer } from "echarts/renderers";

echarts.use([
  BarChart, LineChart, PieChart,
  GridComponent, TooltipComponent, TitleComponent, LegendComponent,
  CanvasRenderer            // 或 SVGRenderer
]);

const chart = echarts.init(document.getElementById("main"));
chart.setOption({ /* … */ });
```

规则：**用什么引什么**——图表类型从 `echarts/charts`、组件从 `echarts/components`、渲染器从 `echarts/renderers`。图表类型和组件（尤其 `GridComponent`）**不 use 上就画不出来**，只引 `echarts/core` 会得到空图。

**什么时候用**：打包体积敏感的前端项目；页面上只用一两种图时，按需引入能把 ECharts 从几百 KB 压到几十 KB。

### V37 Canvas 渲染器下的常见 option 块

```js
chart.setOption({
  // 视觉映射：把数值映射到颜色/大小，不用手算
  visualMap: {
    type: "continuous", min: 0, max: 100,
    inRange: { color: ["#dbeafe", "#1e3a8a"] }     // 连续色阶（避开彩虹色）
  },
  // 大数据量：打开大图模式 / 采样
  series: [{
    type: "line",
    large: true,                                    // 大数据量优化
    sampling: "lttb",                               // 降采样保趋势
    smooth: true,                                   // 平滑，等价曲线插值
    areaStyle: { opacity: 0.18 },                   // 面积填充
    data: bigArray
  }]
});
```

**什么时候用**：颜色按数值连续变化用 `visualMap`（别手搓颜色）；单序列上十万点用 `large` + `sampling`。`smooth` 对应 V17 的平滑曲线，`areaStyle` 对应 V21 的面积填充。

## 5. 三条库选型判据

### V38 用 Chart.js —— 快速出标准图

选它当：**几十行拿到一张能交付的标准图**，样式默认就够看，图表类型在它的内置/社区清单里，团队接受 canvas 呈现。

理由（来自其官方定位）：默认配置「开箱即用」、动画默认开、有 TS 类型、生态插件多、canvas 渲染在大数据量下性能好、树摇能减包。

**别选它当**：需要 CSS 参与图元样式/动画时（canvas 不行）；需要逐帧和页面动画编舞时。

### V39 用 ECharts —— 复杂交互 / 中文生态 / 大数据量

选它当：需要 **tooltip / legend / 缩放 / 联动 / 数据区域缩放 / 视觉映射** 这些开箱组件；国内业务项目、中文文档与示例更顺手；数据量大；需要 SVG 矢量导出或服务端渲染（切渲染器即可）。

**判据**：**「交互组件多 + 数据量大」→ ECharts**。要矢量就把渲染器换成 `svg`（V35）；要小包体就按需引入（V36）。

### V40 手绘 SVG —— 极致版式控制 / 逐帧动画 / 图表要给文字让位

选它当：
- **版式要极致控制**（轴、标注、图例、留白都要精确到像素，不能用库的默认布局）；
- **要逐帧渲染**、要和页面其它动画严格编舞（时间轴、滚动驱动）；
- **图表是「画面」的一部分，要给文字让位**——比如数据新闻/海报里，图表要被文字环绕、局部裁切、跟着排版变形，库的固定布局做不到。

做法：V04/V05 的映射 + V19–V24 的 path 生成 + 第 4 节的动画要求。

**代价**：坐标轴、刻度、tooltip、响应式全得自己写。所以**判据是「库的默认布局是否碍事」**——不碍事就用库，碍事才手绘。

## 6. 「画面即内容」场景下的特殊要求

当图表不是嵌在普通页面里、而是要**被动画**（线条生长、柱子长出来、数字滚动、随滚动形变）时，几何必须**拆成可独立驱动的元素**。这一节是 V40 的落地要求。

### V41 几何必须可寻址

反例与正例：

```js
// ✗ 把所有系列的线拼成一条大 path —— 无法单独驱动某一条
svg.innerHTML = `<path d="${allSeries.map(gen).join(" ")}"/>`;

// ✓ 一条序列一个元素，各自带 id / class，可单独查、单独动
series.forEach((s, i) =>
  svg.insertAdjacentHTML("beforeend",
    `<path class="serie" data-i="${i}" d="${gen(s)}"/>`)
);
```

同理：**一根柱子一个 `<rect>`**，**一个数字一个 `<text>`**。别为了「省节点」把可动单元合并掉。

**什么时候用**：凡是这个图要动，从生成 DOM 的那一刻就按可动单元拆。

### V42 线条生长：`stroke-dasharray` / `stroke-dashoffset`

原理：把虚线的一段设成**整条路径长**，再把偏移从「全长」动画到 0，视觉上就是线在生长。

```js
const el = document.querySelector(".serie");
const len = el.getTotalLength();     // 需要真实路径长度
el.style.strokeDasharray = len;
el.style.strokeDashoffset = len;     // 先藏起来
el.animate(
  [{ strokeDashoffset: len }, { strokeDashoffset: 0 }],
  { duration: 1200, easing: "ease-out", fill: "forwards" }
);
```

更省事的等价写法：给 path 加 `pathLength="1"`，然后 `dasharray="1"`、`dashoffset` 从 `1 → 0` 动，**不用调 `getTotalLength()`**：

```html
<path class="serie" pathLength="1" stroke-dasharray="1" stroke-dashoffset="1" d="…"/>
```

```js
el.animate([{ strokeDashoffset: 1 }, { strokeDashoffset: 0 }], 1200);
```

**什么时候用**：折线、曲线、轮廓线、任何「画出来」的效果。**注意**：`getTotalLength()` 要求元素已在文档里且路径有效；用 `pathLength="1"` 可以绕开这个依赖。

### V43 柱子生长：`scaleY` + 底部原点

柱子要从基线长出来，变形原点必须在**底部**：

```css
.bar {
  transform-box: fill-box;      /* 让 transform-origin 相对自身盒，而不是整个 SVG */
  transform-origin: bottom;     /* 从底部往上长 */
  transform: scaleY(0);
  animation: grow 800ms cubic-bezier(.22,1,.36,1) forwards;
}
@keyframes grow { to { transform: scaleY(1); } }
```

**关键点**：SVG 元素默认 `transform-origin` 是**整个画布的原点**，不加 `transform-box: fill-box` 会绕错点缩放（柱子会飞出去或从顶部缩）。`transform-origin: bottom` 保证从基线长。

**替代方案**（不想用 CSS transform 时）：用 rAF 每帧改 `y` 和 `height`，用同一个 `y` 比例尺算——和 V45 同源。

```js
function grow(rect, targetTop, baseY, t) {          // t: 0→1 进度
  const top = baseY + (targetTop - baseY) * t;      // 从基线插值到目标
  rect.setAttribute("y", top);
  rect.setAttribute("height", baseY - top);
}
```

**什么时候用**：柱状图、堆叠柱（每段都要有各自的底部原点）、条形图同理改 `scaleX` + `transform-origin: left`。

### V44 数字滚动：rAF + 缓动 + 等宽数字

```js
function countTo(el, from, to, duration = 1000) {
  const t0 = performance.now();
  const ease = (p) => 1 - Math.pow(1 - p, 3);        // easeOutCubic
  (function frame(now) {
    const p = Math.min(1, (now - t0) / duration);
    const v = from + (to - from) * ease(p);
    el.textContent = Math.round(v).toLocaleString();
    if (p < 1) requestAnimationFrame(frame);
  })(t0);
}
countTo(document.querySelector(".kpi"), 0, 12845, 1200);
```

防抖动：数字宽度会随位数变化导致文字跳动，给数字容器加**等宽数字**：

```css
.kpi { font-variant-numeric: tabular-nums; }
```

**什么时候用**：KPI 数字、图例数值、轴标签的入场。**统一用同一个缓动函数**，和线条/柱子的动效节奏才一致。

### V45 用同一套比例尺驱动动画（形变不脱轨）

动画过程中**不要手写插值坐标**，而是**动「输入」、让同一个映射函数重新算**。这样动画中途改尺寸/改数据也不会错位。

```js
// 让 x 轴「扫描窗口」从小长大：只动 domain，几何全由比例尺重算
function frame(t) {
  const progress = ease(t);
  const x = scaleLinear([0, data.length * progress], [M.l, M.l + pw]);
  const d = data.map((v, i) => `${i ? "L" : "M"}${x(i)} ${y(v)}`).join(" ");
  path.setAttribute("d", d);
}
```

同理：柱子生长可以「动基线」或「动柱高输入值」，数字滚动可以「动被映射的数值」。**原则：动画只改变换/输入，不改变换规则。**

**什么时候用**：需要几何随动画实时变形（线条扫描露出、柱子从数据 0 长到目标、环形进度）时。这也是 V41「拆成可动单元」之后的自然结论——每个单元都持有同一个比例尺，就能各自驱动又彼此对齐。

### V46 手绘图表必须配套的坑清单

来自选型资料反复强调的常见错误——**手绘时没有库帮你兜底，这些必须自己守**：

| 坑 | 规则 |
|---|---|
| 不排序 | 比较多个实体时**按值排序**，信息量立刻提升 |
| 截断 y 轴 | 柱状图**必须从 0 起**；折线可讨论，但要在图上明示 |
| 意大利面 | 一条图里线太多=不可读，减少系列或改小倍数图 |
| 饼图 | 人眼读角差，能换柱状/棒棒糖就别用饼；非用则直接标注每片 |
| 分箱大小 | 直方图**多试几种 bin**，结论可能完全不同 |
| 泡泡用直径 | 数值映射到**面积**不是直径（`r ∝ √value`） |
| 彩虹配色 | 连续量别用彩虹色阶，用单色深浅或感知均匀色阶 |
| 小倍数方向 | 横向排还是纵向排要看比较的是「趋势」还是「水平」 |

**什么时候用**：每张手绘图**出图前对着这张表过一遍**。
