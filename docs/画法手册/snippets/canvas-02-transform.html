Canvas 变换顺序对照

这个片段演示什么：同一组 translate / rotate / scale，只调换调用顺序，画出来的位置就完全不同；以及「绕自身中心旋转」的正确三步写法。

① 平移 × 缩放：平移量会不会被缩放

两边都画同一个 fillRect(10, 0, 20, 20)。红点是调用完变换后「原点 (0,0)」落在哪。

② 平移 × 旋转：旋转枢轴先定还是后定

同一条横杠，同样转 45°。左图先平移把原点搬到目标点再转；右图先转，之后写的平移是在已旋转的坐标系里发生，原点被甩到别处。

③ 绕自身中心旋转：正确三步

唯一正确的写法是 translate(中心) → rotate → 用「以中心为原点」的坐标画（-w/2, -h/2）。右图漏掉了 translate，于是绕画布原点 (0,0) 转。

核心代码 
// 通用：按 dpr 建高清画布，返回已缩放的 ctx
function setup(id, w, h) {
  const c = document.getElementById(id);
  const dpr = window.devicePixelRatio || 1;
  c.width = w * dpr; c.height = h * dpr;          // 位图分辨率
  c.style.width = w + "px"; c.style.height = h + "px";  // 显示尺寸
  const ctx = c.getContext("2d");
  ctx.scale(dpr, dpr);                            // 之后按 CSS 像素坐标画
  return ctx;
}

// ① 顺序不同 → 平移量是否被缩放不同
ctx.translate(100, 20); ctx.scale(2, 2); ctx.fillRect(10, 0, 20, 20); // x = 120
ctx.scale(2, 2); ctx.translate(100, 20); ctx.fillRect(10, 0, 20, 20); // x = 220

// ② 顺序不同 → 旋转枢轴不同
ctx.translate(90, 85); ctx.rotate(Math.PI / 4); ctx.fillRect(-42, -9, 84, 18); // 绕 (90,85)
ctx.rotate(Math.PI / 4); ctx.translate(90, 50); ctx.fillRect(-42, -9, 84, 18); // 枢轴被甩走

// ③ 绕自身中心旋转的正确三步（★ 记这个）
function drawRotatedRect(ctx, cx, cy, w, h, angle) {
  ctx.save();
  ctx.translate(cx, cy);        // 1) 原点搬到图形中心
  ctx.rotate(angle);            // 2) 绕新原点（= 图形中心）旋转
  ctx.fillRect(-w / 2, -h / 2, w, h);  // 3) 以中心为原点画
  ctx.restore();
}

// 调用方零副作用：任何会改状态的绘制函数都用 save/restore 包裹
// 别这样：ctx.rotate(a); ctx.fillRect(55, 73, 90, 24);  ← 绕 (0,0) 转，图形飞走
