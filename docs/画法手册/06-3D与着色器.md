# Three.js / WebGL 着色器手册（3D 与片段着色器）

> 用途：**给定一个 3D 场景或一个片段着色器效果，代码怎么写出来**。
> 每条技法给可直接复制运行的最小代码，Three.js 部分给「粘进 `.html` 就能看」的单文件示例。
> 每条都标注 **什么时候用 / 什么时候别用**。
> 代码围栏统一 `js` / `glsl` / `html`。

技法编号：`T01`–`T42`，末尾有索引表。

---

## 0. 心法：先决定你到底要不要 3D

在写第一行 `new THREE.Scene()` 之前，先回答三个问题。

**问题一：需要「相机」吗？**
如果画面里物体的远近关系不随视角变化（比如一个卡片、一条分割线、一个背景光晕），你需要的是 2D —— SVG / CSS / Canvas / 纯片段着色器。上 Three.js 只会让你多维护一套坐标系。

**问题二：需要「光照」吗？**
如果需要真实感（金属、玻璃、次表面），需要 `MeshStandardMaterial` + 环境贴图（HDRI）。如果只是平面色块和渐变，光照是纯浪费 —— 用 `MeshBasicMaterial` 或直接片段着色器。

**问题三：需要「很多个」吗？**
1 个物体 → 别上 3D 引擎，可能一段 SVG 就够了。
几十个物体、需要相机交互 → Three.js 值得。
一万个同款物体 → InstancedMesh 或干脆用 GPU 粒子着色器。

**问题的分界线大致是**：

| 需求 | 用什么 |
| --- | --- |
| 静态几何形状（图标、插画、装饰） | SVG |
| 有大量动态实例的 2D 图形（散点、粒子） | Canvas 2D 或片段着色器 |
| 纯色/渐变/噪点/光效滤镜 | 片段着色器（距离场） |
| 一个可以拖动旋转的实体模型 | Three.js |
| 需要阴影、反射、PBR 材质 | Three.js + HDRI |
| 必须 60fps 且物体数 > 10k | 自定义 InstancedMesh / GPU 计算着色器 |

后面的章节按这个顺序组织：**骨架 → 几何 → 变换 → 材质光照 → 相机 → 时间 → 着色器 → 落地 → 性能**。

# 第一部分：Three.js 最小骨架

### T01 scene / camera / renderer 三件套

Three.js 的一切都建立在这三个对象上。没有它们什么都渲染不出来。

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <style>
    html, body { margin: 0; height: 100%; }
    /* canvas 必须交给 CSS 定尺寸，见 T04 */
    canvas { width: 100%; height: 100%; display: block; }
  </style>
  <script type="importmap">
  {
    "imports": {
      "three": "https://cdn.jsdelivr.net/npm/three@0.180.0/build/three.module.js",
      "three/addons/": "https://cdn.jsdelivr.net/npm/three@0.180.0/examples/jsm/"
    }
  }
  </script>
</head>
<body>
  <canvas id="c"></canvas>

  <script type="module">
    import * as THREE from 'three';

    // 1. 场景：所有物体的容器，也是场景图的根
    const scene = new THREE.Scene();

    // 2. 相机：定义「从哪里、朝哪里、看多宽」
    const camera = new THREE.PerspectiveCamera(
      45,                                              // fov（度）
      window.innerWidth / window.innerHeight,          // aspect
      0.1,                                             // near
      100                                              // far
    );
    camera.position.set(0, 2, 6);
    camera.lookAt(0, 0, 0);

    // 3. 渲染器：把 scene + camera 画成 2D 像素
    const renderer = new THREE.WebGLRenderer({ antialias: true });
    renderer.setSize(window.innerWidth, window.innerHeight);
    document.body.appendChild(renderer.domElement);

    // 4. 至少放一个东西进去
    const geometry = new THREE.BoxGeometry(1, 1, 1);
    const material = new THREE.MeshBasicMaterial({ color: 0x00ff00 });
    scene.add(new THREE.Mesh(geometry, material));

    // 5. 渲染一次
    renderer.render(scene, camera);
  </script>
</body>
</html>
```

三个对象的分工必须记牢：

- `Scene` 只管「放」，不管「画」。
- `Camera` 只管「取景」，不是光源。
- `Renderer` 只管「画」，不持有场景状态。
- `Mesh = Geometry + Material`，`scene.add()` 默认把物体放到 `(0,0,0)`，所以相机必须挪开，否则相机在物体内部。

**什么时候用**：任何 3D 内容的绝对起点。哪怕只用 Three.js 画一个全屏着色器（T34），也需要这三个对象（或者用 `OrthographicCamera` 替代透视相机，见 T24）。

**什么时候别用**：静态图片、纯 CSS 动画、纯 2D 矢量图。以及「只有一个渐变色块」——那用一段 CSS `linear-gradient` 就行。

### T02 透视相机的 fov / near / far

`PerspectiveCamera(fov, aspect, near, far)` 四个参数的物理含义：

- `fov`：**垂直**视场角，单位是**度**。越大视野越广（广角、畸变强），越小越像长焦（压缩、扁平）。40–50 最接近人眼观感，75 是 Three.js 文档示例里的「游戏视角」。
- `aspect`：宽高比，**必须**等于画布显示宽 / 显示高，否则物体被拉伸（见 T04）。
- `near`：近裁剪面距离。比它近的物体不渲染。
- `far`：远裁剪面距离。比它远的物体不渲染。

`fov` 决定的是「多高」，宽度 = 高度 × `aspect`。所以改 `fov` 和改 `near/far` 之后**必须**调 `updateProjectionMatrix()`。

```js
camera.fov = 30;
camera.near = 0.1;
camera.far = 100;
camera.updateProjectionMatrix();   // 改投影参数后必调
```

**near/far 不能随便设成 0.00001 和 1e12**。GPU 的深度精度是有限的，且在 `near` 附近精细、在 `far` 附近粗糙。`near` 设得越小的，远处精度越差，会出现 **z-fighting**（两个共面物体的前后关系闪烁、出现条纹）。

```js
// 反例：near 太小 → z-fighting
const camera = new THREE.PerspectiveCamera(45, aspect, 0.00001, 100);

// 正例：near 尽量大、far 尽量小，刚好包住你的场景
const camera = new THREE.PerspectiveCamera(45, aspect, 1, 60);
```

如果确实需要极大动态范围，可以开启对数深度缓冲，但代价是性能下降且部分移动 GPU 不支持：

```js
const renderer = new THREE.WebGLRenderer({ antialias: true, logarithmicDepthBuffer: true });
```

**什么时候用**：默认就用 `PerspectiveCamera`。需要「近大远小」的纵深感时。

**什么时候别用**：
- 需要正交投影（2D 排版、工程三视图、像素级对齐）→ 用 `OrthographicCamera`（T24）。
- 需要极近距离看到睫毛、同时又要看到 50 公里外的山 → 这不是靠调 near/far 能解决的，要拆成多个场景/多个相机分层渲染。

### T03 渲染循环：`setAnimationLoop`

只渲染一次是静态图。要动起来，用渲染器自带的循环方法。

```js
renderer.setAnimationLoop((time) => {
  // time 是 DOMHighResTimeStamp，单位毫秒，由浏览器给，不是你自己算的
  cube.rotation.x = time / 2000;
  cube.rotation.y = time / 1000;
  renderer.render(scene, camera);
});
```

`setAnimationLoop` 内部就是 `requestAnimationFrame`，但它有两个关键好处：

1. **切到别的标签页时自动暂停**，不浪费 CPU/GPU 和电池。`setInterval` 做不到。
2. 接 WebXR 时是官方唯一支持的循环入口（用 `rAF` 某些头显会不同步）。

退出手动循环用 `renderer.setAnimationLoop(null)`。

**什么时候用**：任何有动画的场景。这是默认选择。

**什么时候别用**：内容完全静态、或者只在用户操作时变化 → 用「按需渲染」（T32），省电。

### T04 响应式 resize（最容易做错的一节）

这里有两个「尺寸」，混在一起就错：

| 名称 | 含义 | 谁来决定 |
| --- | --- | --- |
| `clientWidth/clientHeight` | CSS 显示尺寸（CSS 像素） | **CSS** |
| `canvas.width/canvas.height` | drawingBuffer 尺寸（真实像素） | **JS，`renderer.setSize`** |

只改 CSS，会出现两种 bug：

- **物体被拉伸**：因为 `camera.aspect` 还是旧的。
- **画面糊/马赛克**：因为 drawingBuffer 还是 300×150 的默认值，被浏览器放大显示。

正确做法是「让 CSS 定尺寸，让 JS 跟上去」：

```js
function resizeRendererToDisplaySize(renderer) {
  const canvas = renderer.domElement;
  const pixelRatio = window.devicePixelRatio;
  let width  = Math.floor(canvas.clientWidth  * pixelRatio);
  let height = Math.floor(canvas.clientHeight * pixelRatio);

  // 可选：封顶内部像素数，防止 4K + devicePixelRatio=3 把 GPU 打死
  const maxPixels = 3840 * 2160;
  const px = width * height;
  if (px > maxPixels) {
    const s = Math.sqrt(maxPixels / px);
    width  = Math.floor(width * s);
    height = Math.floor(height * s);
  }

  const needResize = canvas.width !== width || canvas.height !== height;
  if (needResize) {
    renderer.setSize(width, height, false);   // 第三个参数 false 是关键
  }
  return needResize;
}

renderer.setAnimationLoop(() => {
  if (resizeRendererToDisplaySize(renderer)) {
    const canvas = renderer.domElement;
    camera.aspect = canvas.clientWidth / canvas.clientHeight;
    camera.updateProjectionMatrix();
  }
  renderer.render(scene, camera);
});
```

三个必须记住的细节：

- `renderer.setSize(w, h, false)` 的 `false` 意思是「**不要**改 canvas 的 CSS 尺寸」。Three.js 默认会帮你设 CSS，但那会让 CSS 失去控制权。我们只让它改 drawingBuffer。
- **只在尺寸真的变了时才 resize**。反复调用 `setSize` 同一尺寸会触发 canvas 缓冲区重建，掉帧。
- `camera.aspect` 用 `clientWidth/clientHeight`（CSS 尺寸），不是 `canvas.width/height`（真实像素）——两者比值相同，但前者语义正确。

**不要用 `renderer.setPixelRatio(window.devicePixelRatio)`**。它会让 `setSize` 内部偷偷乘一个倍数，导致你「请求的尺寸」和「实际 drawingBuffer 尺寸」不一致。只要你要读 `gl_FragCoord`、做后处理、截图、GPU picking，这就会变成无法调试的坑。手动乘 `pixelRatio`（如上面代码）永远是对的。

**什么时候用**：所有需要适配窗口的场景。移动端尤其重要。

**什么时候别用**：固定尺寸离屏渲染（`WebGLRenderTarget`）、`OffscreenCanvas` 场景 —— 那些尺寸是你说一不二的，不需要监听窗口。

# 第二部分：几何体（primitives）

### T05 内置几何体的参数含义

所有内置几何体都是「运行时用参数生成顶点」，不是从文件加载的模型。

```js
const THREE_GEOS = {
  // 宽度, 高度, 深度, 宽分段, 高分段, 深分段
  box:      new THREE.BoxGeometry(2, 2, 2, 1, 1, 1),
  // 半径, 经线分段, 纬线分段, phiStart, phiLength, thetaStart, thetaLength
  sphere:   new THREE.SphereGeometry(1, 32, 16),
  // 顶半径, 底半径, 高, 径向分段, 高分段, 是否开口
  cylinder: new THREE.CylinderGeometry(1, 1, 2, 32, 1, false),
  // 半径, 高, 径向分段, 高分段, 是否开口
  cone:     new THREE.ConeGeometry(1, 2, 32, 1, false),
  // 半径, 管半径, 径向分段, 管向分段, 整圆弧度
  torus:    new THREE.TorusGeometry(1, 0.4, 16, 100),
  // 宽, 高, 宽分段, 高分段
  plane:    new THREE.PlaneGeometry(2, 2, 1, 1),
  // 内半径, 外半径, 圆周分段
  ring:     new THREE.RingGeometry(0.5, 1, 32),
  // 圆半径, 圆周分段
  circle:   new THREE.CircleGeometry(1, 32),
  // 半径, 细节层级（越高越接近球）
  icosa:    new THREE.IcosahedronGeometry(1, 0),
  // 半径, 管半径, 径向分段, 管向分段, 打结参数 p, q
  torusKnot: new THREE.TorusKnotGeometry(1, 0.4, 128, 16, 2, 3),
};
```

高频参数的直觉：

- **`radiusSegments` / `widthSegments`**：横向切多少刀。圆润度主要看它。
- **`heightSegments`**：纵向切多少刀。球体低于 6 会露出明显的棱。
- **`phiLength` / `thetaLength`**：小于 `Math.PI*2` / `Math.PI` 时生成**局部**球面，是画碗、半球、扇形的最快方式。
- **`openEnded`**：`true` 时不生成上下盖，省一半三角形。管道、纸筒用它。
- **`PlaneGeometry` 默认躺在 XY 平面上**。做地面必须转：
  ```js
  mesh.rotation.x = -Math.PI / 2;   // 转到 XZ 平面当地面
  ```

**什么时候用**：原型、调试、占位、以及程序化生成的场景（数据可视化里的柱条/球点、图标形状）。

**什么时候别用**：需要美术质感的角色、道具、建筑。这些应该在 Blender 里建模，导出 glTF 加载 —— 内置几何体的目的不是做美术资产。

### T06 分段数：性能与外观的取舍

分段数是**乘法增长**的：

```js
// 分段数 → 三角形数的换算
// 球体：(widthSegments × heightSegments) 个四边形 × 2 = 三角形数
new THREE.SphereGeometry(1, 5, 3);    // 15 个四边形  = 30 个三角形
new THREE.SphereGeometry(1, 24, 10);  // 240 个四边形 = 480 个三角形
new THREE.SphereGeometry(1, 50, 50);  // 2500 个四边形 = 5000 个三角形
```

关键在于：**「分段少」的损失是可以被平滑着色掩盖的**。同一个 24×10 的球：

- 打开线框 + `flatShading: true` → 一眼看出是低模。
- 关闭线框 + 平滑着色（默认）→ 和 50×50 的球肉眼几乎分不出。

所以策略是：

```js
// 少分段 + 平滑着色，是性价比最高的组合
const geometry = new THREE.SphereGeometry(1, 24, 10);
const material = new THREE.MeshStandardMaterial({ roughness: 0.6 });
// 不要设 flatShading: true（默认就是平滑）
```

数量级估算：

```js
// 1000 个球 × 每个 10000 三角形 = 10,000,000 三角形
// 60fps → 每秒 6 亿三角形。这是不现实的。
// 换成 24×10（480 三角形）→ 每秒 2880 万，才安全。
```

**什么时候用**：低多边形风格（刻意保留棱面）、远景物体、大量实例、移动端。

**什么时候别用**：单个主角模型（一个地球仪用 10000 三角形完全没问题）、需要雕塑感轮廓的场合、需要用 `displacementMap` 扰动顶点的场合（顶太少位移就出不来）。

### T07 BufferGeometry 与 Geometry：只有一个还活着

| 名称 | 状态 | 原理 | 速度 |
| --- | --- | --- | --- |
| `Geometry` | **已移除**（r125 起） | 基于 JS 对象数组存每个顶点 | 慢、内存大 |
| `BufferGeometry` | 唯一存在 | 基于 TypedArray 的并行数组 | 快、可直接上传 GPU |

所以现在不存在「用哪个」的问题 —— **只有 `BufferGeometry`**。所有内置几何体（`BoxGeometry`、`SphereGeometry`…）都是 `BufferGeometry` 的子类。

`BufferGeometry` 的本质是「一组同名 `BufferAttribute` 的集合」：

- `position`：每个顶点的 xyz，3 个分量
- `normal`：每个顶点的法线方向，3 个分量
- `uv`：贴图坐标，2 个分量
- `color`：顶点色，3 个分量（可选）

它们是**并行数组**：第 N 个顶点的 pos/normal/uv 分别在三个数组的第 N 组。名字是硬约定 —— 除非你写自定义着色器，否则必须叫 `position` / `normal` / `uv` / `color`。

**什么时候用**：只要涉及几何体，你就在用它。需要手搓或修改顶点时直接操作它。

**什么时候别用**：没有任何场景该用 `Geometry`，它已经不存在了。见到基于 `Geometry` 的老教程要警惕（API 也变了，比如 `geometry.vertices` → `geometry.attributes.position`）。

### T08 自定义几何：手搓顶点数组

一个立方体的「角」看起来是 1 个顶点，实际上是 **3 个顶点** —— 因为三个面在那个角上的法线和 UV 都不同。**只要一个顶点的任何一个分量不同，它就必须是独立顶点**。所以立方体需要 36 个顶点（6 面 × 2 三角形 × 3 顶点）。

```js
import * as THREE from 'three';

// 先写「人话」版本，每个顶点带齐所有数据
const vertices = [
  // front
  { pos: [-1, -1,  1], norm: [ 0,  0,  1], uv: [0, 0] },
  { pos: [ 1, -1,  1], norm: [ 0,  0,  1], uv: [1, 0] },
  { pos: [-1,  1,  1], norm: [ 0,  0,  1], uv: [0, 1] },

  { pos: [-1,  1,  1], norm: [ 0,  0,  1], uv: [0, 1] },
  { pos: [ 1, -1,  1], norm: [ 0,  0,  1], uv: [1, 0] },
  { pos: [ 1,  1,  1], norm: [ 0,  0,  1], uv: [1, 1] },
  // ... 其余 4 个面同理，每个面写 6 个顶点
];

// 摊平成 3 个并行数组
const positions = [];
const normals = [];
const uvs = [];
for (const v of vertices) {
  positions.push(...v.pos);
  normals.push(...v.norm);
  uvs.push(...v.uv);
}

const geometry = new THREE.BufferGeometry();
geometry.setAttribute('position', new THREE.BufferAttribute(new Float32Array(positions), 3));
geometry.setAttribute('normal',   new THREE.BufferAttribute(new Float32Array(normals),   3));
geometry.setAttribute('uv',       new THREE.BufferAttribute(new Float32Array(uvs),       2));
```

**用索引省内存**。同样的立方体，去重后只有 24 个独立顶点，再用 36 个索引指过去：

```js
// 24 个去重顶点（每个面的 4 个角各存一份，因为法线不同）
geometry.setIndex([
   0,  1,  2,   2,  1,  3,   // front
   4,  5,  6,   6,  5,  7,   // right
   8,  9, 10,  10,  9, 11,   // back
  12, 13, 14,  14, 13, 15,   // left
  16, 17, 18,  18, 17, 19,   // top
  20, 21, 22,  22, 21, 23,   // bottom
]);
```

**直接上 TypedArray**（避免中间 JS 数组，也为了后续能动态改）：

```js
const numVertices = vertices.length;
const positions = new Float32Array(numVertices * 3);
const normals   = new Float32Array(numVertices * 3);
const uvs       = new Float32Array(numVertices * 2);
let pNdx = 0, nNdx = 0, uNdx = 0;
for (const v of vertices) {
  positions.set(v.pos,  pNdx); pNdx += 3;
  normals.set(v.norm,   nNdx); nNdx += 3;
  uvs.set(v.uv,         uNdx); uNdx += 2;
}
```

**动态修改顶点**（每帧改位置）：

```js
const positionAttribute = new THREE.BufferAttribute(positions, 3);
positionAttribute.setUsage(THREE.DynamicDrawUsage);   // 告诉 GPU 这块数据会常变
geometry.setAttribute('position', positionAttribute);

// 渲染循环里：
for (let i = 0; i < positions.length; i += 3) {
  // ... 修改 positions[i], positions[i+1], positions[i+2]
}
positionAttribute.needsUpdate = true;   // 不设这一行，改动不会生效
```

一个坑：`geometry.computeVertexNormals()` 能帮你算法线，但它在**接缝处**会出错。因为接缝上的顶点为了不同 UV 被拆成了两份，算法线时它们各自独立，于是球体/圆柱上会出现一条明显的硬边。**需要无缝就自己提供法线。**

**什么时候用**：程序化几何（地形、粒子云、数据驱动的形状、自定义文字排布）、需要每帧改顶点的动画、`InstancedMesh` 也不够用的极端定制。

**什么时候别用**：能用内置几何体组合出来的形状。手搓顶点极易出错（法线方向、三角形缠绕顺序导致背面消失），能用 `BoxGeometry` 拼装就别写顶点数组。

# 第三部分：变换与场景图

### T09 position / rotation / scale

每个 `Object3D`（含 `Mesh`、`Camera`、`Light`）都有这三个属性。它们是**本地坐标**，相对于父节点。

```js
mesh.position.set(2, 1, 0);           // 平移（单位 = 世界单位）
mesh.rotation.set(0, Math.PI / 4, 0); // 欧拉角，弧度制
mesh.scale.set(2, 2, 2);              // 缩放
```

几个必须知道的点：

- `position.x = 2` 和 `position.set(2, 1, 0)` 等价，但后面那个不会意外把 y/z 清零之外的属性重置。
- 角度单位是**弧度**。度转弧度用 `THREE.MathUtils.degToRad(45)`。
- Three.js 的旋转在内部**始终**用四元数保存，`rotation`（欧拉角）只是一个便捷视图。欧拉角存在万向节死锁，动画里连续绕多轴旋转时可能出问题 —— 那种情况用四元数：
  ```js
  mesh.quaternion.setFromEuler(new THREE.Euler(0, Math.PI/4, 0));
  // 或沿轴转
  mesh.quaternion.setFromAxisAngle(new THREE.Vector3(0, 1, 0), Math.PI/4);
  ```
- **缩放会传给子节点**。如果父节点 `scale = 5`，子节点既被放大 5 倍，它的 `position` 也被乘 5。这是场景图最容易踩的坑（见 T11）。

**什么时候用**：所有物体的摆放。这是 Three.js 里改动频率最高的三行。

**什么时候别用**：不要用 `scale` 去改变几何体的「形状比例」来做变形动画 —— 非均匀缩放会让法线计算失效，光照会错。形状变形要么改几何体顶点，要么在着色器里做。

### T10 矩阵与 `matrixAutoUpdate`

`position / quaternion / scale` 最终会被合成一个 `Matrix4`。这就是「矩阵」在 Three.js 里的角色。

两种更新方式，**不要混用**：

```js
// 方式 A：改便捷属性，让 Three.js 自动重算矩阵（默认行为）
mesh.position.copy(startPos);
mesh.quaternion.copy(q);
// matrixAutoUpdate 默认是 true，不用管

// 方式 B：直接改矩阵 —— 必须关掉 autoUpdate，且绝不能再调 updateMatrix()
mesh.matrix.makeRotationFromQuaternion(q);
mesh.matrix.setPosition(startPos);
mesh.matrixAutoUpdate = false;
```

静态物体（不动的地面、墙、装饰）关掉 `matrixAutoUpdate` 能省一笔每帧的矩阵重算：

```js
staticMesh.matrixAutoUpdate = false;
staticMesh.updateMatrix();   // 关掉的瞬间手动算一次
```

关键概念：

- `object.matrix` 是**相对于父节点**的矩阵。
- `object.matrixWorld` 是**世界坐标**矩阵。父或子任意一方变化后，调 `object.updateMatrixWorld()` 刷新（渲染时会自动调，手动改时要自己调）。
- 修改 `position/rotation` 后，同一帧内如果要用世界坐标，**必须先** `updateMatrixWorld()`：
  ```js
  mesh.position.set(0, 5, 0);
  mesh.updateMatrixWorld();          // 不调这一行，下面拿到的是旧位置
  const worldPos = new THREE.Vector3();
  mesh.getWorldPosition(worldPos);
  ```
- `object.applyMatrix4(matrix)` 可以一次性套用变换，但它依赖 `decompose()`，**遇到非均匀缩放的父节点可能失败**，谨慎使用。

**什么时候用**：性能优化（大量静态物件）、手动排布变换、以及需要拿世界坐标时。

**什么时候别用**：99% 的代码用方式 A 就够了。别为了「显得底层」去手动写矩阵 —— 调试成本远大于那点性能收益。

### T11 场景图层级：Group / Object3D 做父子叠加

场景图是一棵树，**子节点在父节点的本地坐标系里**。这让你不用做复杂的数学，就能做出「卫星绕行星、行星绕恒星」这种运动。

```js
import * as THREE from 'three';

// 太阳：一个空节点 + 一个球
const solarSystem = new THREE.Object3D();   // 空节点，只代表一个坐标系
scene.add(solarSystem);

const sphereGeo = new THREE.SphereGeometry(1, 6, 6);

const sunMesh = new THREE.Mesh(sphereGeo, new THREE.MeshPhongMaterial({ emissive: 0xffff00 }));
sunMesh.scale.set(5, 5, 5);
solarSystem.add(sunMesh);

// 地球：挂在太阳系节点的「轨道子节点」上
const earthOrbit = new THREE.Object3D();
earthOrbit.position.x = 10;                 // 距离太阳 10 个单位
solarSystem.add(earthOrbit);

const earthMesh = new THREE.Mesh(sphereGeo, new THREE.MeshPhongMaterial({ color: 0x2233ff }));
earthOrbit.add(earthMesh);                  // 注意：不要再设 earthMesh.position.x

// 月亮：挂在「地球轨道」节点下
const moonOrbit = new THREE.Object3D();
moonOrbit.position.x = 2;
earthOrbit.add(moonOrbit);

const moonMesh = new THREE.Mesh(sphereGeo, new THREE.MeshPhongMaterial({ color: 0x888888 }));
moonMesh.scale.set(0.5, 0.5, 0.5);
moonOrbit.add(moonMesh);

// 旋转「轨道节点」，子节点自动跟着画圈
function animate(time) {
  time *= 0.001;
  earthOrbit.rotation.y = time * 0.5;
  moonOrbit.rotation.y = time * 2;
  renderer.render(scene, camera);
}
```

上面这段的关键洞察：月亮相对于太阳走的是复杂的花瓣形（外摆线）轨迹，但代码里**没有任何三角函数**。它只知道自己要绕「地球轨道节点」转圈。

**用 `Group` 还是 `Object3D`？** 两者功能完全一样，`Group` 只是 `Object3D` 的语义化子类（名字上告诉你「这是一组东西」），且带 `name` 便于识别。团队协作里推荐用 `Group`：

```js
const wheels = new THREE.Group();
wheels.name = 'wheels';
car.add(wheels);
```

**什么时候用**：任何「一堆物体要一起移动」的场合（车轮随车身、UI 面板整体位移、角色骨骼层级）、任何「相对某点做圆周运动」的场合。

**什么时候别用**：层级别做太深。实测过 10 层以上的嵌套会带来可感知的矩阵计算开销，而且更难调试。**用 `AxesHelper` / `GridHelper` 可视化节点**是排查层级问题的利器：

```js
// 给每个节点画上坐标轴和网格，一眼看出本地坐标系在哪
const axes = new THREE.AxesHelper();
axes.material.depthTest = false;   // 让坐标轴穿透球体显示
axes.renderOrder = 1;              // 保证画在球体之后，不被盖住
node.add(axes);
```

`renderOrder` 是渲染顺序的手动控制（默认 0，大的后画）。当两个 helper 重叠时，把想显示在上面的那个设更大的值。

### T12 `lookAt` 与 `up`

`lookAt` 让物体的 **-Z 轴**指向目标点。它同时被相机和普通物体使用。

```js
// 相机看向原点
camera.position.set(0, 10, 20);
camera.lookAt(0, 0, 0);

// 物体朝向另一个物体（必须传世界坐标！）
const targetPos = new THREE.Vector3();
otherMesh.getWorldPosition(targetPos);
turretPivot.lookAt(targetPos);
```

`up` 定义「哪个方向是头顶」。默认 `(0, 1, 0)`（Y 轴向上）。当你需要**俯视正下方**时，相机看向方向和 `up` 平行了，`lookAt` 就会失效（矩阵退化）。这时必须改 `up`：

```js
// 相机在正上方俯视 —— 默认的 up=(0,1,0) 会和视线方向共线
camera.position.set(0, 50, 0);
camera.up.set(0, 0, 1);      // 改用 Z 轴作为「上」
camera.lookAt(0, 0, 0);
```

**什么时候用**：相机对准目标、炮塔/角色朝向、`billboard`（广告牌，永远面向相机）效果。

**什么时候别用**：需要平滑转向时不要直接 `lookAt`（会瞬间跳转）。要么用 `quaternion.slerp()` 插值，要么用阻尼系数逐步逼近。

# 第四部分：材质与光照

### T13 材质阶梯：从最省到最贵

按性能和真实度排序，只有一条阶梯：

```
MeshBasicMaterial  →  MeshLambertMaterial  →  MeshPhongMaterial  →  MeshStandardMaterial  →  MeshPhysicalMaterial
    最快、无光照          顶点光照、无高光        逐像素光照、带高光        PBR、金属度/粗糙度         PBR + 清漆/透射
```

| 材质 | 受光照影响 | 高光 | 关键参数 | 适用 |
| --- | --- | --- | --- | --- |
| `MeshBasicMaterial` | 否 | 无 | `color`、`map` | 无光照需求、UI 平面、辅助线、常量色 |
| `MeshLambertMaterial` | 是（逐顶点） | 无 | `color`、`emissive` | 低配兜底、大平面、马赛克风格 |
| `MeshPhongMaterial` | 是（逐像素） | 有 | `shininess`（默认 30） | 需要一点高光的日常场景 |
| `MeshStandardMaterial` | 是（PBR） | 有 | `roughness`、`metalness` | **默认首选**，真实感 |
| `MeshPhysicalMaterial` | 是（PBR+） | 有 | `clearcoat`、`clearCoatRoughness`、`transmission` | 车漆、玻璃、水面 |
| `MeshToonMaterial` | 是 | 无 | `gradientMap`（X×1 的小贴图） | 卡通两段式着色 |
| `MeshNormalMaterial` | 否 | 无 | — | 调试法线（x=红 y=绿 z=蓝） |
| `MeshDepthMaterial` | 否 | 无 | — | 调试深度、自定义后处理 |
| `ShadowMaterial` | 否 | 无 | `opacity` | 只画阴影不画物体的「隐形地板」 |

两个等价性技巧，很有用：

```js
// Basic 等价于「黑色 Lambert/Phong + 纯 emissive」
// 反过来说：想让 Phong 也发光而不受光照影响，就用 emissive
const glow = new THREE.MeshPhongMaterial({ color: 0x000000, emissive: 0xff00ff, shininess: 0 });
```

物性两参数的直觉：

- `roughness`（粗糙度，0–1）：**`shininess` 的反面**。0 = 台球（锐利反射），1 = 棒球（无反射）。
- `metalness`（金属度，0–1）：0 = 非金属，1 = 金属。**中间值只对「脏金属」有物理意义**，做非金属物体时保持 0。
- `clearcoat`（清漆层，0–1）：在 PBR 基础上再叠一层清漆高光 —— 汽车漆、上了釉的陶瓷、湿润表面。

**什么时候用**：
- 默认 → `MeshStandardMaterial`（`roughness: 0.5`、`metalness: 0`）。
- 移动端 / 大量物体的兜底 → `MeshLambertMaterial`。
- 不需要任何光照的平面 → `MeshBasicMaterial`。
- 真实玻璃/水 → `MeshPhysicalMaterial` + `transmission`。

**什么时候别用**：
- **不要无脑全用 `MeshPhysicalMaterial`**。它的额外通道（清漆、透射）在移动 GPU 上非常贵。
- 不要用 `MeshPhongMaterial` 去追求「真实感」——想真实就必须上 PBR。
- `MeshBasicMaterial` 看起来「和 Lambert 一样」时就该用 Basic —— 没必要为看不出的效果付光照计算成本。

### T14 材质的通用属性与 `needsUpdate` 陷阱

**颜色有 5 种设值方式**，别记住一种就以为只有一种：

```js
material.color.set(0x00ffff);         // 十六进制
material.color.set('#F32');           // 任意 CSS 颜色串
material.color.set('rgb(255,127,64)');
material.color.set('hsl(180,50%,25%)');
material.color.setHSL(h, s, l);       // 全部 0..1
material.color.setRGB(r, g, b);       // 全部 0..1

// 创建时也能直接用字符串
new THREE.MeshBasicMaterial({ color: 'rebeccapurple' });
```

`setHSL(hue, saturation, luminance)` 在批量造色时特别顺手：

```js
// hue 0..1 绕色轮：0=红 0.33=绿 0.66=蓝
// luminance：0 → 黑，0.5 → 最饱和的 hue，1 → 白
material.color.setHSL(Math.random(), 1, 0.5);
```

**`needsUpdate` 的坑**：Three.js 有些材质设置只在**第一次使用材质时**应用一次，因为改动它们需要重新编译着色器。改了之后必须手动通知：

```js
material.flatShading = true;
material.needsUpdate = true;    // 不加这行，改动会被忽略

// 同理：从「无贴图」切到「有贴图」，或反着切
material.map = someTexture;
material.needsUpdate = true;
```

实际会踩到的只有两类：`flatShading` 的切换、贴图的增删。绝大多数项目一辈子碰不到。

另外两个高频通用属性：

```js
material.flatShading = true;          // 平面着色：露出每个三角形的面片感。默认 false
material.side = THREE.DoubleSide;     // 双面渲染。默认 FrontSide
```

`side` 的三种取值：`FrontSide`（默认，只画正面）、`BackSide`（只画背面，做「盒子里」用）、`DoubleSide`（两面都画）。

**什么时候用**：
- `flatShading: true` → 低多边形风格、刻意强调结构。
- `DoubleSide` → 单层平面（`PlaneGeometry`、`ShapeGeometry`、树叶、纸片）。这些没有「内部」，不设双面会从背面看时凭空消失。

**什么时候别用**：
- `DoubleSide` **比单面慢**（要关掉背面剔除、光照要处理反面）。实心物体（球、盒）不需要它。只为真正需要的几个材质开。
- `flatShading` 让低模的棱角更明显，如果你要的是「顺滑」，开了反而毁掉 T06 里省分段的收益。

### T15 光照类型与参数

先明确一件事：`AmbientLight` 和 `HemisphereLight` **没有方向**，只是把材质颜色乘一下。

```js
// 环境光：color = materialColor * light.color * light.intensity
const ambient = new THREE.AmbientLight(0xffffff, 1);
scene.add(ambient);
```

它「100% 均匀」，所以单独用场景会非常平（没有体积感）。它的真实用途是**把暗部抬起来，别让阴影死黑**。

```js
// 半球光：天空色 × 朝上的面，地面色 × 朝下的面
const hemi = new THREE.HemisphereLight(0xb1e1ff /* 天蓝 */, 0xb97a20 /* 土橙 */, 1);
scene.add(hemi);
```

半球光比环境光有信息量（有上下之分），常用来替代环境光、给场景「环境色」。

```js
// 方向光：模拟太阳。平行光线，没有「灯的位置」概念
const dirLight = new THREE.DirectionalLight(0xffffff, 1);
dirLight.position.set(0, 10, 0);
dirLight.target.position.set(-5, 0, 0);   // 朝哪照
scene.add(dirLight);
scene.add(dirLight.target);               // target 也必须加进场景，否则不生效
```

方向光**必须把 `target` 也 `add` 进场景**。这是最常见的「光没反应」原因。调试时加 helper：

```js
scene.add(new THREE.DirectionalLightHelper(dirLight));
```

```js
// 点光源：从一点向所有方向发光。intensity 需要很大（因为按距离衰减）
const pointLight = new THREE.PointLight(0xffffff, 150);
pointLight.position.set(0, 10, 0);
pointLight.distance = 0;    // 0 = 照到无穷远；>0 则衰减到该距离为止
scene.add(pointLight);
scene.add(new THREE.PointLightHelper(pointLight));
```

点光/聚光的 `intensity` 和方向光的量级完全不同（150 vs 1），因为点光按距离平方衰减。别以为单位一样。

```js
// 聚光灯：加了锥形的点光。角内是内锥，角外是外锥，之间是渐变带
const spotLight = new THREE.SpotLight(0xffffff, 150);
spotLight.angle = THREE.MathUtils.degToRad(30);  // 锥角，弧度
spotLight.penumbra = 0.5;                        // 内锥占外锥的比例，0..1
spotLight.target.position.set(-5, 0, 0);
scene.add(spotLight);
scene.add(spotLight.target);
scene.add(new THREE.SpotLightHelper(spotLight));
```

`penumbra` 的精确含义：

- `0`：内外锥同大小 → 边缘**锐利**（默认）。
- `1`：从锥心就开始衰减 → 边缘**最柔**。
- `0.5`：从锥的 50% 半径处开始衰减。

```js
// 矩形面光：模拟长条灯管、磨砂天窗。只对 Standard / Physical 材质有效
import { RectAreaLightUniformsLib } from 'three/addons/lights/RectAreaLightUniformsLib.js';
RectAreaLightUniformsLib.init();   // 忘了这行，光照会「看起来怪怪的」

const rectLight = new THREE.RectAreaLight(0xffffff, 5, 12, 4);
rectLight.position.set(0, 10, 0);
rectLight.rotation.x = THREE.MathUtils.degToRad(-90);
scene.add(rectLight);
```

`RectAreaLight` 的两个特殊性：**不用 `target`，靠 `rotation` 定方向**；**必须把 helper 挂成它的子节点**（其他 helper 是挂在 scene 上的）。

**什么时候用**：
- 环境光 → 永远作为「垫底」，低 `intensity` 防止暗部全黑。
- 半球光 → 户外场景，替代环境光，带一点天地色。
- 方向光 → 一个主光源（太阳、主灯）。
- 点光 → 灯泡、蜡烛、发光小球。
- 聚光 → 舞台追光、手电筒、车前灯。
- 矩形面光 → 室内建筑的柔和主光、产品展示。

**什么时候别用**：
- **每个光源都会拖慢渲染**。三个以内是常态，超过五个要想清楚。优先用「一个方向光 + 半球光」解决 80% 的场景。
- 不要用多个点光来堆亮度 —— 直接用更强的方向光或环境光更便宜。
- `RectAreaLight` 别用在 `MeshPhongMaterial` 上，完全不生效。

### T16 阴影：开启方式与真实代价

先看代价，再决定要不要开。Three.js 用的是 **shadow map**。规则是：**每个投射阴影的光源，都会把场景里所有投射阴影的物体重画一遍**。

```
20 个物体 + 5 个光源（都投阴影）
= 场景被画 6 次
= 每个物体被画 5 次（给每个光源），加上最终画面 1 次
```

如果是**点光源**投阴影，因为要朝立方体的 6 个面各画一次，**一个点光源就是 6 遍**。

开启需要的四步：

```js
// 1. 渲染器开启阴影
const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.shadowMap.enabled = true;

// 2. 光源开启投射
light.castShadow = true;
light.position.set(0, 10, 5);
light.target.position.set(-5, 0, 0);

// 3. 谁投阴影
mesh.castShadow = true;

// 4. 谁接收阴影
groundMesh.receiveShadow = true;
```

只有 `DirectionalLight`、`SpotLight`、`PointLight` 支持阴影。

**常见 bug：阴影缺一块**。原因是每个光源有自己的「阴影相机」，它定义了「哪块区域的阴影会被计算」，区域外的物体不参与。把阴影相机可视化了就一目了然：

```js
const cameraHelper = new THREE.CameraHelper(light.shadow.camera);
scene.add(cameraHelper);

// 方向光用正交阴影相机，靠 left/right/top/bottom/near/far 定区域
light.shadow.camera.left   = -30;
light.shadow.camera.right  =  30;
light.shadow.camera.top    =  30;
light.shadow.camera.bottom = -30;
light.shadow.camera.near   =   0.1;
light.shadow.camera.far    =  50;
light.shadow.camera.updateProjectionMatrix();
```

**第二个 bug：阴影很块状/马赛克**。阴影贴图是一张有固定尺寸的纹理（默认 512×512），上面那个区域会被拉伸铺到这张贴图上。区域越大，每个像素覆盖的物理范围越大，阴影越糊。

```js
// 提高分辨率（默认 512）
light.shadow.mapSize.width  = 2048;
light.shadow.mapSize.height = 2048;

// 但真正要做的是「缩小阴影相机区域」—— 越小越清晰，且不费显存
light.shadow.camera.left   = -20;
light.shadow.camera.right  =  20;
```

上限受 `renderer.capabilities.maxTextureSize` 约束。

**三种更省的方式**（真实项目里比开阴影贴图更常见）：

```js
// 方案 A：只让一个方向光投阴影，其他光源不投
dirLight.castShadow = true;
pointLight.castShadow = false;   // 默认就是 false
```

```js
// 方案 B：烘焙光照贴图 / AO 贴图（离线算好，运行时零成本）
// 方案 C：假阴影 —— 在半透明贴图上画一片灰，贴在物体下方的地面上
const shadowMat = new THREE.MeshBasicMaterial({
  map: shadowTexture,        // 一张模糊的圆形灰度图
  transparent: true,
  depthWrite: false,         // 多片阴影重叠时不互相遮挡
});
const shadowMesh = new THREE.Mesh(new THREE.PlaneGeometry(1, 1), shadowMat);
shadowMesh.position.y = 0.001;          // 抬高一点点防止和地面 z-fighting
shadowMesh.rotation.x = -Math.PI / 2;
shadowMesh.scale.setScalar(sphereRadius * 4);
```

假阴影还能**随物体高度淡出**，效果极好：

```js
const yOff = Math.abs(Math.sin(time * 2));      // 0..1 的弹跳量
shadowMesh.material.opacity = THREE.MathUtils.lerp(1, 0.25, yOff);  // 越高越淡
```

**什么时候用**：
- 单个方向光 + 中小场景 → 真阴影（`mapSize: 2048`，阴影相机贴紧场景）。
- 移动端 / 大量物体 / 风格化美术 → **假阴影**。便宜得多，而且卡通风格的圆片阴影反而更「对味」。
- 静态场景（建筑、产品）→ 烘焙光照贴图，运行时完全免费。

**什么时候别用**：
- 别给多个光源同时开阴影，尤其别给点光源开（6 倍代价）。
- 别靠「把阴影相机开到 100×100」来覆盖整个场景 —— 得到的是马赛克阴影。
- 别在低端机上开 4K 阴影贴图。

### T17 环境贴图与 HDRI：不需要光源的照明

环境贴图（environment map）让物体表面**反射周围环境**。对于 PBR 材质，它还充当**环境光照** —— 也就是「没有光源时物体也有明暗」，这是做出真实感的关键。

三种背景/环境方案，从简单到真实：

```js
// A. 纯色背景
scene.background = new THREE.Color(0xaaaaaa);

// B. CSS 背景图（最省 —— 完全不占 GPU 计算）
// canvas { background: url(bg.jpg) no-repeat center center; background-size: cover; }
// 同时渲染器要开 alpha 让没画东西的地方透出来
const renderer = new THREE.WebGLRenderer({ antialias: true, canvas, alpha: true });
```

```js
// C. 全景图（equirectangular，360 相机拍的那种）
const loader = new THREE.TextureLoader();
const texture = loader.load('equirect.jpg', () => {
  texture.mapping = THREE.EquirectangularReflectionMapping;
  texture.colorSpace = THREE.SRGBColorSpace;
  scene.background = texture;    // 当背景
  scene.environment = texture;   // 同时当作环境光照，PBR 材质立刻变真实
});
```

`scene.background` 和 `scene.environment` 是**两个独立的东西**：

- `background` 只是「画在后面的图」。
- `environment` 是「参与光照计算的图」。
- 通常两个给同一张贴图，但你可以只要其中一个（比如要环境光照但背景用纯色）。

```js
// D. Cubemap（6 张图，对应立方体六个面）
const cubeLoader = new THREE.CubeTextureLoader();
const cubeTex = cubeLoader.load([
  'pos-x.jpg', 'neg-x.jpg',
  'pos-y.jpg', 'neg-y.jpg',
  'pos-z.jpg', 'neg-z.jpg',
]);
scene.background = cubeTex;      // cubemap 不需要调 repeat/offset
```

**如果用普通图片当背景**，要注意拉伸问题（图片宽高比和画布不一致时会被拉扁）。手动算 `repeat/offset` 保住宽高比：

```js
const canvasAspect = canvas.clientWidth / canvas.clientHeight;
const imageAspect = bgTexture.image ? bgTexture.image.width / bgTexture.image.height : 1;
const aspect = imageAspect / canvasAspect;
bgTexture.offset.x = aspect > 1 ? (1 - 1 / aspect) / 2 : 0;
bgTexture.repeat.x = aspect > 1 ? 1 / aspect : 1;
bgTexture.offset.y = aspect > 1 ? 0 : (1 - aspect) / 2;
bgTexture.repeat.y = aspect > 1 ? 1 : aspect;
```

**什么时候用**：
- HDRI 环境贴图 → **任何想要真实感的 PBR 场景，这是最高性价比的一步**。一张 HDRI 顶好几个光源。
- Cubemap → 需要「人在一个封闭空间里转头看四周」的效果。
- CSS 背景 → 纯装饰性背景，不需要参与光照，也不需要被后处理影响。
- `scene.background = 贴图` → 背景要参与后处理（模糊、色调映射）时。

**什么时候别用**：
- HDRI 文件很大（2K 的约 1–5MB）。移动端要缩到 1K 或更小。
- 别为了「有个背景」就加载 HDRI —— CSS 背景免费得多。
- 用 `MeshBasicMaterial` / `MeshLambertMaterial` 时，`environment` 几乎不起作用（只有 PBR 材质完整支持）。这时候别浪费时间配环境贴图。

# 第五部分：相机与轨道控制

### T18 OrbitControls：让用户拖动相机

`OrbitControls` 是 addon，**必须单独 import**（不能只 import `three`）。

```js
import * as THREE from 'three';
import { OrbitControls } from 'three/addons/controls/OrbitControls.js';

const controls = new OrbitControls(camera, renderer.domElement);
controls.target.set(0, 5, 0);   // 环绕的中心点
controls.update();               // 改了 target 之后必须调
```

关键点：

- 第二个参数是「接收鼠标/触摸事件的 DOM 元素」。传 `renderer.domElement` 或你的 canvas。
- 旋转的中心由 `target` 决定，**不是相机的位置**。
- 在渲染循环里如果开了阻尼（`enableDamping`），**每帧都要 `controls.update()`**：

```js
controls.enableDamping = true;   // 惯性滑动，手感更顺
controls.dampingFactor = 0.05;

renderer.setAnimationLoop(() => {
  controls.update();             // 有阻尼时必须在每帧调用
  renderer.render(scene, camera);
});
```

**什么时候用**：任何「让用户自由查看 3D 物体」的场景（产品展示、模型查看器、图表 3D 版、3D 编辑器）。

**什么时候别用**：
- 相机需要按剧本走（过场动画、跟随角色）→ 用 `lookAt` + 手动插值，OrbitControls 会打架。
- **需要逐帧可复现渲染时**（T31）→ 阻尼是有状态的，会破坏确定性。要么关掉阻尼，要么完全不接入交互。
- 多个视图各自要独立相机时，注意每个 `OrbitControls` 要绑到**不同的 DOM 元素**，否则会抢事件。

### T19 OrthographicCamera：正交投影（2D / 三视图）

不透视，没有近大远小。用 `left/right/top/bottom/near/far` 定义一个**盒子**。

```js
const left = -1, right = 1, top = 1, bottom = -1;
const near = 5, far = 50;
const camera = new THREE.OrthographicCamera(left, right, top, bottom, near, far);
camera.zoom = 0.2;   // 缩小视野 = 放大画面
camera.updateProjectionMatrix();
```

**让它变成「1 单位 = 1 像素」的 2D 画布**（原点在中心）：

```js
camera.left   = -canvas.width  / 2;
camera.right  =  canvas.width  / 2;
camera.top    =  canvas.height / 2;
camera.bottom = -canvas.height / 2;
camera.near = -1;
camera.far  = 1;
camera.zoom = 1;
camera.updateProjectionMatrix();
```

**原点在左上角**（跟 Canvas 2D 坐标系一致）：

```js
camera.left   = 0;
camera.right  = canvas.width;
camera.top    = 0;
camera.bottom = canvas.height;    // 注意 top < bottom，y 向下增长
camera.near = -1;
camera.far  = 1;
camera.updateProjectionMatrix();
```

窗口尺寸变化时，正交相机要跟着改：

```js
if (resizeRendererToDisplaySize(renderer)) {
  camera.right  = canvas.width;
  camera.bottom = canvas.height;
  camera.updateProjectionMatrix();
}
```

**什么时候用**：
- 用 Three.js 画 2D 内容但想要 3D 的着色器和纹理能力（大量 sprite、粒子、后处理）。
- 工程三视图 / 建模软件的 quad view（1 个透视 + 3 个正交）。
- 像素级对齐的 2D 排版（像素艺术、精确图标摆放）。

**什么时候别用**：需要空间纵深感时。正交投影画面会「平」，做 3D 场景不自然。

# 第六部分：时间与动画

### T20 Clock 与 requestAnimationFrame 的组合

Three.js 提供 `Clock` 来管理时间。它和 `requestAnimationFrame` 是配合关系，不是替代关系。

```js
const clock = new THREE.Clock();

renderer.setAnimationLoop(() => {
  const dt = clock.getDelta();        // 距上一帧的秒数
  const t  = clock.getElapsedTime();  // 从 start 到现在的秒数

  cube.rotation.y = t;                // 用绝对时间：不累积误差
  // cube.position.x += dt * speed;   // 用 delta：适合速度积分

  renderer.render(scene, camera);
});
```

两者的适用场景不同：

| 时间量 | 方法 | 适合 |
| --- | --- | --- |
| 绝对时间 t | `getElapsedTime()` | 周期运动、正弦动画、旋转、基于 t 的着色器 `uTime` |
| 时间增量 dt | `getDelta()` | 速度积分、物理、帧率无关的位移 |

`setAnimationLoop` 回调里的 `time` 参数是 `DOMHighResTimeStamp`（毫秒），也可以直接换算：

```js
renderer.setAnimationLoop((time) => {
  const t = time * 0.001;   // 毫秒 → 秒
  // 但注意：这是 performance.now() 的绝对值，不是「从 0 开始」
  // 需要从 0 开始就在第一帧记下 T0，然后 (time - T0) * 0.001
});
```

`Clock` 内部也是用 `performance.now()`，但它帮你处理了 `T0` 和自动启动。

**什么时候用**：所有动画。默认组合就是「`setAnimationLoop` 的 time 参数 + `Clock.getElapsedTime()`」。

**什么时候别用**：静态内容（用 T32 的按需渲染）。以及需要严格可复现的场合 —— `getDelta()` 会累积浮点误差，同一段动画跑两遍结果会有微小差异（见下一条）。

---

### T21 逐帧确定性渲染：给定 t 渲染第 t 帧

目标：**`renderAtTime(3.25)` 执行一万次都得到完全相同的画面**。这样才能做帧对齐、离线导出、视觉回归测试、渲染农场。

三条规则：

**规则一：场景状态必须是 `t` 的纯函数。** 不能用 `+=`，不能读 `Date.now()` / `Math.random()`。

```js
// 反例：状态累积，不可复现
function badUpdate(dt) {
  cube.rotation.y += dt;             // 浮点误差随帧数累积
  cube.position.x += Math.random();  // 每次跑都不一样
}

// 正例：状态由 t 直接算出
function setStateAtTime(t) {
  cube.rotation.x = t * 0.8;
  cube.rotation.y = t * 1.5;
  cube.position.x = Math.sin(t * 2.0) * 3;
  // 需要「随机感」时用确定性伪随机，不叫 Math.random()
  const cell = Math.floor(t * 4);
  cube.scale.setScalar(1 + hash01(cell) * 0.5);
}

// 一个不依赖 Math.random 的确定性 hash
function hash01(n) {
  const s = Math.sin(n * 127.1 + 311.7) * 43758.5453;
  return s - Math.floor(s);
}

function renderAtTime(t) {
  setStateAtTime(t);
  renderer.render(scene, camera);
}
```

**规则二：不要依赖 `getDelta()` 的累积。** 用绝对时间：

```js
// 播放循环：把墙钟时间映射成确定性的 t
const clock = new THREE.Clock();
let t = 0;

renderer.setAnimationLoop(() => {
  const dt = clock.getDelta();   // 只用来推进 t，不直接改变场景
  t += dt * playbackSpeed;
  renderAtTime(t);               // 场景状态完全由 t 决定
});
```

**规则三：外部状态也要能给定。** 相机位置、uniform、模型的 morph 进度 —— 全都应该是 `setStateAtTime(t)` 的一部分。

```js
function setStateAtTime(t) {
  // 相机也走函数，不要靠 OrbitControls 的自由状态
  const a = t * 0.3;
  camera.position.set(Math.cos(a) * 8, 4, Math.sin(a) * 8);
  camera.lookAt(0, 1, 0);

  // uniform 也是 t 的函数
  shaderMaterial.uniforms.uTime.value = t;
}
```

导出精确一帧：

```js
// 无论播放到哪，这一句永远产出同一张图
renderAtTime(3.25);
const dataURL = renderer.domElement.toDataURL('image/png');
```

**什么时候用**：
- 离线导出视频/序列帧（每一帧都精确可控，不用「按实际帧率录屏」）。
- 视觉回归测试：固定 `t`，截图对比。
- 需要和音轨/时间轴严格对齐的动画。
- 服务端渲染缩略图。

**什么时候别用**：
- 交互式场景（用户拖动相机、鼠标跟随）本质上就是不确定的，别硬做。
- 用 `OrbitControls` + `enableDamping` 时不要指望确定性（阻尼是有状态的）。要做确定性就自己写相机运动（如上面的圆周环绕），或者用 `OrbitControls` 但每次渲染前把相机状态设回确定值。

### T22 按需渲染：不动的画面就别每帧画

静态场景跑 60fps 循环是纯浪费电。改成「只在需要时渲染」。

```js
let renderRequested = false;

function render() {
  renderRequested = false;

  if (resizeRendererToDisplaySize(renderer)) {
    const canvas = renderer.domElement;
    camera.aspect = canvas.clientWidth / canvas.clientHeight;
    camera.updateProjectionMatrix();
  }

  renderer.render(scene, camera);
}

function requestRenderIfNotRequested() {
  if (!renderRequested) {
    renderRequested = true;
    requestAnimationFrame(render);      // 合并同一帧内的多次请求
  }
}

render();                                        // 首帧
window.addEventListener('resize', requestRenderIfNotRequested);
controls.addEventListener('change', requestRenderIfNotRequested);  // 相机动了就重画
gui.onChange(requestRenderIfNotRequested);                        // 参数改了也重画
```

那个 `renderRequested` 标志位不是冗余 —— 它是**防止无限循环**的关键。如果开了 `controls.enableDamping`，`render` 里会调 `controls.update()`，而 `controls.update()` 又会派发 `change` 事件，`change` 又触发 `render`……用 `requestAnimationFrame` + 标志位把这个环断开。

**什么时候用**：3D 地图查看器、3D 编辑器、静态图表、产品目录、任何「用户不动就不变」的页面。

**什么时候别用**：游戏、粒子动画、视频墙 —— 这些本来就每帧都变，按需渲染没有意义。

# 第七部分：片段着色器 —— 把图形当距离场画

核心思想（来自 The Book of Shaders）：**不要「画一个圆」。而是「对每个像素，回答它到圆心的距离是多少」，然后用 `step` / `smoothstep` 把这个距离切成黑白。**

这就是 **distance field（距离场）**。它比「先算边界再填充」更容易做抗锯齿、描边、组合、形变。

### T23 GLSL 最小片段着色器骨架

一个能跑的最小片段着色器需要：声明精度、一个输出颜色。

```glsl
// 在 Three.js ShaderMaterial 里可以直接粘这一段
precision highp float;

uniform vec2  uResolution;   // 画布像素尺寸
uniform float uTime;         // 秒

void main() {
  // gl_FragCoord 是像素坐标，原点在左下角，范围 [0, 分辨率]
  vec2 st = gl_FragCoord.xy / uResolution.xy;   // 归一化到 0..1

  vec3 color = vec3(st.x, st.y, 0.0);           // 把坐标直接当颜色看
  gl_FragColor = vec4(color, 1.0);
}
```

必知的 GLSL 类型与函数：

```glsl
// 类型
float f = 1.0;            // 浮点必须带小数点！写 1 会编译失败
int   i = 1;
vec2  v2 = vec2(1.0, 0.0);
vec3  v3 = vec3(1.0);     // 单参数广播到所有分量
vec4  v4 = vec4(v3, 1.0);

// 常用内建函数
abs(x)  min(a,b)  max(a,b)  clamp(x,0.0,1.0)
floor(x)  fract(x)  mod(x,y)  sign(x)
length(v)  distance(a,b)  dot(a,b)  normalize(v)
step(edge,x)         // x < edge → 0.0，否则 1.0
smoothstep(e0,e1,x)  // 在 [e0,e1] 内平滑过渡 0→1，两端夹紧
mix(a,b,t)           // a*(1-t) + b*t
sin(x)  cos(x)  atan(y,x)  radians(deg)  degrees(rad)
```

向量分量有**多套别名**，可以互换，也可以组合（swizzle）：

```glsl
vec4 v;
v[0] = v.r = v.x = v.s;   // 四套名字指向同一个分量
v[1] = v.g = v.y = v.t;
v[2] = v.b = v.z = v.p;
v[3] = v.a = v.w = v.q;

// swizzle：任意顺序、任意重复
vec3 yellow;
yellow.rg = vec2(1.0);      // r、g 设成 1
yellow[2] = 0.0;            // b 设成 0
vec3 magenta = yellow.rbg;  // 交换 g、b 通道
vec3 green   = yellow.bgb;  // 用 b 通道的值填 r、b
```

函数参数的修饰符（在 Book of Shaders 和 GLSL 里都常见）：

```glsl
int f(in vec4 a,       // 只读（默认就是 in）
      out vec3 b,      // 只写：用来「返回」额外结果
      inout int c);    // 可读写：相当于传引用
```

**什么时候用**：任何自定义效果 —— 渐变、噪声、光晕、遮罩、程序化纹理、后处理。

**什么时候别用**：能用 CSS 渐变 / SVG 滤镜做出来的效果。GLSL 的调试成本远高于 CSS。

---

### T24 `gl_FragCoord`、`st`、`uv` 的关系

三个坐标系统，别搞混：

| 名字 | 来源 | 范围 | 原点 |
| --- | --- | --- | --- |
| `gl_FragCoord` | 内建 varying | `[0, width] × [0, height]`（像素） | **左下角** |
| `st` | 自己算：`gl_FragCoord.xy / uResolution` | `0..1` | **左下角** |
| `uv` | 顶点属性，从顶点着色器传过来 | `0..1` | **左下角**（Three.js 约定） |

```glsl
// 屏幕空间（推荐：不受几何体形状影响）
vec2 st = gl_FragCoord.xy / uResolution.xy;

// 物体表面空间（需要 vertexShader 传 varying）
// vertexShader: varying vec2 vUv; vUv = uv;
// fragmentShader: varying vec2 vUv;
```

选哪个：

- **`st`（屏幕空间）**：全屏着色器、背景、UI 覆盖层、不随几何体缩放的图案。**默认选这个。**
- **`uv`（表面空间）**：图案要贴在物体表面上跟着走（棋盘贴图、木纹、法线贴图）。

两者都有一个陷阱：**它们默认不是方的**。`st` 在 16:9 画布上，x 范围 0..1 但 y 只有 0..1 的「可见高度」对应更少的像素 —— 画出来的圆会是椭圆。修正方法：

```glsl
// 把坐标等比拉伸，保证圆是正圆
vec2 st = gl_FragCoord.xy / uResolution.xy;
st.x *= uResolution.x / uResolution.y;    // 或者 st.x *= aspect
st -= vec2(uResolution.x / uResolution.y * 0.5, 0.5);   // 重新居中
```

**什么时候用 `st`**：全屏效果、2D 图形、不关心物体形状的图案。

**什么时候用 `uv`**：纹理/图案要跟着物体走、要做平铺贴图、要用 `MeshStandardMaterial` 之外的接法。

**什么时候别用**：不要用 `gl_FragCoord` 原值当坐标做几何运算 —— 像素数值量级（几百到几千）会让所有手调的阈值失效。先用 `uResolution` 归一化。

---

### T25 形状函数：用 `step` 画矩形

`step(edge, x)` 的返回是 `0.0` 或 `1.0`。乘起来就是逻辑 **AND**。

```glsl
uniform vec2 uResolution;

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;

  // 每个分量独立判断：x > 0.1 且 y > 0.1
  vec2  borders = step(vec2(0.1), st);
  float pct     = borders.x * borders.y;   // 乘法 = AND

  // 另外两条边：把坐标翻转，同一个技巧再来一次
  vec2  bordersTR = step(vec2(0.1), 1.0 - st);
  pct *= bordersTR.x * bordersTR.y;

  gl_FragColor = vec4(vec3(pct), 1.0);
}
```

展开写更直观：

```glsl
// 四条边：左下角 (0.1,0.1) 到右上角 (0.9,0.9) 的实心矩形
float left   = step(0.1, st.x);
float bottom = step(0.1, st.y);
float right  = step(0.1, 1.0 - st.x);
float top    = step(0.1, 1.0 - st.y);
float rect   = left * bottom * right * top;

// 反相（画边框而不是实心）
float border = max(left, bottom) - left * bottom;   // 或者用下面的 abs 方法（T26）
```

**什么时候用**：想要硬边（无抗锯齿）的矩形、像素风、遮罩区域划分、快速原型。以及所有「阈值判断」的场景（不只是画图形，也包括「亮度超过某值就…」）。

**什么时候别用**：需要抗锯齿的边缘 —— `step` 是硬切的，斜边会有阶梯。用 `smoothstep`（T27）或 `fwidth`（T29）。

### T26 SDF 形状函数：`abs` 折叠象限画矩形

把坐标对中心取 `abs`，四个象限就折叠成一个；再用 Chebyshev 距离（`max(|x|,|y|)`）就得到正方形的距离场。

```glsl
uniform vec2 uResolution;

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;

  vec2 p = abs(st - 0.5);          // 折叠：四个象限 → 第一象限
  float d = max(p.x, p.y) - 0.3;   // Chebyshev 距离，减 0.3 是「半径」

  // d < 0 在内部，d > 0 在外部
  float inside = 1.0 - step(0.0, d);
  gl_FragColor = vec4(vec3(inside), 1.0);
}
```

通用的**矩形 SDF**（带圆角、能进 SDF 运算体系）：

```glsl
// p: 相对矩形中心的坐标；b: 半宽半高
float sdBox(vec2 p, vec2 b) {
  vec2 d = abs(p) - b;
  return length(max(d, 0.0)) + min(max(d.x, d.y), 0.0);
}

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;
  vec2 p = st - 0.5;
  p.x *= uResolution.x / uResolution.y;      // 修正宽高比

  float d = sdBox(p, vec2(0.3, 0.2));        // 0.6 × 0.4 的矩形
  float m = 1.0 - smoothstep(-0.005, 0.005, d);
  gl_FragColor = vec4(vec3(m), 1.0);
}
```

**矩形边框**（空心）也用 `abs`：

```glsl
float d     = sdBox(p, vec2(0.3, 0.2));
float outline = abs(d) - 0.01;              // |d| 小的位置 → 边框
float m     = 1.0 - smoothstep(-0.005, 0.005, outline);
gl_FragColor = vec4(vec3(m), 1.0);
```

`abs(d) - 线宽` 这个模式对所有 SDF 都适用 —— 这是画描边的通用手法，一次学会到处用。

**什么时候用**：需要组合多个形状、需要描边、需要圆角、需要抗锯齿（T29）。**SDF 是画图形的正规做法。**

**什么时候别用**：只想画一个硬边色块（`step` 更短）。以及不能接受 SDF 函数库体积的极限抠体积场景。

### T27 形状函数：用 `length` 画圆

圆就是「到中心距离 < 半径」的区域。

```glsl
uniform vec2 uResolution;

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;

  // 三种等价写法，选一个
  float d1 = distance(st, vec2(0.5));
  float d2 = length(st - vec2(0.5));
  vec2  dv = st - vec2(0.5);
  float d3 = sqrt(dv.x * dv.x + dv.y * dv.y);

  // 小于半径的涂白
  float circle = 1.0 - step(0.2, d1);
  gl_FragColor = vec4(vec3(circle), 1.0);
}
```

如果想直接当 SDF 用（推荐）：

```glsl
float dCircle(vec2 p, float r) {
  return length(p) - r;    // d < 0 内部，> 0 外部
}

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;
  vec2 p  = st - 0.5;
  p.x *= uResolution.x / uResolution.y;

  float d = dCircle(p, 0.3);
  float m = 1.0 - smoothstep(0.0, 0.02, d);
  gl_FragColor = vec4(vec3(m), 1.0);
}
```

**性能提示**：`length()` / `distance()` / `sqrt()` 在 GPU 上比加减乘除贵。如果只是想要「圆形衰减」，可以用 `dot` 避免开方：

```glsl
// r2 = d^2，比较平方距离即可，省掉 sqrt
float r2   = dot(p, p);
float glow = 1.0 - smoothstep(0.0, 0.09, r2);   // 注意阈值也要平方（0.3² = 0.09）
```

**什么时候用**：圆点、光圈、径向渐变、发光、圆形遮罩、任何「以某点为中心的衰减」。

**什么时候别用**：大量圆（几千个）用逐个 `distance()` 会很慢 —— 改用 T37 的极坐标技巧或 InstancedMesh。需要「正圆」时记得先修正宽高比（上面 `p.x *= aspect`）。

### T28 形状函数：十字与星形

**十字**：两个矩形的**并集**（`min`）。

```glsl
float sdBox(vec2 p, vec2 b) {
  vec2 d = abs(p) - b;
  return length(max(d, 0.0)) + min(max(d.x, d.y), 0.0);
}

uniform vec2 uResolution;

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;
  vec2 p  = st - 0.5;
  p.x *= uResolution.x / uResolution.y;

  // 竖条 ∪ 横条：并集用 min
  float vertical   = sdBox(p, vec2(0.06, 0.35));
  float horizontal = sdBox(p, vec2(0.35, 0.06));
  float d = min(vertical, horizontal);

  float m = 1.0 - smoothstep(0.0, 0.008, d);
  gl_FragColor = vec4(vec3(m), 1.0);
}
```

如果要**带圆角的十字**，用 `min` 前先各自减一个小圆角半径再补回来：

```glsl
float r = 0.03;
float d = min(vertical, horizontal) - r;    // 相当于给整体倒圆角
```

**星形**：改极坐标下「半径随角度变化」。这是 Book of Shaders 第 7 章的 polar shapes 核心。

```glsl
uniform vec2 uResolution;
uniform float uTime;
uniform float uSpikes;      // 几个尖角，比如 5.0

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;

  // 转到「以中心为原点」并修正宽高比
  vec2 pos = st - 0.5;
  pos.x *= uResolution.x / uResolution.y;

  float r = length(pos) * 2.0;          // 半径，中心 0、边缘约 1
  float a = atan(pos.y, pos.x);         // 角度，-PI..PI

  // 用 cos 调制半径：角度转到尖角处半径最大
  float shape = 0.5 + 0.5 * cos(a * uSpikes);
  float radius = mix(0.15, 0.55, shape);   // 内径 → 外径

  float d = r - radius;
  float m = 1.0 - smoothstep(0.0, 0.01, d);

  gl_FragColor = vec4(vec3(m), 1.0);
}
```

`uSpikes` 换成 `6.0` 就是六角星，`3.0` 是三角星。加时间让星慢转：

```glsl
float a = atan(pos.y, pos.x) + uTime * 0.5;   // 角度整体偏移 = 旋转
```

**什么时候用**：星形、花形、齿轮、雪花、徽章 —— 任何「N 个重复瓣」的对称图形。极坐标一章的所有技巧都能用在星形上。

**什么时候别用**：形状尖端需要极锐利（`cos` 调制的尖端是圆的）。要锐利尖角得用 `pow(abs(cos(...)), k)` 或直接写多边形 SDF。

### T29 距离场抗锯齿：用 `fwidth` 让边缘不锯齿

`step` / `smoothstep` 的阈值是**屏幕无关**的常数。屏幕像素越密，边缘跨越的像素越少，锯齿越明显。`fwidth` 给出「当前像素上，这个量的变化率」，用它当平滑宽度就是**像素级自适应**的抗锯齿。

```glsl
uniform vec2 uResolution;

float sdCircle(vec2 p, float r) { return length(p) - r; }

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;
  vec2 p  = st - 0.5;
  p.x *= uResolution.x / uResolution.y;

  float d = sdCircle(p, 0.3);

  // fwidth(d)：d 在一个像素内的变化量 ≈ 一个像素的物理宽度
  float w = fwidth(d);

  // 用 ±w 作为过渡带 → 边缘正好柔和一个像素
  float m = 1.0 - smoothstep(-w, w, d);

  gl_FragColor = vec4(vec3(m), 1.0);
}
```

想要「几个像素宽」的软边就乘系数：

```glsl
float m = 1.0 - smoothstep(-w * 1.5, w * 1.5, d);
```

`fwidth` 的正确性来自它的定义：`fwidth(x) = abs(dFdx(x)) + abs(dFdy(x))`，也就是 x 在 x、y 方向上的梯度之和。用 SDF 的距离值求 `fwidth`，得到的就是「一个像素对应的距离」。

**它同样适用于边框**（和 T26 的 `abs` 组合）：

```glsl
float outline = abs(d) - 0.01;
float w = fwidth(outline);
float m = 1.0 - smoothstep(-w, w, outline);
```

**兼容性**：`fwidth` 属于导数函数。Three.js 默认编译 GLSL ES 1.00；在 WebGL2 上下文里导数函数可以直接用。如果目标包含 WebGL1，需要显式声明 GLSL3：

```js
const material = new THREE.ShaderMaterial({
  glslVersion: THREE.GLSL3,
  uniforms: { uResolution: { value: new THREE.Vector2() } },
  vertexShader,
  fragmentShader,
});
```

Three.js 在 GLSL3 模式下会通过内建宏保持 `varying` / `gl_FragColor` 的写法可用，所以代码不用改。

**什么时候用**：**只要画 SDF 形状就该用**。这是「看起来专业 vs 看起来凑活」的分界线。

**什么时候别用**：目标环境连导数函数都没有（极老的 WebGL1 + 无扩展设备）。以及在**非均匀缩放**的物体上（`fwidth` 会给出失真值）—— 那种情况改用常数阈值。

### T30 颜色混合：`mix` 与 `clamp`

`mix(a, b, t)` 就是 `a*(1-t) + b*t`，`t` 被设计成 `0..1` —— 正好和前面所有成形函数（`smoothstep`、`sin` 归一化后）的输出范围对齐。这是「图形 → 颜色」的桥梁。

```glsl
uniform vec2 uResolution;
uniform float uTime;

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;

  vec3 colorA = vec3(0.0, 0.5, 0.8);
  vec3 colorB = vec3(0.9, 0.4, 0.1);

  // 沿 x 轴做渐变
  float t = st.x;
  vec3 color = mix(colorA, colorB, t);

  gl_FragColor = vec4(color, 1.0);
}
```

**用 `vec3` 当 `t`：逐通道混合**（做出「不是直线过渡」的彩色渐变）：

```glsl
// t 是 vec3，每个通道走自己的曲线
vec3 t = vec3(
  st.x,
  smoothstep(0.2, 0.8, st.x),
  pow(st.x, 3.0)
);
vec3 color = mix(colorA, colorB, t);
```

**用 `sin` 做呼吸/往返过渡**：

```glsl
// abs(sin) 得到 0..1 的往返值
float t = abs(sin(uTime));
vec3 color = mix(colorA, colorB, t);
```

**`clamp` 的两个用途**：

```glsl
// 1. 防止越界（HDR 色调映射前的安全网）
color = clamp(color, 0.0, 1.0);

// 2. 把任意范围映射到 0..1
float d = length(p) - 0.3;              // 可能是 -0.3 .. 0.7
float t = clamp(d * 5.0 + 0.5, 0.0, 1.0);   // 强行压进 0..1

// 也可以直接用 remap 写法
float t2 = (d - (-0.3)) / (0.7 - (-0.3));
float t3 = clamp(t2, 0.0, 1.0);
```

**加色混合**（发光、叠加）用加法，注意 `clamp` 防溢出：

```glsl
vec3 glow = vec3(1.0, 0.6, 0.2) * intensity;
color = clamp(color + glow, 0.0, 1.0);
```

**什么时候用**：几乎所有「形状 + 颜色」的组合。`mix` 用于插值/混合，`clamp` 用于钳位。

**什么时候别用**：需要 HSL 空间插值时不要在 RGB 里 `mix`（两种颜色之间会经过灰色）。那种情况先转 HSB（T31）再插值。

### T31 极坐标与 HSB 颜色

**Cartesian → Polar**（Book of Shaders 第 7 章的核心换元）：

```glsl
vec2 pos = vec2(0.5) - st;      // 以中心为原点，注意 y 方向（这里 y 向上）
float r = length(pos) * 2.0;    // 半径，归一化到约 0..1
float a = atan(pos.y, pos.x);   // 角度，-PI..PI
```

`atan(y, x)`（GLSL 版 `atan2`）返回 `-PI..PI`。要归一化到 `0..1`：

```glsl
#define TWO_PI 6.28318530718
float angle01 = a / TWO_PI + 0.5;   // -0.5..0.5 → 0..1
float radius01 = r * 0.5;           // 最大 0.5，乘 2 反过来
```

**HSB（色相/饱和度/亮度）**：比 RGB 直观得多，非常适合「把角度映射成色相」这种操作。

```glsl
vec3 rgb2hsv(vec3 c) {
  vec4 K = vec4(0.0, -1.0 / 3.0, 2.0 / 3.0, -1.0);
  vec4 p = mix(vec4(c.bg, K.wz), vec4(c.gb, K.xy), step(c.b, c.g));
  vec4 q = mix(vec4(p.xyw, c.r), vec4(c.r, p.yzx), step(p.x, c.r));
  float d = q.x - min(q.w, q.y);
  float e = 1.0e-10;
  return vec3(abs(q.z + (q.w - q.y) / (6.0 * d + e)), d / (q.x + e), q.x);
}

vec3 hsv2rgb(vec3 c) {
  vec4 K = vec4(1.0, 2.0 / 3.0, 1.0 / 3.0, 3.0);
  vec3 p = abs(fract(c.xxx + K.xyz) * 6.0 - K.www);
  return c.z * mix(K.xxx, clamp(p - K.xxx, 0.0, 1.0), c.y);
}
```

**色相环 / 色轮**（HSB 天生适合极坐标）：

```glsl
#define TWO_PI 6.28318530718
uniform vec2 uResolution;

// 把上面两个 rgb2hsv / hsv2rgb 的完整实现粘到此处，再写 main

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;
  vec2 pos = st - 0.5;

  float r = length(pos) * 2.0;
  float a = atan(pos.y, pos.x);

  float hue        = a / TWO_PI + 0.5;    // 角度 → 色相
  float saturation = 1.0;                 // 或者 = r，做径向饱和度变化
  float brightness = 1.0;                 // 或者 = 1.0 - r，做中心亮

  vec3 color = hsv2rgb(vec3(hue, saturation, brightness));
  gl_FragColor = vec4(color, 1.0);
}
```

**放射状 / 扇形图案**（`atan` 的另一个高频用法）：

```glsl
uniform vec2 uResolution;
uniform float uTime;

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;
  vec2 pos = st - 0.5;
  pos.x *= uResolution.x / uResolution.y;

  float a = atan(pos.y, pos.x);
  float r = length(pos);

  // 12 条辐射瓣，随时间和半径扭转
  float rays = 0.5 + 0.5 * cos(a * 12.0 + uTime * 1.5 + r * 6.0);

  // 半径衰减，让中心亮、边缘暗
  float fade = 1.0 - smoothstep(0.0, 0.7, r);

  vec3 color = vec3(rays * fade);
  gl_FragColor = vec4(color, 1.0);
}
```

`cos(a * N)` 里的 `N` 就是瓣数。加 `r * k` 会得到螺旋（因为半径越大角度偏移越多）。

**什么时候用**：
- 色相环、彩虹、按角度着色的仪表盘。
- 放射光、星芒、螺旋、花朵、齿轮。
- 雷达/声呐、饼图的极坐标绘制。
- **任何「绕中心对称」的图案** —— 极坐标会大幅简化公式。

**什么时候别用**：非中心的图案、矩形裁剪、需要精确直线边界的场合。`atan` 在 `±PI` 处有**接缝**（`-PI` 和 `+PI` 是同一条线），画连续图案时会在某一角度出现一条亮线 —— 需要单独处理（比如用 `fract` 让图案在接缝处闭合）。

### T32 图案函数：`random` / `hash` 做伪随机

GLSL 没有 `Math.random()`。标准做法是把坐标塞进 `sin` 再取小数部分。

```glsl
// 最经典的 2D 伪随机（够用，但高精度下有规律）
float random(vec2 st) {
  return fract(sin(dot(st.xy, vec2(12.9898, 78.233))) * 43758.5453123);
}

// 更稳的 2D hash（推荐，工业级写法）
float hash21(vec2 p) {
  p = fract(p * vec2(123.34, 456.21));
  p += dot(p, p + 45.32);
  return fract(p.x * p.y);
}
```

**关键点：必须先量化坐标**。直接 `random(st)` 会像噪点一样糊成一片，因为每个像素坐标都不同。想做「一小格一个随机值」必须先 `floor`：

```glsl
uniform vec2 uResolution;

float hash21(vec2 p) {
  p = fract(p * vec2(123.34, 456.21));
  p += dot(p, p + 45.32);
  return fract(p.x * p.y);
}

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;

  vec2 cells = floor(st * 20.0);        // 20×20 的格子
  float n = hash21(cells);              // 每格一个 0..1 的随机值

  vec3 color = vec3(n);                 // 灰度噪声图
  gl_FragColor = vec4(color, 1.0);
}
```

用随机值驱动颜色（彩色马赛克）：

```glsl
vec2 cells = floor(st * 12.0);
float n = hash21(cells);
vec3 color = hsv2rgb(vec3(n, 0.7, 1.0));   // 随机色相
gl_FragColor = vec4(color, 1.0);
```

用随机值驱动几何（随机大小的方块）：

```glsl
vec2 cells = floor(st * 10.0);
vec2 local = fract(st * 10.0) - 0.5;        // 格内坐标 -0.5..0.5
float n = hash21(cells);
float size = mix(0.1, 0.45, n);             // 每格不同大小
float d = length(local) - size;             // 圆形
// float d = max(abs(local).x, abs(local).y) - size;   // 或者方形
float m = 1.0 - smoothstep(0.0, 0.02, d);
gl_FragColor = vec4(vec3(m), 1.0);
```

**什么时候用**：噪点纹理、星星散布、马赛克、随机变形、任何「避免规整感」的地方。程序化生成的场景里，它是打破机械感的唯一手段。

**什么时候别用**：
- 不能用于加密或任何安全性需求 —— 这是 hash 的视觉近似，不是密码学 hash。
- 需要**可复现的跨平台一致性**时小心：`sin` 在不同 GPU 上的精度略有差异，可能产出不同的图案。要严格一致就用整数位运算（需要 GLSL3）。
- 需要真随机（每次刷新都不同）→ 传一个 JS 生成的 `uSeed` uniform 进来。

---

### T33 图案函数：噪声（noise）

`random` 产出的是「跳变」的噪声（每格不同值，格与格之间不连续）。**值噪声（value noise）**在格点上取随机值，格内做平滑插值，于是就变得连续、有机。

```glsl
float hash21(vec2 p) {
  p = fract(p * vec2(123.34, 456.21));
  p += dot(p, p + 45.32);
  return fract(p.x * p.y);
}

// 2D 值噪声：返回 0..1，平滑连续
float noise(vec2 st) {
  vec2 i = floor(st);      // 格点索引
  vec2 f = fract(st);      // 格内坐标 0..1

  // 平滑插值系数：3f²-2f³（smoothstep 的多项式形式，两端导数为 0）
  vec2 u = f * f * (3.0 - 2.0 * f);

  // 四个角的随机值做双线性插值
  return mix(
    mix(hash21(i + vec2(0.0, 0.0)), hash21(i + vec2(1.0, 0.0)), u.x),
    mix(hash21(i + vec2(0.0, 1.0)), hash21(i + vec2(1.0, 1.0)), u.x),
    u.y
  );
}
```

多层噪声叠加得到 **fBm（分形噪声）**，得到云、地形那种细节丰富的纹理：

```glsl
float fbm(vec2 st) {
  float value = 0.0;
  float amplitude = 0.5;
  for (int i = 0; i < 5; i++) {          // 层数越多越细腻，也越慢
    value += amplitude * noise(st);
    st *= 2.0;                            // 每层频率翻倍
    amplitude *= 0.5;                     // 每层振幅减半
  }
  return value;
}
```

用 fBm 做云：

```glsl
uniform vec2 uResolution;
uniform float uTime;

// (noise / fbm 定义粘在这里)

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;
  st.x *= uResolution.x / uResolution.y;
  st *= 3.0;

  // 时间偏移 y，噪声就会像云一样流动
  float n = fbm(st + vec2(uTime * 0.1, uTime * 0.05));

  vec3 sky   = vec3(0.2, 0.5, 0.9);
  vec3 cloud = vec3(1.0);
  vec3 color = mix(sky, cloud, smoothstep(0.4, 0.7, n));

  gl_FragColor = vec4(color, 1.0);
}
```

**什么时候用**：云、雾、水面、木纹、石纹、地形高度、有机纹理、发光柔化、以及给任何规则图案「加脏」让它不机械。

**什么时候别用**：
- **fBm 常数多、开销大**。5 层噪声 = 20 次 hash + 大量 mix。如果需要覆盖全屏且还要叠其他效果，把层数降到 3。
- 不要用它做「确定性随机」（噪声是空间函数，同一坐标永远同一值 —— 想要时间随机用 T32 的 hash）。
- 需要真实感流体/体积效果时，值噪声不够，得上 simplex/worley。但那已经超出「手写 100 行以内」的范围了。

### T34 图案函数：`fract` 重复与 `floor`/`mod` 网格

`fract(x)` 取小数部分，等于「把无限空间折叠成一个格子」。这是做重复图案的第一工具。

```glsl
uniform vec2 uResolution;

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;

  // 坐标乘 8 再取小数 → 屏幕被折叠成 8×8 个重复的 [0,1] 空间
  vec2 cell = fract(st * 8.0);

  // 现在 cell 在每个格子里都是 0..1，画同样的东西就会重复 64 次
  float d = abs(length(cell - 0.5) - 0.3);
  float m = 1.0 - smoothstep(0.0, 0.05, d);   // 重复的圆环

  gl_FragColor = vec4(vec3(m), 1.0);
}
```

**格子编号**用 `floor`（`fract` 的搭档）：

```glsl
vec2 cell  = fract(st * 8.0);    // 格内坐标 0..1
vec2 id    = floor(st * 8.0);    // 格子编号（整数，当浮点用）

// 用格子编号做交替（棋盘）
float checker = mod(id.x + id.y, 2.0);
vec3 color = mix(vec3(0.1), vec3(0.9), checker);
```

**网格线**（用 `abs(fract - 0.5)` 找边界）：

```glsl
uniform vec2 uResolution;

void main() {
  vec2 st = gl_FragCoord.xy / uResolution.xy;
  float n = 10.0;                            // 10×10 格

  // 每个格中心为 0，边界为 0.5
  vec2 c = abs(fract(st * n) - 0.5);
  float edge = max(c.x, c.y);                // 靠近边界 → 趋近 0.5

  // 用 fwidth 做自适应线宽（T29）
  float w = fwidth(edge);
  float line = smoothstep(0.5 - w * 2.0, 0.5, edge);

  vec3 color = mix(vec3(0.05), vec3(0.8), line);
  gl_FragColor = vec4(color, 1.0);
}
```

**`mod` 做环绕索引**（做序列图案、调色板循环）：

```glsl
// 在 3 个颜色之间循环
float idx = mod(v, 3.0);   // 0,1,2,0,1,2...
```

**无限平铺的关键**：写完图案后不要用 `clamp` 或 `step` 破坏边界 —— 用 `fract` 折叠后的坐标算出的图案天然无缝（因为相邻格的边缘数值相同）。

**什么时候用**：纹理平铺、网格、棋盘、重复图标、瓦片背景、无限滚动的图案。

**什么时候别用**：
- `fract(st * n)` 在 `n` 很大时会有精度问题（远处坐标会抖）。UI 图案建议 `n ≤ 64`。
- 想要「不重复的噪声感」时不要用 `fract` —— 那正是 T32/T33 的活儿。`fract` 的目的是**刻意重复**。
- `fract` 在边界会产生硬接缝，如果图案本身在边界不连续，会出现一条明显的线。要做无缝图案，图案函数必须在 `0` 和 `1` 处取值相同。

### T35 距离场组合：`min` 并集、`max` 交集

一旦所有形状都写成 SDF（`d < 0` 内部），组合就是集合运算：

```glsl
float dCircle = length(p) - 0.3;
float dBox    = sdBox(p, vec2(0.25));

float dUnion        = min(dCircle, dBox);   // 并集：在任一形状内
float dIntersection = max(dCircle, dBox);   // 交集：同时在两个形状内
float dDifference   = max(dCircle, -dBox);  // 差集：在圆内且不在方块内
```

同时用 `mix` / `pow` 做「软过渡」（smooth union），得到液体融合感：

```glsl
// 软并集：k 越大越「粘」
float smoothUnion(float a, float b, float k) {
  float h = clamp(0.5 + 0.5 * (b - a) / k, 0.0, 1.0);
  return mix(b, a, h) - k * h * (1.0 - h);
}

float d = smoothUnion(dCircle, dBox, 0.1);
```

Book of Shaders 第 7 章还给了更「野」的组合方式，直接对距离值做算术：

```glsl
pct = distance(st, vec2(0.4)) + distance(st, vec2(0.6));   // 加法：花生形
pct = distance(st, vec2(0.4)) * distance(st, vec2(0.6));   // 乘法：夸张的融合
pct = min(distance(st, vec2(0.4)), distance(st, vec2(0.6)));  // 并集
pct = max(distance(st, vec2(0.4)), distance(st, vec2(0.6)));  // 交集
pct = pow(distance(st, vec2(0.4)), distance(st, vec2(0.6)));  // 指数：锯齿形
```

`fract` 一个距离场会得到「禅园沙纹」一样的同心环（因为距离场的等值线是同心圆）：

```glsl
vec2 p = abs(st - 0.5);                // 折叠到第一象限（四重对称）
float d = max(p.x, p.y);               // Chebyshev 距离 → 方形距离场
color = vec3(fract(d * 10.0));         // 同心方环
```

**`abs` 折叠象限是画对称图形的核心技巧**：先 `abs(st - center)`，四个象限的内容就完全一样了，代码量直接少一半。

**什么时候用**：图标、Logo、徽章、复杂遮罩、有机形状、液体融合（meta-ball）效果、字体渲染。SDF 是程序化图形的通用语言。

**什么时候别用**：只需要一个简单矩形或圆（直接写更短）。以及形状需要**精确曲线**（贝塞尔、字体轮廓）时 —— 手写 SDF 逼近成本高，用预先烘焙的 SDF 贴图（字体渲染就是这么干的）。

# 第八部分：在 Three.js 里用自定义着色器

### T36 ShaderMaterial 完整接法

目标：用自定义片段着色器画满一个平面，并带上时间和分辨率。

```html
<!DOCTYPE html>
<html>
<head>
  <meta charset="utf-8">
  <style>
    html, body { margin: 0; height: 100%; background: #111; }
    canvas { width: 100%; height: 100%; display: block; }
  </style>
  <script type="importmap">
  {
    "imports": {
      "three": "https://cdn.jsdelivr.net/npm/three@0.180.0/build/three.module.js"
    }
  }
  </script>
</head>
<body>
  <canvas id="c"></canvas>

  <script type="module">
    import * as THREE from 'three';

    const canvas = document.querySelector('#c');

    // 用正交相机做「全屏着色器」：视口正好是 -1..1
    const camera = new THREE.OrthographicCamera(-1, 1, 1, -1, 0, 1);

    const scene = new THREE.Scene();

    const renderer = new THREE.WebGLRenderer({ antialias: true, canvas });

    // ---- 顶点着色器：把 vUv 传给片段着色器 ----
    const vertexShader = /* glsl */ `
      varying vec2 vUv;
      void main() {
        vUv = uv;
        gl_Position = vec4(position, 1.0);
      }
    `;

    // ---- 片段着色器 ----
    const fragmentShader = /* glsl */ `
      precision highp float;

      uniform vec2  uResolution;
      uniform float uTime;

      varying vec2 vUv;

      float sdCircle(vec2 p, float r) { return length(p) - r; }

      void main() {
        // 屏幕空间归一化坐标（T24）
        vec2 st = gl_FragCoord.xy / uResolution.xy;
        vec2 p  = st - 0.5;
        p.x *= uResolution.x / uResolution.y;   // 修正宽高比，保证正圆

        float d = sdCircle(p, 0.3 + 0.05 * sin(uTime));
        float w = fwidth(d);                     // 像素级抗锯齿（T29）
        float m = 1.0 - smoothstep(-w, w, d);

        // mix 混合颜色（T30）
        vec3 bg    = vec3(0.06, 0.07, 0.10);
        vec3 front = vec3(0.20, 0.80, 0.90);
        vec3 color = mix(bg, front, m);

        gl_FragColor = vec4(color, 1.0);
      }
    `;

    const material = new THREE.ShaderMaterial({
      glslVersion: THREE.GLSL3,          // 保证 fwidth 在 WebGL1 上也能用
      uniforms: {
        uResolution: { value: new THREE.Vector2() },
        uTime:       { value: 0 },
      },
      vertexShader,
      fragmentShader,
    });

    // 铺满视口的平面（正交相机下 2×2 正好覆盖 -1..1）
    const mesh = new THREE.Mesh(new THREE.PlaneGeometry(2, 2), material);
    scene.add(mesh);

    // ---- resize：同步 drawingBuffer 和 uniform ----
    function resize() {
      const pixelRatio = Math.min(window.devicePixelRatio, 2);
      const w = Math.floor(canvas.clientWidth  * pixelRatio);
      const h = Math.floor(canvas.clientHeight * pixelRatio);
      if (canvas.width !== w || canvas.height !== h) {
        renderer.setSize(w, h, false);
      }
      material.uniforms.uResolution.value.set(w, h);
    }

    // ---- 渲染循环 ----
    const clock = new THREE.Clock();

    renderer.setAnimationLoop(() => {
      resize();
      material.uniforms.uTime.value = clock.getElapsedTime();
      renderer.render(scene, camera);
    });
  </script>
</body>
</html>
```

三个必须对齐的点：

1. **顶点着色器的 `gl_Position` 与相机匹配**。上面用正交相机 `-1..1` + `PlaneGeometry(2,2)`，所以直接 `gl_Position = vec4(position, 1.0)` 就铺满。如果用透视相机，就得写成标准式：
   ```glsl
   gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
   ```
   并且 `PlaneGeometry` 要放在相机视野内。

2. **`uResolution` 必须和 drawingBuffer 尺寸一致**，不是 CSS 尺寸。所以要在 `setSize` 之后同步更新 —— 否则 `gl_FragCoord / uResolution` 算出来的 `st` 会错位。

3. **`THREE.ShaderMaterial` 会自动注入内建 uniform / attribute**（`projectionMatrix`、`modelViewMatrix`、`position`、`uv`、`normal` 等），你不需要自己声明。只有你自己加的 uniform 才要写进 `uniforms`。

`glslVersion: THREE.GLSL3` 的说明：Three.js 会通过内建宏让 `varying` / `gl_FragColor` 的写法继续可用，所以代码不用改；但开启了之后 `fwidth` 在任何环境都能用。

如果哪天需要完全自己控制（连内建 uniform 都不要），用 `RawShaderMaterial` —— 那时所有 uniform/attribute 都要自己声明。

**什么时候用**：任何内置材质做不到的效果 —— 自定义光照模型、程序化纹理、特殊的混合与遮罩、全屏后处理（配合 `WebGLRenderTarget`）。

**什么时候别用**：
- 能用内置材质 + 贴图解决的，不要写 shader。shader 的调试成本（白屏、黑屏、无报错）远高于调 `roughness`。
- 需要光照 + 阴影 + 雾 + 环境贴图 时，不要从零写 `ShaderMaterial`。正确做法是 `material.onBeforeCompile` 去**改写**内置材质，这样所有光照逻辑都还在。
- 需要写 500 行以上的 shader 时，先想想是不是该用后处理管线（`EffectComposer`）而不是单材质。

### T37 uniforms 的更新方式与性能

`uniforms` 是「每帧可能变、所有像素共享」的值。和顶点属性（每个顶点一个值）相对。

```js
const material = new THREE.ShaderMaterial({
  uniforms: {
    uTime:       { value: 0 },                            // float
    uResolution: { value: new THREE.Vector2(1, 1) },      // vec2
    uColor:      { value: new THREE.Color(0xff8800) },    // vec3
    uTexture:    { value: someTexture },                  // sampler2D
    uMatrix:     { value: new THREE.Matrix4() },          // mat4
    uArray:      { value: new Float32Array([1, 2, 3]) },  // float[]
  },
  vertexShader,
  fragmentShader,
});

// 更新：改 value，不要重新创建 material
material.uniforms.uTime.value = t;
material.uniforms.uColor.value.setRGB(r, g, b);
```

在 `material.onBeforeCompile` 里给内置材质加 uniform：

```js
const uniforms = { uTime: { value: 0 } };

material.onBeforeCompile = (shader) => {
  shader.uniforms.uTime = uniforms.uTime;
  shader.vertexShader = shader.vertexShader.replace(
    '#include <common>',
    '#include <common>\nuniform float uTime;'
  );
  // 在片段着色器里注入计算…
};

// 之后照常更新
uniforms.uTime.value = clock.getElapsedTime();
```

**性能规则**：

- 改 `uniforms.x.value` 是**廉价**的（只是 JS 赋值），真正的上传发生在 `renderer.render()` 时。
- **不要每帧 `new THREE.ShaderMaterial(...)`** —— 那会触发着色器重编译，是几十毫秒级的卡顿。
- 复用一个 material 给多个 mesh 时，uniform 是共享的。要让每个 mesh 不同，就得 `material.clone()`（会各编译一份着色器），或者把差异放到顶点属性里。
- 大量物体用同一份 uniform → 用 `InstancedMesh` + `instanceMatrix`，别为每个物体建一个材质。

**什么时候用**：所有需要从 JS 往 GPU 传动态值的地方（时间、鼠标位置、进度、颜色、纹理）。

**什么时候别用**：值不会变（那就写死在 shader 里当 `const`，编译器能更好地优化）。以及值只和顶点有关（那应该是 attribute 不是 uniform）。

### T38 顶点着色器传 uv / 自建 varying

`varying` 是顶点着色器与片段着色器之间的「插值通道」。

```glsl
// ---- vertexShader ----
varying vec2 vUv;          // 传递贴图坐标
varying vec3 vNormalW;     // 传递世界空间法线

void main() {
  vUv = uv;                // uv 是 Three.js 自动注入的 attribute
  vNormalW = normalize(mat3(modelMatrix) * normal);

  gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}
```

```glsl
// ---- fragmentShader ----
precision highp float;
varying vec2 vUv;
varying vec3 vNormalW;

void main() {
  // 用插值过来的 uv 做图案（跟着物体走，不跟屏幕走）
  vec2 cell = fract(vUv * 8.0);
  float m = 1.0 - smoothstep(0.45, 0.5, max(abs(cell.x - 0.5), abs(cell.y - 0.5)));

  vec3 color = vec3(m);
  gl_FragColor = vec4(color, 1.0);
}
```

Three.js 自动注入的内建内容（用 `ShaderMaterial` 时不用声明）：

| 类别 | 名字 |
| --- | --- |
| 顶点 attribute | `position`、`normal`、`uv` |
| 矩阵 uniform | `modelMatrix`、`modelViewMatrix`、`projectionMatrix`、`viewMatrix`、`normalMatrix` |
| 相机相关 | `cameraPosition` |
| 顶点着色器内建输出 | `gl_Position`、`gl_PointSize` |
| 片段着色器内建输出 | `gl_FragColor` |

`varying` 的数量是有上限的（移动 GPU 通常 8–16 个 vec4）。**只传你真正需要的**。不要传 `vec3` 能表达的东西用 `vec4`，也不要把「能在片段着色器里从别的 varying 算出来」的值也传一份。

**`uv` vs `st` 再强调一次**：

- 用 `uv` → 图案贴在物体上，物体移动图案跟着动，物体被拉伸图案也拉伸。
- 用 `gl_FragCoord / uResolution` → 图案固定在屏幕上，物体怎么动图案都不动。

**什么时候用 `varying`**：纹理坐标、法线、世界坐标、顶点色、顶点级计算（如视锥剔除标记）。

**什么时候别用**：不要为了「省计算」把本该在片段着色器做的事放到顶点着色器（`MeshLambertMaterial` 的「逐顶点光照」就是这种妥协，效果差很多）。不要传冗余 varying。

# 第九部分：性能与降级

### T39 像素比限制：移动端第一优化

移动设备常有 `devicePixelRatio = 3`。也就是说一个 400×800 CSS 像素的区域有 1200×2400 = 288 万真实像素 —— **9 倍**于 `dpr = 1` 的工作量。

```js
// 方案 A：完全不管 dpr（最省，也是最常见的做法）
// 直接按 CSS 尺寸渲染，浏览器负责放大
renderer.setSize(canvas.clientWidth, canvas.clientHeight, false);

// 方案 B：限制上限（推荐）
const pixelRatio = Math.min(window.devicePixelRatio, 2);
renderer.setSize(
  Math.floor(canvas.clientWidth  * pixelRatio),
  Math.floor(canvas.clientHeight * pixelRatio),
  false
);

// 方案 C：按总像素数封顶（应对 150% 系统缩放等分数缩放场景）
const maxPixels = 1920 * 1080;                 // 或 3840 * 2160
const px = width * height;
if (px > maxPixels) {
  const s = Math.sqrt(maxPixels / px);
  width  = Math.floor(width  * s);
  height = Math.floor(height * s);
}
```

移动端把上限设成 1.5–2 是常态。肉眼分辨不出 2 和 3 的差别，但帧率差别巨大。

配合动态降级：

```js
// 简单自适应：连续掉帧就降像素比
let frames = 0, last = performance.now(), scale = 1.0;

function adapt() {
  frames++;
  const now = performance.now();
  if (now - last > 1000) {
    const fps = frames * 1000 / (now - last);
    if (fps < 45 && scale > 0.5) scale -= 0.1;
    else if (fps > 58 && scale < 1.0) scale += 0.05;
    frames = 0;
    last = now;
  }
}
```

**什么时候用**：所有会跑在移动设备上的 3D 内容。全屏着色器尤其敏感（像素数 = 着色器执行次数）。

**什么时候别用**：需要精确像素对齐的场合（后处理管线里 `RenderTarget` 的尺寸、GPU picking、截图导出）。这些场景你必须显式给定尺寸，不能让 dpr 参与。

---

### T40 着色器复杂度：成本模型

片段着色器的成本 = **像素数 × 每个像素的指令数**。所以：

```glsl
// 4 次纹理采样 —— 每次采样都是内存访问，很贵
vec4 c = texture2D(tex, uv) + texture2D(tex, uv2)
       + texture2D(tex, uv3) + texture2D(tex, uv4);

// 5 层 fBm = 20 次 hash + 大量 mix —— 计算密集型
float n = fbm(st);   // 每个像素跑 20 次 sin/hash

// 一个 length() 相对便宜，但全屏 × 60fps 也是可观的
float d = length(p);
```

降本手段，按收益排序：

```glsl
// 1. 降低分辨率（最有效，收益是平方级的）
//    全屏效果渲染到 0.5× 的 RenderTarget 再放大 —— 模糊类效果几乎看不出差别

// 2. 用平方距离省 sqrt
float r2 = dot(p, p);                              // 替代 length(p)*length(p)
float m  = 1.0 - smoothstep(0.0, 0.09, r2);

// 3. 用低阶近似替代高阶
float n = noise(st);                               // 1 层，替代 5 层 fbm

// 4. 减少分支和循环（GPU 上循环要展开）
//    固定次数的 for 比 while 好；能算成闭式就别循环

// 5. 把能预计算的东西挪到 JS 或纹理里
//    比如把噪声烘焙成一张贴图，shader 里只采样

// 6. 只在需要的区域计算（用 discard 或提前 return，但 GPU 上收益有限）
```

**什么时候用这些技巧**：移动端、全屏效果、4K 显示器、需要 60fps 的交互效果。

**什么时候别用**：桌面端单物体、离线烘焙、静态图导出 —— 这些场景下写清楚的 shader 比抠性能更重要。

### T41 WebGL2 vs WebGL1 的取舍

Three.js 的 `WebGLRenderer` 现在默认走 WebGL2（如果设备支持），失败则回退 WebGL1。

WebGL2 带来的实际好处：

- 原生的 GLSL ES 3.00（`in`/`out`、`texture()`、整数运算、`flat` 修饰符）。
- **导数函数（`fwidth` / `dFdx` / `dFdy`）不再需要扩展** —— 这也是为什么 T29 的抗锯齿在 WebGL2 上无痛。
- 3D 纹理、顶点纹理采样、`sampler2DArray`。
- 非 2 次幂纹理的完整支持（mipmap + repeat wrap）。
- 实例化渲染（`InstancedMesh`）无扩展依赖。

实际取舍：

```js
// 显式要 WebGL2
const renderer = new THREE.WebGLRenderer({ antialias: true });

// 检查实际拿到的版本
console.log(renderer.capabilities.isWebGL2);          // true / false
console.log(renderer.capabilities.maxTextureSize);    // 别超过这个值

// 需要严格 WebGL1 兼容（老设备、某些嵌入式浏览器）时的写法
// 避免依赖：整数位运算、3D 纹理、sampler2DArray、导数函数的有无
```

**判断策略**：

- **2026 年的常态**：假设 WebGL2 可用。用 `fwidth`、`InstancedMesh`、非 2 次幂纹理都不用犹豫。
- **需要覆盖 2018 年前的设备**（老 Android、某些车机、部分国产浏览器内核）：保守写 GLSL1，把 `fwidth` 包在 `#ifdef GL_OES_standard_derivatives` 里。
- **需要最高的未来确定性**：直接上 `WebGPURenderer`。但要注意它的后处理管线（`PostProcessing`）和 WebGL 版不通用，迁移成本不低。

**什么时候别用 WebGL2**：目标环境明确只有 WebGL1（极少数）。这种情况下 Three.js 仍能工作，但要少用上面列的 WebGL2-only 特性。

### T42 什么时候不要上 3D

这是全篇最省钱的一条。以下情况**不要**用 Three.js：

**1. 静态装饰图形。**
一条曲线、一个几何图标、一个渐变光斑 —— SVG 或 CSS 更快、更清晰、可访问、能响应式、能被搜索引擎和屏幕阅读器读取。

```html
<!-- 一个 20 行的 SVG 替代 200 行的 Three.js -->
<svg viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40" fill="none" stroke="currentColor" stroke-width="4"/>
</svg>
```

**2. 纯 2D 的大量动态图形。**
散点图 5000 个点、粒子效果、程序化插画 —— Canvas 2D 或纯片段着色器（`T23`）就够，不需要相机、光照、场景图那一整套。

**3. 需要无障碍和可选中文本的内容。**
3D 画布里的文字对屏幕阅读器是不可见的，也不能被用户选中复制。场景里的标注应该是**叠在 canvas 上的 HTML**，而不是画进 3D。

**4. 移动端首屏。**
下载 `three.module.js` + 初始化 WebGL 上下文的成本在低端机上是几百毫秒到一秒。首屏需要立刻可见的内容不要塞进 3D。

**5. 只需要一次「伪 3D」效果。**
CSS `transform: perspective()` + `rotate3d()` 能做翻转卡片、3D 按钮、视差层次 —— 零 JS、零依赖、GPU 加速。

**6. 数据量不足以撑起 3D。**
只有 3 个数据点的「3D 柱状图」比 2D 柱状图更难读、更慢、更容易误解。3D 在数据可视化里通常是**减分项**（遮挡、透视失真、难以精确比较），除非第三个维度本身就是数据（地形、体数据、分子结构）。

**什么时候上 3D 是值得的**：

- 用户需要**旋转/缩放来理解空间结构**（产品、模型、地形）。
- **光照/材质**是信息的一部分（金属 vs 塑料 vs 玻璃的区分）。
- **景深和遮挡**本身就是叙事手段（场景漫游、游戏、建筑可视化）。
- **规模**大到 2D 撑不住（几万个实例、GPU 粒子系统）。
