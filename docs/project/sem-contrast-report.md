## 结论

1. **强调字只落在浅底上，且全部过 AA。** `paper`（纸白）与 `cream`（近白，暗底版式里
   当浅底用）是强调字实际出现的唯二背景——这两列三系×四色**全部 ≥ 3.0**（最低 3.05 =
   editorial.warm on sand，但 sand 不承载强调字；real 文本底 paper/cream 最低 3.16）。

2. **1241 的「1.84~2.67」是过时测量，不是当前缺陷。** 那次是在「强调色压纸白过 AA」
   修复（补记五/六，把 `#ff5a3c`→`#ff3e1b` 等、统一到单一事实源）**之前**量的，当时
   语义色明度更高、压纸白本就只有 2.87~2.90。修复后语义色压纸白已稳定 ≥ 3.0（见
   `style-system.test.ts` 同名断言），1.84~2.67 的口径在现行代码里不复存在。

3. **矩阵里所有 ⚠（< 3.0）格子都是「sem 压彩底/深底」的装饰组合**
   （aux / steel / clay / ember / blush / sand）——这些底是色带、装饰圆、深底面板，
   **强调字从不落在上面**（`render.tsx` 的语义 tspan 只在 headline 槽的浅底上；
   `kaojin` / `wangji` 的语义大字的底是其低透明度（0.1）语义圆，叠出来仍接近纸白）。
   所以这些格子是「不会被触发的判据」，不进门禁，避免把装饰组合误判成可读性缺陷。

## 顺带发现（不在本次范围，记在案待设计判断）

`v2:num-band` 这类板把**单位标签（accent 色）压在蓝色 `aux` 色带上**：
accent vs aux 对比度 flat-vector 1.07 / chart-motion 1.39 / editorial 1.68，远低于 3.0。
这是 `tone.accent` 压彩底，不是 `sem`，且单位标签字号小、属「大字」边界情形，与本次
「sem 强调字」不是一个判据。要不要把 num-band 的单位标签改压纸白 / 加描边，是设计决定，
先记在案，不动。
