## 二、产物拆解：`二十种画面 · 100 秒.html`

### 2.1 架构事实【代码事实】

- **文件头 invariant 块**（第 49–56 行）：四条不变量写在代码顶部——① 画面只由 `render(t)` 决定；② 每风格 5 秒、局部时间 `ts=t-5k`、**转场切换点定义为"斜切面板完全盖住屏幕的瞬间"**；③ 随机量只来自带种子的 `rng`/`hash`，禁用 `Math.random`；④ 逻辑坐标恒 1920×1080，画布分辨率用缩放系数适配。
- **调度**：`SCENES=[s0..s19]`，`render(t)` 里 `idx=floor(t/5)`、`ts=t-idx*5`，每场景一个自包含函数（约 30 行），彼此无共享可变状态。
- **状态复位**（第 751 行）：`render` 入口显式重置 `transform / globalAlpha / globalCompositeOperation / shadow* / setLineDash([])`，再画。
- **自动化钩子**：`window.__render = render; window.__DUR = DUR` —— 供外部脚本按 t 截图/比对。
- **低分辨率离屏缓冲当画法**：`pcv` 240×135 像素风（关 `imageSmoothing` 整数放大）、`mcv` 240×135 液态（元球场 + `createImageData` 法线光照，开平滑放大）。
- **转场**：三段斜切面板（`inOutQuart`，每段错开 0.09s），面板内印风格序号与中英名。
- **每个场景的注释写"画法"而非"名字"**：如「12 逐帧手绘 —— 12fps 量化，线条每帧重抖，洋葱皮，错位上色」「16 真实页面 2.5D 推进 —— 分层视差：缩放 = F/(深度-相机z)」。
- **样式名表** `NAMES`：20 组「中文名 + 英文名」，一行一组，供标签与转场印字。

### 2.2 值得偷的三条【意图解释 + 代码事实】

1. **一个关系量驱动多层**（s15，第 558–588 行最有代表性）：`push = E.inOutCubic(pr(ts,.3,4.6))` 一个变量推出 `cz / camx / camy`，每层只声明 `{深度 d, x, y, 入场延迟 t0, draw}`，缩放由 `F/(d-cz)` 统一算出、按 `d` 排序做画家算法；连"鼠标点击"落点都用同一套投影数学反推。**这就是方法论 §5.1 的教科书实现。**
2. **低分辨率缓冲区分"硬边"与"柔边"**：同一块离屏画布，关平滑得到像素风、开平滑得到液态——材质差异由**采样方式**而非贴图决定。
3. **不变量写在文件里而不是文档里**：任何人（或并行会话的 agent）打开文件第一屏就看到四条硬约束。srt-film 的不变量目前只在 `progress.md`/`baseline-audit.md` 里。

## 四、明确不采纳 / 需改写后采纳

1. **"一个主体 / 只用 5–7 色 / 每风格 3–5 特征"**（§1.2 末尾自注为启发式）：srt-film 的信息图场景是多主体数据叙事，catalog 已有 216 套版式 16 个组，套用单主体启发式会削掉已有的表达力。**不采纳为规则。**
2. **"共用一个变量即是好动画"**（§5.1 后半句自带警告）：采纳关系量的**形式**，但必须配语义校验——本项目已有槽级属性冲突门禁（`motion/conflict.ts`）可作为"关系是否成立"的机器判据之一。
3. **低分辨率缓冲当画法**（产物 2.2 第 2 条）：**暂不采纳**。srt-film 的 fx 层是氛围叠加而非主体像素画法，改成低分辨率会牺牲 fx 与内容的合成质量。记账观察，若将来做"点阵/故障风"再启用。
4. **方法论 §1.1 的视觉简报**：不新造文档模板，改为在 `progress.md` 的阶段段落里固定七行（表达目标 / 视觉主体 / 运动逻辑 / 时间结构 / 技术约束 / 验收方式 / 假设），省一份文件维护成本。
