## 二、本轮新增的真实证据（不只是复述机器结论）

### ⚠️ 镜头连续性 2 分 —— `03-data-comparison.srt` 的 visual-ab 覆盖率 0

这是机器测出来的，不是我主观判断。按 rubric 的映射规则「覆盖 = 0 → 2」，属于**门禁设计的失败态**（该门禁存在就是为了拦这个）。

事实：`OVERLAP = 0.25` 的交叠是**时间上的**——前一拍与后一拍在时间上重叠 0.25s，视觉上没有任何承接。03 语料的数据板之间更是零像素差：坐标柱各自画各自的，柱子不会「长」成下一根。

为什么其余两语料覆盖数 > 0（01 覆盖 3、09 覆盖 1）：因为那些拍之间恰好存在形状或位置相近的元素，**是偶然撞上的，不是设计出来的承接**。

计划 §6 对这一维的原话是「是否传递位置、形状、方向、颜色、结构或概念」。当前实现只做到了「时间」，五项语义承接一项都没有。这条要修，属 Phase 11 的能力沉淀（跨拍视觉承接机制），不是 Phase 10 的返修范围。

### 人工维度的观察（不做分数，只记判断依据）

rubric 规定主观维度必须是 `待人工` 而不是拍出来的数字——遵守。人工盲评需要 ≥ 10 人、随机 ID 隐藏版本号、带置信区间的 MOS，本轮不具备条件，因此不评。

单条目视观察（抽帧 `.tmp/score/sheet_0*.png`，仅供参考，不构成评分）：

- **叙事推进**：01 语料连续三拍都用「章节卡 + 巨号数字」，节奏偏平；03 语料版式随语义切换明显（坐标柱 / 数字带 / 巨号 / 阶梯），推进感更强。
- **图形质量**：03 的坐标柱带刻度与数值标签，是真数据驱动；01 的尘埃点阵偏「氛围」而非「信息」。
- **构图与焦点**：机器 5 分（约束层）。人工看偶有偏空的拍（入场动画起点，非稳定构图），故 rubric 标「混合」——机器分高不代表主观分高。

## 三、必须诚实说的事

1. **「机器记分卡全绿」不等于「片子好看」。** 本轮机器给出 8 项 5 分，但 Phase 10 里两个最严重的缺陷（`0.06` 被洗成 `0 06`、白字画白底导致对比度 1.00）都是**当时门禁全绿、抽帧目视才发现**的。机器只能证明它测过的东西是对的。
2. **镜头连续性 2 分是真问题，不是形式主义。** 它是本轮唯一一个非 5 分的自动维度，且 03 语料覆盖率是 0——一个数据都没采到，说明数据板之间视觉上完全不承接。
3. **扣分的不是修不好的，是我判断这一刀不该修。** 修连续性要建立跨拍视觉承接机制（形状/位置/颜色的传递），这是新增能力而非修 bug，风险与收益不匹配。

## 四、复现

```bash
node tools/run-ts.mjs tools/quality-score.ts \
  --mp4 .tmp/phase10/01.mp4,.tmp/phase10/02.mp4,.tmp/phase10/03.mp4,.tmp/phase10/04.mp4,.tmp/phase10/05.mp4 \
  --tests .tmp/quality-check.log
```

（`--mp4` 支持逗号分隔多文件；缺 `--tests` 时工程稳定性按规则判「待人工」而不是默认绿，
所以复现本表必须带测试日志。）

规则全文见 `docs/project/visual-quality-rubric.md`；记分卡原始产物在 `.tmp/quality/scorecard.md` + `.json`。
