# 视觉质量与工程质量评分规则（visual-quality-rubric）

> 来源：项目档案 §6「视觉质量与工程质量的评分规则」。
> 本文件是该节的落地版——十个维度、每维 1–5 分、固定解释锚点；
> 配套工具 `tools/quality-score.ts` 按本文件的映射规则自动生成记分卡。
>
> **禁止只用一个模糊的"美感分"。** 每一维独立评分，机器能判的走门禁，机器判不了的走人工盲评，
> 记分卡上主观维度必须是 `待人工` 而不是一个拍出来的数字。

## 一、十个维度总表

| # | 维度 | 关注问题 | 主要验证方式 | 记分类型 | 自动证据来源 |
|---|---|---|---|---|---|
| 1 | 语义准确 | 画面是否正确表达字幕，是否凭空造事实 | 事实溯源 + 人工审查 | 自动 | phase10-qa G1（画面数字守恒） |
| 2 | 叙事推进 | 每拍是否提供新信息，镜头顺序是否合理 | 镜头表审查 + 全片观看 | 人工 | plan（拍数/版式多样性/角色分布，仅作证据） |
| 3 | 构图与焦点 | 主次是否清楚，是否拥挤/空洞 | 关键帧 + 盲评 | 混合 | constraint-audit（出界/溢出硬错误） |
| 4 | 图形质量 | 主体是否有设计，而非随机几何拼接 | 关键帧 + 参考案例对照 | 人工 | plan（版式多样性，仅作证据） |
| 5 | 排版可读性 | 字号、行距、对比、密度和安全区 | 自动检查 + 人工审查 | 混合 | plan-dry 门禁 problems（超宽/分句截断） |
| 6 | 动画质量 | 运动是否有目的、连贯、自然 | 连续帧 + 慢放检查 | 混合 | motion-audit（属性冲突/跑出拍外） |
| 7 | 镜头连续性 | 是否传递位置、形状、方向、颜色、结构或概念 | 接触印相 + 全片观看 | 混合 | visual-ab continuity 层（像素差 + 覆盖率） |
| 8 | 风格一致性 | 设计语言是否统一，差异是否有意图 | 全片评审 | 混合 | plan 风格判定 + problems |
| 9 | 工程稳定性 | 错误、确定性、性能、导出兼容性 | 自动测试与日志 | 自动 | npm run check / plan-dry / audit / qa-frames 确定性 |
| 10 | 输出正确性 | MP4 可解码、尺寸/帧率/时长正确、无音轨 | 媒体探测 + 抽帧 | 自动 | ffprobe + phase10-qa F |

「混合」= 机器层有可判定判据（约束、冲突、守恒、覆盖），先出机器分；
主观锚点（好不好看、有没有设计感）由人工盲评补齐，**机器分高不代表主观分高**。

## 二、每维 1–5 分锚点（固定解释）

评 2 分或 4 分 = 落在相邻两个锚点描述的中间态。锚点全部写成可观察判据，不写"更好看"这类不可判词。

### 1. 语义准确

| 分 | 判据 |
|---|---|
| 5 | 画面每个数字/专名都能在对应 SRT 句找到（G1 守恒 0 违规），无事实漂移 |
| 3 | 个别非关键装饰元素无法溯源，但不与原文矛盾；关键信息全部守恒 |
| 1 | 画面出现 SRT 中没有的数字或事实，或与原文矛盾（G1 违规 ≥ 1） |

### 2. 叙事推进

| 分 | 判据 |
|---|---|
| 5 | 每拍提供新信息或新视角；顺序符合叙事弧（钩子 → 证据 → 结论）；无重复构图凑数 |
| 3 | 多数拍有推进；个别拍信息重复但可接受 |
| 1 | 多拍重复同一信息或同一构图；顺序混乱 |

### 3. 构图与焦点

| 分 | 判据 |
|---|---|
| 5 | 主次分明；主体占比与负空间均衡；不拥挤不空洞；全部元素在安全区内 |
| 3 | 主次清楚；个别拍偏挤/偏空或贴近安全区边缘 |
| 1 | 主体被压、元素出安全区、拥挤或空洞到影响阅读 |

### 4. 图形质量

| 分 | 判据 |
|---|---|
| 5 | 主体图形有设计（图形语言与语义对应）；非随机几何拼接；与全片风格一致 |
| 3 | 图形可读但设计感弱，接近模板素材 |
| 1 | 随机几何拼接；与语义无关的装饰堆砌 |

### 5. 排版可读性

| 分 | 判据 |
|---|---|
| 5 | 字号/行距/对比/密度全部达标；无超宽、无截断；安全区通过 |
| 3 | 个别拍密度偏高或标题接近截断阈值，不影响阅读 |
| 1 | 文字出安全区、被截断、或对比不足到读不清 |

### 6. 动画质量

| 分 | 判据 |
|---|---|
| 5 | 运动有目的（入场/强调/氛围各司其职）；连贯自然；无属性冲突、无跑飞；镜内运动量达标 |
| 3 | 多数拍运动合理；个别拍运动过弱或过快 |
| 1 | 运动随机、属性互相盖写、跑出拍外，或整片静止如幻灯片 |

### 7. 镜头连续性

| 分 | 判据 |
|---|---|
| 5 | 连续性层真实存在且按设计强度呈现（ghost 传递位置/形状/方向/颜色/概念）；跨拍有承接 |
| 3 | 连续性层存在但偏弱或覆盖少 |
| 1 | 无连续性传递；或该层像素贡献为零（代码存在、画面里没有） |

### 8. 风格一致性

| 分 | 判据 |
|---|---|
| 5 | 全片设计语言统一（色板/字阶/图形语法）；风格判定与内容匹配；差异处有意图 |
| 3 | 主体统一；个别拍风格漂移但可解释 |
| 1 | 风格混杂无解释；或风格与内容错配（图表风讲情绪故事等） |

### 9. 工程稳定性

| 分 | 判据 |
|---|---|
| 5 | tsc / 测试 / 干跑门禁 / 版式审计 / 运动审计 / 渲染确定性全绿，零错误零告警 |
| 3 | 全绿但存在告警项（不拦截播放） |
| 1 | 任一硬失败：测试红、规划崩、版式硬错误、渲染不确定 |

### 10. 输出正确性

| 分 | 判据 |
|---|---|
| 5 | MP4 可完整解码；分辨率/帧率/时长/帧数符合导出档位；无音轨；无黑帧爆白 |
| 3 | 可解码但个别指标漂移（如时长偏差 < 0.5s）或有 WARN 级帧问题 |
| 1 | 解码失败、尺寸/帧率错误、带音轨、或存在黑帧/爆白 |

## 三、自动记分映射（tools/quality-score.ts 的实现规则）

工具只把**已有机器的判据**换算成分数；没有证据的维度输出 `待人工`，绝不编分。

| 维度 | 类型 | 映射规则 |
|---|---|---|
| 语义准确 | 自动 | phase10 G1 违规 0 → 5；≥ 1 → 1；无报告 → 待人工 |
| 构图与焦点 | 混合 | 版式审计 硬错误 0 且告警 0 → 5；告警 > 0 → 4；硬错误 > 0 → 2；主观待盲评 |
| 排版可读性 | 混合 | plan problems 0 → 5；仅 warnings → 4；problems > 0 → 2；主观待盲评 |
| 动画质量 | 混合 | 运动审计 冲突+越界 0 → 5；> 0 → 2；主观待盲评 |
| 镜头连续性 | 混合 | visual-ab continuity 覆盖 > 0 且全过 → 5；覆盖 = 0 → 2（按门禁设计即失败）；无报告 → 待人工 |
| 风格一致性 | 混合 | plan problems 0 → 5；> 0 → 2；主观待盲评 |
| 工程稳定性 | 自动 | 全部门禁绿 → 5；仅告警 → 4；任一硬失败 → 1 |
| 输出正确性 | 自动 | ffprobe 全过 → 5；任一不符 → 1；未提供 MP4 → 待人工 |
| 叙事推进 | 人工 | 恒为待人工；工具附拍数/版式多样性/角色分布作证据 |
| 图形质量 | 人工 | 恒为待人工；工具附版式多样性作证据 |

退出码：任一**自动维度** < 3 → 1；否则 0。待人工维度不影响退出码（它们本来就等人）。

## 四、人工盲评规则（蒸馏自 references/manual/06-质量评审方法）

1. **量表对照**：ACR 五级标签 —— 1 = bad（差）/ 2 = poor（较差）/ 3 = fair（一般）/ 4 = good（好）/ 5 = excellent（优秀）。评审表必须印这张对照表，避免各人理解不一。
2. **盲评必须打乱顺序、隐藏版本号**：成品展示名与文件名替换为随机 ID；成对序列左右位置随机；界面不出现 v1/v2/旧/新等泄露字段。
3. **人数**：小批量内部盲评 ≥ 10 人；正式验收目标 15 人；按「目标有效人数 × 1.2」招募，预留筛查剔除。
4. **MOS 必须带置信区间**：只报「MOS = 4.2」不报「4.2 ± 0.3」的报告视为不合格。
5. **效度筛查**：视力/色觉自评；平台记录停留时长与是否拖动跳过；远程评审插入已知好/坏的对照陷阱，未通过者数据作废。
6. **环境留痕**：每批评审记录设备型号、分辨率、亮度/对比度、观看距离、环境光；同批条件一致才可合并统计。
7. **片段要求**：从无损母版切取，单条 ≥ 10 秒；不用重编码多次的旧成片当源。
8. **双轨通过**：最终结论必须同时包含「自动检查」与「人工盲评」两条记录，缺任一条则验收状态为未通过。
9. **客观指标的边界**：SSIM 通过只表示「结构没被破坏」，不表示「更好看/更易读」；客观与主观冲突时以人工为准并记录冲突样本。

## 五、改进有效的最低证据

声称「改版提升了质量」必须同时给出：

1. 同一基准输入的前后两个版本；
2. 相同导出参数；
3. 前后关键帧 / 接触印相；
4. 自动测试结果（记分卡前后各一份）；
5. 涉及审美的修改，尽可能做隐藏版本信息的盲评。

只展示最好看的单个镜头、只给"感觉变好了"的结论，不构成有效证据。

## 六、工具用法

```bash
# 记分卡（自动维度 + 证据聚合；主观维度标 待人工）
node tools/run-ts.mjs tools/quality-score.ts \
  --mp4 .tmp/phase10/03.mp4 \
  --tests .tmp/quality-check.log
# 可选：--corpus 01,03 限定语料；--phase10/--vab 指证据文件；--out 指定输出目录
# --mp4 支持逗号分隔多个文件（如五语料成片一起测）；缺 --tests 时工程稳定性判「待人工」而非默认绿
```

输出 `.tmp/quality/scorecard.json`（机读）+ `scorecard.md`（人读）。
退出码 1 表示有自动维度跌破 3 分——**这一条也必须反向验证过**：
故意喂坏证据（见 progress.md 的反向验证节），分数必须掉、退出码必须变 1。
