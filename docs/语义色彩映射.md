# 语义色彩映射

画面上的颜色不是装饰，是**语义**。这份文档定义：一句话里出现「疼 / 代价 / 在乎」这类
强词时，该给它什么颜色、什么字重、什么字号 —— 以及这些取值背后的依据。

代码实现：`src/layouts/emphasis.ts`（词表与色值都在 `SEM_ROLES` 一个数组里，改它就够）。

---

## 一、为什么不能随便挑颜色

联网核对了主流设计系统的语义色约定（Material Design 3、Ant Design、Tailwind、Dell DS、
Semiotic），结论高度一致：**语义色是恒定值，只有品牌色才随风格变**。

### 1. Material Design 3 的 token 架构

M3 把颜色拆成 45 个 role，关键概念有四个：

| 概念 | 含义 | 我们的用法 |
|---|---|---|
| `Surface` | 背景 / 大面积低强调区域 | 纸白 `#faf9f6` / 暗底 `#0b0b0f` |
| `Primary / Secondary / Tertiary` | 强调前景色的层级 | 我们的 accent（品牌朱红 / 电光青绿） |
| `Container` | 前景元素的填充（按钮底），**不用于文字** | 未使用（本片没有按钮类元素） |
| `On-*` | 叠在某个父色**之上**的文字 / 图标色 | 语义色直接作前景，不做容器配对 |

M3 的原话是「color roles are like the numbers in a paint-by-number canvas」——
role 不描述「这是什么颜色」，只描述「这个颜色用在哪」。这正是本文件的意义。

### 2. 业界语义色锚点

| 语义 | 业界锚点 | 典型出处 |
|---|---|---|
| danger / error | `#dc2626` | Tailwind red-600、多家 DS 的 error |
| warning | `#d97706` | Tailwind amber-600 |
| success | `#16a34a` | Tailwind green-600 |
| info | `#2563eb` | Tailwind blue-600 |

这三条稳定得几乎像公约数 —— «success / warning / danger 在整个注册表里保持稳定，
锚定人类色彩语义的一致性»。所以「危险是红、安全是绿」不需要重新发明，照搬即可。

### 3. Ant Design 的中文语义命名（中文语境的权威参照）

Ant Design 给每个基础色配了**中文语义名**，这是中文设计界最通行的语义词典：

| 色系 | 中文名 | 语义 |
|---|---|---|
| red | 薄暮 | 斗志、奔放 |
| volcano | 火山 | **醒目、澎湃** |
| gold | 金盏花 | 活力、积极 |
| green | 极光绿 | 健康、创新 |
| cyan | 明青 | 希望、坚强 |
| blue | 拂晓蓝 | 包容、科技、普惠 |

它的功能色原则也很关键（原文）：

> 功能色代表了明确的信息以及状态……选取需要遵守用户对色彩的基本认知。
> 建议在一套产品体系下，功能色尽量保持一致，不要有过多的自定义干扰用户的认知体验。

以及一条对本片特别重要的例外：

> **在配图插画以及展示性页面中可以适当打破这一思路。**

视频是展示性内容 —— 所以本方案在**编辑风保持克制（4 色）、海报风可以放开**，
这条界线有出处，不是我随手定的。

## 二、心理学依据（跨文化基线）

约**半数**色-情关联跨人种一致（生物基线），另一半由文化编程：

| 颜色 | 自然原型 | 跨文化关联 | 生理效应 |
|---|---|---|---|
| 红 | 血、火 | 危险、紧迫、强度 | 心率与呼吸上升 |
| 绿 | 植被 | 安全、生长、恢复 | 生理唤起最低 |
| 黄 | 阳光 | 注意力、警示 | 高饱和易致视觉疲劳 |
| 暗色 | 黑暗 | 严肃、负向、不确定 | 低明度 = 低期望 |
| 蓝 | 天空、水 | 冷静、信任、稳定 | 降低血压与呼吸 |

**关键补充**：饱和度与明度才是情绪强度的旋钮 —— 高饱和 = 强情绪、低饱和 = 克制、
明度压暗 = 负向。同一个色相靠明度就能分出正负。

## 三、中国语境的注意

红在中文语境是**吉庆色**（幸运、繁荣、庆典），与西式「红 = 危险」并不一致。
所以本项目**不**用鲜红表危险，而是压暗一档 —— 把西式「红 = 危险」与中式「红 = 吉」
错开：吉庆感留给亮朱红，危险交给暗红。

## 四、本项目取值

编辑风是「纸白 + 朱红」的极简调性，多色会破坏它。所以只开 **4 个语义角色**，
且全部落在红 / 金 / 绿的暖域内，不引入蓝紫：

| 角色 | 代表 | 编辑风 | 海报风 | 业界锚点 | AntD 对照 |
|---|---|---|---|---|---|
| `danger` | 威胁、疼痛、已发生的失去 | `#a5170a` 深朱红 | `#ff4d2e` | `#dc2626` | red-7 `#a8071a` |
| `cost` | 需要支付的代价（账单，非威胁） | `#9a6b1c` 赭金 | `#ffd166` | `#d97706` | gold-7 `#ad6800` |
| `safe` | 底线、安全、不被伤害 | `#1a6b52` 墨绿 | `#38e8c6` | `#16a34a` | green-7/8 `#237804` |
| `warm` | 正向情感投入（在乎、心动） | `#c8401f` 品牌朱红 | `#ff9ecd` | —（品牌色） | volcano-6 `#d4380d` |

「AntD 对照」一列说明这些值不是拍脑袋：编辑风的四个取值都落在 Ant Design 中文色板的
**同一档位**（第 6~8 级，即暗调），与中文语境的语义命名对得上 ——
`warm` 对应「火山 · 醒目澎湃」，`danger` 对应「薄暮」压暗后的沉郁。

### 核心设计：danger 与 warm 同为红系

稿子的中心论点是「**痛苦和幸福其实是同一个源头**」。把「疼 / 代价」与「在乎 / 心动」
放进同一色系、只靠明度拉开（暗红 `#a5170a` vs 亮朱红 `#c8401f`），画面本身就复述了
这句话 —— 颜色承担了论证，而不是装饰。

## 五、词表（触发词）

白名单，只收旁白真实用词，不引入稿子没说过的话（与「不允许无数据画图」同一条诚实约束）：

| 角色 | 词 |
|---|---|
| danger | 痛苦、危险、伤害、失恋、亏损、可怕、风险、疼、痛、损失、失去、孤独、失败 |
| cost | 价格、代价、付出、保费、成本、止损 |

价格×2、失恋×1、亏损×1、损失×1、孤独×1、代价×1、通透×1、不怕×1、心动×1、爱×1。
（未命中的词是通用词表的正常冗余，留给以后的语料。）

## 六、怎么改

改 `src/layouts/emphasis.ts` 的 `SEM_ROLES` 一个数组即可 —— 色板与词表都从它派生：

```ts
{
  tone: "danger",
  means: "威胁、疼痛、已经发生的失去",
  editorial: "#a5170a",   // ← 改这里换色
  terms: ["痛苦", "危险", ...],  // ← 改这里增删词
}
```

放大倍数与字重是全局旋钮：`SEM_SCALE`（1.14）、`SEM_WEIGHT`（800）。
强调同时放大加粗不只是好看 —— 色盲用户靠字号与字重也能读出色别（不能只靠颜色传递信息）。
